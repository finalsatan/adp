1. 文档说明

本初稿只确定一级、二级功能模块的范围和优先级，具体功能细节在后续版本中逐模块补充。

  • 目的：为公司内部智能体开发平台确定整体功能架构，作为后续详细需求和技术方案的基线。
  • 功能架构基准：联通万悟（wanwu）的菜单与模块划分，以其开源前端菜单为准。
  • 模块实现参考：知识库与 RAG 参考腾讯 WeKnora 和 Haystack；工作流参考 Dify 的节点设计，执行引擎基于 LangGraph 自研；其余模块先对齐万悟。
  • 版本：v0.1 初稿，不沿用此前的需求文档。

2. 产品定位与目标用户

平台定位是公司内部的一站式智能体开发平台：功能范围对齐万悟，在知识库/RAG 和工作流两个模块上做得更深。差异化不靠功能数量，靠问答效果可评测、全链路可观测。

5. 平台通用能力

以下能力不单独成为菜单，由所有模块共用，需要在首版就统一设计。

  • 多租户：所有资源和应用归属租户，数据按租户隔离。
  • 权限与审计：基于角色的菜单和资源权限，关键操作留审计日志。
  • 统一资源引用：知识库、工具、MCP、提示词、Skills 可被知识问答、工作流、智能体通过同一套接口引用。
  • 可观测与评测：所有模型调用和检索过程统一打点，供链路追踪和效果评测使用。
  • 开放 API：应用和主要资源均提供 API，由 API Key 鉴权。
  • 异步任务：文档解析、向量化、评测、长工作流走统一任务队列，可查看进度。

6. 非功能需求

本节只列方向，具体指标在技术方案中确定。

方面初步要求
技术栈推荐后端 Python（FastAPI + LangGraph + Haystack），前端 TypeScript（React + React Flow）；待确认
部署公司内网私有化部署，支持 Docker Compose 和 Kubernetes
模型以云端模型 API 为主，兼容 OpenAI 协议的自部署模型
开源许可证不 fork Dify、FastGPT、n8n 等附带多租户限制的项目，只借鉴设计
安全数据不出公司环境，密钥加密存储
性能问答首字响应时间、并发量、入库吞吐，指标待定

7. 版本规划与待定事项

版本按优先级分三批交付，每批上线后平台都能独立使用。

  1. 首版（P0）：系统管理、模型管理、知识库、知识问答、应用发布、链路追踪、效果评测。跑通“文档入库 → 问答 → 评测”闭环。
  2. 第二批（P1）：工作流、智能体、MCP、插件工具、提示词、模型体验、统计看板、API Key。
  3. 第三批（P2/P3）：Skills、安全护栏、探索广场、通用智能体；决策智能体视业务需求再定。

待定事项

  • 后端语言：全 Python，还是 TS 主服务 + Python RAG 服务
  • 决策智能体（数字员工、本体建模）是否纳入范围
  • 多租户的租户粒度：公司、部门，还是团队空间
  • 首版上线时间与团队分工
