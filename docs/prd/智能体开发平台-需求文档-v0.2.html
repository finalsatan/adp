1. 文档说明

本版确定一级、二级功能模块的范围、优先级和平台级规则，模块内的详细功能在后续版本中逐个补充。

  • 目的：为公司内部智能体开发平台确定整体功能架构，作为后续详细需求和技术方案的基线。
  • 功能架构基准：联通万悟（wanwu）的菜单与模块划分，以其开源前端菜单为准；租户与权限模型也参考万悟。
  • 模块实现参考：知识库与 RAG 参考腾讯 WeKnora 和 Haystack；工作流参考 Dify 的节点设计；其余模块先对齐万悟。
  • 技术选型：不在本文档中确定，见技术方案；本文档只列对技术的约束（第 7 节）。

v0.2 相对 v0.1 的变更：确定组织与权限模型（参考万悟）；知识库拆出二级功能；API Key 基础功能提到 P0；新增终端用户反馈、首版成功标准、不做的事；明确数据安全口径；移除决策智能体；技术栈移到技术方案。

2. 产品定位与目标用户

平台定位是公司内部的一站式智能体开发平台：功能范围对齐万悟，在知识库/RAG 和工作流两个模块上做得更深。差异化不靠功能数量，靠问答效果可评测、全链路可观测。

5. 平台通用能力

以下能力不单独成为菜单，由所有模块共用，需要在首版就统一设计。

5.1 组织与权限（参考万悟）

  • 组织树：组织为多级树结构，对应公司内的子公司、部门。一个用户可属于多个组织，在界面上切换当前组织。
  • 角色：每个组织自带“组织管理员”角色，组织内可自定义角色；系统管理员可创建全局角色，跨组织分配给用户。菜单和操作权限按角色控制。
  • 资源归属：所有资源和应用同时记录所属组织和创建人，数据按组织隔离。
  • 可见范围：知识库、提示词、工具、MCP、应用统一按三档发布：仅自己、本组织、全平台。下级组织不自动继承上级组织的资源，需显式发布到全平台。
  • 审计：关键操作（权限变更、发布、删除、密钥操作）留审计日志。

5.2 其他通用能力

  • 统一资源引用：知识库、工具、MCP、提示词、Skills 可被知识问答、工作流、智能体通过同一套接口引用。
  • 可观测与评测：所有模型调用和检索过程统一打点，供链路追踪和效果评测使用。
  • 用户反馈闭环：终端用户对回答点赞、点踩、纠错；点踩记录可一键加入评测集。
  • 开放 API：应用和主要资源均提供 API，由 API Key 鉴权。
  • 异步任务：文档解析、向量化、评测、长工作流走统一任务队列，可查看进度。

6. 首版成功标准

首版（P0）以一个真实知识问答场景验收，数值在选定场景后确定。

项目要求
试点场景选定 1 个真实知识问答场景及其文档集（待定）
评测集不少于 200 条问题，由业务方确认标准答案
答案正确率≥ X%（待定）
引用准确率≥ Y%（待定）
首字响应≤ Z 秒（待定）

7. 非功能需求

本节只列约束和方向，具体指标和技术选型在技术方案中确定。

方面要求
部署公司内网私有化部署，支持 Docker Compose 和 Kubernetes
模型以云端模型 API 为主，兼容 OpenAI 协议的自部署模型
数据安全文档、向量、对话记录存储在公司内网；模型调用可走云端，由管理员决定接入哪家；密钥加密存储；P1 支持按知识库限制只使用自部署模型
开源许可证不 fork Dify、FastGPT、n8n 等附带多租户限制的项目，只借鉴设计
终端管理后台只支持 PC；Web 对话页适配手机浏览器
性能问答首字响应时间、并发量、入库吞吐，指标待定

8. 不做的事

  • 决策智能体（数字员工、本体建模、数据连接）
  • 计费与计量收费（Token 用量只做统计展示）
  • 移动端 App；管理后台的移动端适配
  • 知识库内的文档级权限过滤

9. 版本规划

版本按优先级分三批交付，每批上线后平台都能独立使用。没有硬性上线时间。

  1. 首版（P0）：系统管理（组织、角色、权限）、模型管理、知识库核心功能、知识问答、应用发布、API Key 基础功能、链路追踪、效果评测、用户反馈。跑通“文档入库 → 问答 → 反馈 → 评测”闭环。
  2. 第二批（P1）：工作流、智能体、MCP、插件工具、提示词、模型体验、统计看板、知识库问答对/同义词/Contextual Retrieval、按组织和角色授权、API Key 权限范围。
  3. 第三批（P2）：Skills、安全护栏、探索广场、通用智能体、数据源同步。

后续细化顺序：知识库 → 知识问答 → 链路追踪与效果评测 → 系统管理（组织、权限）→ 模型服务与应用发布。
