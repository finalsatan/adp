1. 功能模块一览

编号模块一句话说明
M1模型服务统一接入和管理平台使用的各类模型
M2资源库沉淀知识库、工具、提示词等可被应用复用的资源
M3应用开发用资源和模型搭建知识问答、工作流、智能体，并发布给终端用户
M4探索广场浏览和复用平台内已发布的应用、模板与共享资源
M5系统观测看到应用运行得怎么样、评估效果，并统计模型用量
M6通用智能体面向全员、开箱即用的通用助手
M7API Key 管理让外部程序以受控方式调用已发布应用
M8系统管理用户、组织、角色、权限与平台运营

平台只在 PC 端浏览器访问和使用，包括发布出去的应用，不做移动端适配。

2. 各模块需要做的事情

M1 模型服务

目标：让平台能统一使用各类模型，使用者不用关心接入细节。
  • 接入对话（Chat）、向量化（Embedding）、重排（Rerank）三类模型；扫描件的文字识别由解析引擎负责，不在这里登记。
  • 模型由系统管理员统一添加和维护，添加后全平台可用。
  • 模型密钥加密保存，界面和接口不暴露明文。
  • 可测试模型是否可用；可启用、停用模型。
  • 提供在线对话体验，并支持多个模型对比效果。

详细需求见第 3 节。

M2 资源库

目标：把应用开发要用的素材集中管理，一次建好、多处引用。
  • 知识库（重点）：分文档库和问答库；上传、更新、删除文档并查看入库进度与失败原因；用可复用的入库方案配置解析、分块和分块增强；查看和修改解析结果与分块；维护问答对；配置检索并用命中测试验证召回效果；引用定位到原文；通过可见范围和协作者控制权限。后续补充同义词、外部数据源同步。
  • MCP 服务：接入外部 MCP Server，并按工具粒度启用。
  • 插件工具：提供内置工具，并支持导入 OpenAPI 描述的自定义工具。
  • 提示词：管理提示词模板与版本，并支持对提示词做评测。
  • Skills：管理技能包，并在沙箱中执行。
  • 安全护栏：对输入输出做过滤，支持敏感词与提示词注入检测。
  • 所有资源用同一套权限：可见范围分仅自己、本组织（含下级组织）、全平台三档，另可添加协作者共同编辑；入库方案固定全平台可见。资源能被应用以统一方式引用。

详细需求见第 4 节（目前已细化知识库和入库方案）。

M3 应用开发

目标：让搭建者把模型和资源组合成可用的应用，并发布出去。
  • 知识问答（重点）：基于知识库的问答应用；检索策略按应用配置；支持多轮对话；回答带引用，点击可定位到原文；每次问答可调试回放。
  • 工作流（重点）：可视化编排，支持分支、循环、并行、人工介入与断点续跑。
  • 智能体：组合模型、知识库、工具、MCP 与记忆，支持多步检索与推理。
  • 应用发布：发布为 Web 对话页、嵌入组件和 API；终端用户可查看历史会话，并对回答点赞、点踩、纠错。

M4 探索广场

目标：让大家发现并复用已有成果，减少重复搭建。
  • 应用广场：浏览并使用发布到全平台的应用。
  • 模板、MCP、Skill 广场：复用模板和共享资源。

M5 系统观测

目标：让运行情况、问答效果和模型用量可见、可衡量。下设两个子菜单：应用观测、用量统计。
  • 用量统计：按模型、应用、组织、用户统计调用量与 Token 用量，含模型体验页的调用（仅统计，不计费）。
  • 应用观测：包含下面三项。
  • 统计看板：展示应用的调用量与活跃度。
  • 链路追踪（重点）：回放每次对话的查询改写、召回、重排、上下文与模型调用。
  • 效果评测（重点）：评测集可来自人工导入、大模型按文档生成、终端用户点踩转入；衡量召回、答案正确性、引用准确性与拒答；同一评测集可对比两套检索配置。

M6 通用智能体

目标：给全体员工一个开箱即用的助手，不需要自己搭建。
  • 提供面向全员的通用 AI 助手入口。

M7 API Key 管理

目标：让外部系统安全地调用平台上的应用。
  • 创建、吊销 API Key，并绑定到具体应用。
  • 后续支持细分权限范围。

M8 系统管理

目标：管好谁能用、能用什么，并留下可追溯的记录。
  • 用户与组织：多级组织树，对应子公司、部门；每个用户只属于一个组织。
  • 角色与权限：固定四个角色（系统管理员、组织管理员、搭建者、终端用户）；资源按可见范围和协作者控制。
  • 资源归属与隔离：所有资源与应用记录所属组织和创建人，数据按组织隔离。
  • 登录与账号安全：用户由平台创建，使用平台账号密码登录（本阶段不对接 SSO）。
  • 审计：对权限变更、发布、删除、密钥操作等关键动作留日志。
  • 系统设置：集中配置密码策略、上传与解析参数、模型调用参数和解析引擎。

详细需求见第 10 节。

3. M1 模型服务（详细需求）

原型：prototype/style-a1-antd.html。接入方式参考联通万悟（wanwu）的模型管理；万悟的模型分私有、本组织、公开三档，本平台简化为全平台可用（见 3.3）。以下均为已与产品负责人确认的结论。

3.1 接入方式

  • 平台所有模型调用统一经由 LiteLLM 转发，由它屏蔽各供应商的协议差异，平台不自写各家 SDK 适配。
  • 只接云端模型供应商，不做本地部署模型的托管。
  • 系统管理员添加模型时填写：显示名称、供应商/模型 ID、类型、接口地址（可选）、密钥、描述（可选）、能力参数、默认参数，以及调用设置（超时、重试、限流，见 3.5）。
  • LiteLLM 以 Python SDK 方式嵌入后端，不单独部署 proxy 服务（见技术方案）。

3.2 模型类型与能力参数

  • 类型：对话（Chat）、向量化（Embedding）、重排（Rerank）。语音识别、文生图本阶段不做。
  • 不设 OCR/视觉模型类型：扫描件和图片的文字识别由解析引擎（Docling、PaddleOCR、MinerU）负责，见 4.4。以后做图片描述时再增加视觉模型。
  • “支持视觉输入”是 Chat 模型的能力开关，不单列类型。
  • Chat 模型声明：上下文长度、最大输出、是否支持视觉、是否支持函数调用、是否支持深度思考开关，以及默认参数（温度、top_p 等）。
  • Embedding 模型声明：向量维度、最大输入长度（tokens）、单次请求最多条数。
  • 应用开发选模型时按能力过滤，例如只列出支持函数调用的模型。
  • 系统提示词不在模型上配置，由应用决定。

3.3 范围与权限

  • 只有系统管理员能添加、编辑、停用、删除模型和更换密钥；其他角色不能。
  • 模型不设可见范围，不按组织隔离：能进入控制台的用户（搭建者及以上）都能在模型体验、应用、知识库、入库方案中选用任何已启用的模型；运行时（问答、入库）只检查模型是否启用。理由：本阶段不做组织级配额和计费，用量可在 M5 按组织统计追溯；按组织隔离会带来跨组织引用的鉴权、缩小范围后已有引用如何处理等问题。以后如果需要按组织限制（如子公司自带密钥），再增加可见范围。
  • 密钥加密保存，界面和接口均不返回明文，只显示末几位。
  • 创建、修改、停用、删除模型及密钥变更，都写入审计日志。

3.4 模型管理

  • 列表：按类型、状态、关键字筛选。搭建者及以上都能查看模型列表和能力参数、测试连通，只有系统管理员看到编辑、停用、删除操作。
  • 测试连通：保存前后均可测试，发送一条简短请求（对话类最多输出 16 tokens，测试时关闭深度思考），显示成功/失败、耗时和返回内容；失败时显示原因，如密钥无效、模型不存在、连接超时（10 秒）。编辑模型时如果没有重新填写密钥，用已保存的密钥测试。测试调用计入用量统计，来源记为“连通测试”。
  • 接口地址：默认不允许指向内网、本机地址，防止借模型接口探测内网；系统管理员可配置允许的地址白名单（如客户内网的模型网关）。
  • 启用、停用：停用允许，界面提示受影响的应用、知识库、入库方案清单（入库方案引用的是分块增强用的对话模型）；应用运行时提示“模型不可用”。停用后，排队中和处理中的入库任务失败，失败原因为“模型已停用”，重新启用后可批量重试；知识库的向量化模型停用后，检索该知识库（含命中测试）提示“模型不可用”。
  • 删除：被应用、知识库、入库方案或检索配置引用时禁止删除，需先解除引用。
  • 知识库创建后不允许更换 Embedding 模型，只能新建知识库。
  • 向量化模型被知识库引用后，模型 ID 和向量维度不可修改（修改会让已有向量失效）；显示名称、密钥、调用设置等仍可修改。
  • 批量替换应用里的模型：本阶段不做。

3.5 调用稳定性

  • 可配置调用超时和失败重试次数。超时分两项：首字超时（默认 30 秒，等第一个字返回的时间）和总超时（默认 300 秒，包含重试在内的全部时间）。
  • 失败重试只在还没有输出任何内容时进行；流式输出中途出错直接报错，不重试。
  • 可按模型设置限流（QPS 与并发），避免超出供应商给的额度；限流按模型计算，不区分应用；不设时不限流。
  • 入库与在线调用分开限流：入库（向量化、语义分块、分块增强）最多占用该模型限额的一部分（默认 50%，管理员可调），超出时入库任务排队等待，不报错，保证在线问答不被大批量入库挤占。入库和在线合计不超过该模型的限额；模型未设限流时这一比例不起作用。
  • 不做组织或用户级配额；用量在 M5 用量统计中按组织查看，事后可追溯。
  • 主模型失败后自动切换备用模型：本阶段不做。

3.6 模型体验

  • 搭建者及以上可用，可选任何已启用的对话模型。
  • 可调整温度、最大输出等参数；支持多模型对比，最多同时 4 个。
  • 对话记录不保存。
  • 生成过程中可以停止；停止后已产生的用量照常计入。
  • 体验页的调用计入用量统计。

3.7 本阶段不做

  • 本地部署模型的托管。
  • 语音识别、文生图模型。
  • 组织、用户级的用量配额与计费。
  • 备用模型自动切换。
  • 应用内模型批量替换。

3.8 模型服务待定问题

  • 暂无。

4. M2 资源库（详细需求）

原型：prototype/style-a1-antd.html。本节先细化知识库和入库方案；MCP 服务、插件工具、提示词、Skills、安全护栏待细化。参考万悟（wanwu）和 WeKnora，调研见 docs/research/知识库模块调研-万悟与WeKnora.html。术语以仓库根目录 GLOSSARY.md 为准。以下均为已与产品负责人确认的结论。

4.1 概念与范围

概念说明
知识库可被应用引用的资源，分文档库和问答库两种类型，创建后类型不可改。
文档上传到文档库中的一个文件。
入库方案针对一种文件类型的解析设置、分块设置和分块增强开关。可跨知识库复用，上传时选用。
解析结果文档经解析引擎转换得到的带结构的文本，分块由它切出。
分块解析结果切出的一段内容，是检索和引用的最小单位。
问答对问答库中的一条知识：一个标准问、若干相似问、一个答案。

菜单位置：资源库 → 知识库、入库方案。

4.2 知识库管理

  • 创建时填写：类型（文档库 / 问答库）、名称、描述、向量化模型、可见范围。类型和向量化模型创建后不可修改；要换向量化模型只能新建知识库。
  • 创建后可设置：各文件类型的默认入库方案（仅文档库）、默认检索配置。
  • 列表：按类型、可见范围、所属组织、关键字筛选；显示文档数或问答对数、分块数、更新时间。
  • 停用：引用它的应用检索不到其内容，但应用本身不报错。
  • 删除：被应用引用时禁止删除，需先解除引用；删除前列出引用它的应用。
  • 缩小可见范围（如全平台改为本组织）或移除协作者时，如果正在引用它的应用会因此不能再引用它（如其他组织的应用），禁止操作，列出这些应用，需先解除引用（规则见 10.4）。
  • 容量默认值（管理员可调）：单个文件不超过 200MB；单个知识库文档数不设上限；同时解析的文档数由管理员配置。

4.3 文档管理

支持的文件类型（入库方案按此划分）

文件类型扩展名
PDFpdf（含扫描件）
Worddoc、docx（doc 先转换为 docx）
PPTppt、pptx（ppt 先转换为 pptx）
Excelxls、xlsx（xls 先转换为 xlsx）
CSVcsv
Markdownmd
TXTtxt
HTMLhtml、htm
图片png、jpg、jpeg、bmp、tiff

wps、ofd、epub、音视频本阶段不支持。

上传

  • 可一次上传多个文件，也可上传整个本地文件夹（保留目录结构）。
  • 混合类型上传时按文件类型分组，每组选一个入库方案，默认选中知识库为该类型设的默认方案；未设置时用平台内置的该类型通用方案。
  • 同名文件（只在同一文件夹内判断，不同文件夹中的同名文件不算同名）：让用户选择“替换”（覆盖原文档并重新入库，不保留历史版本；保留原文档的元数据和所在文件夹）或“保留两份”。
  • 内容重复：按文件内容哈希判断，同一文档库内提示“与已有文档 X 内容相同”，让用户选择“跳过”或“仍然上传”。不同文档库之间不检查。
  • 超长预检：上传时用所选方案的最大长度（开启父子分块时取子块最大长度），加上标题路径、上下文说明的预留长度，与本库向量化模型最大输入长度的 90% 比较；可能超长时在该组上提示，用户可换方案或仍然上传（超长检查见 4.4）。
  • 上传后直接走完整个入库流程，中间不停下来等确认。

文件夹

  • 多级文件夹；一个文档只属于一个文件夹；可在文件夹间移动文档。
  • 文件夹不单独设权限。检索时可按文件夹过滤（含下级）。

元数据

  • 每个文档库自定义元数据字段，类型：文本、数字、日期、单选。
  • 可对单个文档设值，也可批量设值。
  • 系统字段（只读）：文件名、文件类型、上传人、上传时间、所在文件夹。
  • 检索时可按元数据过滤，条件可用“且 / 或”组合。

文档状态与操作

  • 入库状态依次为：排队中 → 解析中 → 分块中 → 增强中（方案开启分块增强时）→ 向量化中 → 已完成；任一步出错为“失败”，显示失败原因。
  • 失败文档可单个或批量重试。
  • 可单个或批量重新解析，例如按入库方案筛选后整批重新解析；方式见 4.5。
  • 文档可启用、停用；停用的文档不参与检索，但保留不删。
  • 删除文档同时删除原文件、解析结果、分块和索引，不可恢复。
  • 有人工修改（解析结果或分块）的文档在列表中加标记。
  • 查看文档详情时显示所用入库方案的名称和参数快照。

4.4 入库方案

  • 一个方案只针对一种文件类型，包含三部分：解析设置、分块设置、分块增强。
  • 入库方案全平台可见、可用，可见范围固定为全平台。其他权限按 10.4：创建人、协作者、管理范围内的组织管理员和系统管理员能修改；删除和增减协作者由创建人、组织管理员和系统管理员操作。
  • 修改被知识库设为默认方案的方案时，保存前提示“将影响 N 个知识库以后上传的文档”，列出这些知识库。
  • 方案列表可按“我创建的 / 本组织 / 全部”和文件类型筛选。
  • 平台为每种文件类型内置至少一个通用方案（只读），如“PDF · 通用”“PDF · 扫描件”“Excel · 表格”。内置方案只用默认部署的引擎（Docling、内置解析），不依赖可选组件和模型，部署后即可使用。
  • 文档入库时记录所用方案，并保存一份完整参数快照。修改方案不影响已入库的文档。
  • 重新解析时默认使用该方案的当前参数，也可以改选其他方案。
  • 删除方案：被任一知识库设为默认方案时禁止删除；只被文档用过的可以删除（文档有快照）。
  • 方案编辑页可上传一个样例文件试运行，查看解析结果、分块和增强结果后再保存。方案不属于任何知识库，试运行时需选一个向量化模型（默认第一个启用的），用于语义分块和超长检查。
  • 导入导出：方案可导出为 JSON 文件，并在其他环境导入。导入时按模型 ID 自动匹配当前环境的模型，找不到的提示重新选择；方案用到的解析引擎在当前环境未配置时提示改选；与已有方案重名时自动改名（加“（导入）”），可再修改。

解析设置：界面直接显示解析引擎名称；未部署或未配置的引擎不可选。扫描件和图片的文字识别（OCR）也由解析引擎完成，不调用模型服务中的模型。

  • 预处理规则：合并多余空白、删除页眉页脚、删除链接和邮箱等，可逐项开关。

  • 图片：文档中的图片提取保存，分块中保留图片位置，回答和引用预览时可显示原图；所选引擎支持 OCR 时（Docling、PaddleOCR、MinerU），图片中的文字并入所在分块。

  • 父子分块：可叠加在任一分块方式之上的开关，默认关闭。检索用子块匹配，命中后返回所在父块。
    • 父块：按所选分块方式切分；该方式的最大长度、重叠长度改用“父块最大长度”（默认 4096），超过时按长度拆开。
    • 子块：在每个父块内按分隔符逐级切分（默认段落、句号，可自定义），仍超长时按长度截断；可设子块最大长度（默认 384）、子块重叠长度（默认 40）。
  • 分块开头可附带标题路径（如“第三章 > 3.2 差旅”），默认开启。
  • 表格按上面的表格规则处理，不受分块方式影响。
  • 超长检查：一个分块连同一起向量化的内容（标题路径、上下文说明等）超过知识库向量化模型最大输入长度的 90% 时，该文档入库失败，失败原因写明超长分块的位置，不再继续后续步骤；需调整入库方案后重新解析。只按 90% 计算，是因为平台统一的分词器与各模型自己的分词器计数有差异，要留出余量。上传时先做预检（见 4.3）。

分块增强：均为可选开关，默认关闭；开启时需选择一个对话模型，会消耗 token、增加入库时间。方案页显示按页估算的预计消耗。

  • 上下文说明：为每个分块生成一句说明其在全文中位置和含义的文字，与分块一起向量化（Contextual Retrieval）。
  • 假设问题：为每个分块生成几个它能回答的问题，参与检索。
  • 摘要、关键词：为每个分块生成摘要和关键词，参与检索。
  • 表格摘要：为表格生成文字摘要，作为单独的分块。

4.5 解析结果与分块

解析结果

  • 原文与解析结果并排对照查看。
  • 可人工修改解析结果；修改后标记“已人工修改”，记录最后修改人和时间，不保留完整历史；可一键恢复为原始解析结果（原始结果始终保留）。
  • 保存修改时提示：“将按入库方案重新分块并重建索引，N 处分块手工修改将被覆盖”，确认后执行。

分块

  • 查看、编辑、新增、删除、启用、停用分块；不需要审核。新增分块时选择插入在哪个分块之后。
  • 保留完整修订历史（版本号、编辑人、时间），可回滚到任一版本；编辑后自动重建该分块的索引。
  • 父子分块时，分块列表按父块展示，每个父块下可展开查看其子块；父块、子块分别编辑。编辑父块后，其子块按入库方案自动重新切分，子块上的人工修改会被覆盖，保存前提示。
  • 方案开启了分块增强时，分块列表中可查看每个分块的增强内容（上下文说明、假设问题、摘要、关键词），只读；编辑或新增分块后自动为该分块重新生成增强内容。
  • 编辑后的分块同样做超长检查（见 4.4），超长时不能保存。

重新解析

  • 重新解析提供两种方式，任何文档都可以选：
    • 重新解析：解析结果和分块全部按方案重新生成，覆盖所有人工修改；
    • 仅重新分块：沿用现有解析结果（含人工修改），只按方案重新分块，覆盖分块上的修改。不再调用解析引擎，适合只改了分块设置的情况，扫描件不会再次 OCR。快照中的解析设置保持不变，只更新分块设置和分块增强。
  • 文档有人工修改时，弹窗先列出“解析结果有人工修改”和“N 处分块有人工修改”，说明每种方式会覆盖哪些修改。批量重新解析时统一选择方式，有人工修改的文档在确认弹窗中汇总列出。
  • 重新入库期间，旧分块在被替换前仍可被检索。

4.6 问答库

  • 问答对包含：一个标准问、多个相似问、一个答案（Markdown，可含图片和链接）、所属分类、启用状态。
  • 分类为问答库内的分类树。
  • 手工增、删、改、启停问答对。
  • Excel 批量导入导出：提供模板下载；导入时可选“追加”或“覆盖全部”；导入后逐行给出失败原因。
  • 检索：用户问题同时与标准问、相似问匹配（向量 + 关键词），返回命中的问答对和得分；可按分类过滤（含下级分类）。
  • 本阶段不做：反例问、多答案随机返回、由大模型从文档自动生成问答对。
  • “命中分数足够高时直接返回答案、不经过大模型”以及“问答库优先于文档库”属于问答应用的配置，在 M3 中定义。

4.7 检索配置与命中测试

检索配置：知识库上保存一套默认值；应用引用知识库时可以覆盖。

  • 检索方式：向量、全文、混合；混合时两路的权重（融合方式在技术方案中确定）。
  • 召回数量（Top K）、分数阈值。开启重排时，阈值作用于重排分数；未开启时作用于融合后的分数（只用一路检索时即该路分数）。
  • 重排：开关、重排模型、重排后保留条数。
  • 过滤：文档库可按元数据、文件夹过滤；问答库可按分类过滤。
  • 父子分块不设开关：文档使用父子分块时，命中子块一律返回所在父块（见 4.4）。
  • 相邻分块扩展：命中分块时一并返回前后 N 个分块，N 取 0–3，默认 0。
  • 查询改写、多轮对话问题合并属于问答应用，在 M3 中定义。

命中测试

  • 输入问题，按步骤分别展示向量召回、全文召回、融合、重排的结果和得分。
  • 可临时调整检索配置再测，满意后“保存为默认配置”。
  • 点击结果可查看分块在原文中的位置。测试记录不保存。
  • 文档库与问答库共用同一命中测试页面。

4.9 权限

知识库按 10.4 的统一规则控制（可见范围 + 协作者）。下表是三类操作在知识库上的具体内容：

  • 问答时不按文档做权限过滤。

4.10 处理队列与存储

  • 解析任务在各知识库之间轮流处理，每个知识库同时占用的并发数有上限（管理员可配置），大批量上传只会拖慢自己的知识库。
  • 文档解析由独立部署的解析服务完成；Docling（含 CPU OCR）随解析服务默认部署，PaddleOCR、MinerU 为可选组件或云端 API（见 4.4）。
  • 原文件、解析结果和图片存储在 S3 兼容的对象存储中；部署包附带 RustFS，也可接客户已有的对象存储。

4.11 审计与用量

  • 写入审计日志：创建、删除知识库；修改可见范围；增减协作者；停用、启用知识库；删除和批量删除文档；删除和批量删除问答对、以“覆盖全部”方式导入问答对；创建、修改、删除入库方案。
  • 上传文档、编辑分块和解析结果不写审计日志（分块有修订历史）。
  • 入库时调用向量化模型（向量化、语义分块）和对话模型（分块增强）产生的用量计入模型用量统计，来源记为“入库”；PaddleOCR、MinerU 云端 API 不经过模型服务，不计入模型用量，解析记录中记下处理页数；命中测试、方案试运行产生的用量同样计入，来源分别记为“命中测试”“方案试运行”。

4.12 本阶段不做

  • 同义词 / 关键词映射。
  • 图片描述（用视觉模型为图片生成文字描述；做的时候再在模型服务中增加视觉模型）。
  • 知识图谱、Wiki 自动生成。
  • 外部数据源同步、对接外部知识库（如 Dify）。
  • 音视频、wps、ofd、epub。
  • 按文件夹路径自动识别元数据。
  • Late Chunking、命题分块、由大模型决定切分。
  • 文档历史版本；知识库内容（文档与分块）导出。
  • 文档级权限。

搭建者自己的资源创建知识库、入库方案、应用等资源；管理自己创建的资源，编辑被加为协作者的资源；使用模型体验
终端用户—只使用发布给自己的应用，不进入控制台
  • 系统管理员不属于任何组织。
  • 组织管理员由系统管理员或上级组织的组织管理员任命和撤销；组织管理员不能任命或撤销同级的组织管理员。
  • 账号管理边界：组织管理员只能管理范围内的搭建者、终端用户，以及下级组织的组织管理员；同级、上级组织管理员和系统管理员的账号不能操作。每个用户只属于一个组织，因此“谁能管这个账号”没有歧义，也避免通过重置密码接管他人账号。
  • 以后需要更细的角色（如“只能维护知识库、不能发布应用”）时再增加自定义角色。
  • 服务端对所有接口做权限校验，不依赖前端隐藏入口。

10.2 用户管理

已定：用户全部由本平台创建，不对接 SSO。
  • 管理员创建用户：用户名（唯一，不区分大小写）、初始密码、姓名、邮箱、手机、备注、所属组织（一个）、角色（一个）。所属组织只能选操作人管理范围内的组织。
  • 用户列表：按组织（含下级）、角色、状态、关键字筛选。
  • 编辑用户资料；在管理范围内调整所属组织和角色；启用、停用（停用后不要求立即踢下线，已登录的会话最迟在访问令牌到期时失效，见 10.5）。
  • 调整所属组织后，用户在原组织创建的资源留在原组织，由原组织的组织管理员管理；本人不再拥有这些资源的创建人权限，需要时可被加为协作者。
  • 管理员重置密码；管理员可解锁因登录失败被锁定的用户（见 10.5）。
  • 用户只做停用，不提供删除；停用后其账号、创建的资源和审计记录都保留。
  • 记录创建人、创建时间、最后登录时间。
  • 个人中心：用户查看自己的资料，修改姓名、邮箱、手机，修改密码（需输入原密码）；用户名、所属组织、角色只读。

10.3 组织管理

已定：组织树先由管理员手工维护；不做组织停用。
  • 多级树结构，对应子公司、部门。系统管理员建顶级组织；组织管理员在自己的组织下建、改、删下级组织。
  • 组织属性：名称、上级组织（创建后不可修改）、备注。
  • 删除组织的前提：无下级组织、无用户、无资源。组织内只要还有资源（知识库、应用、入库方案等），就禁止删除，需先删除资源。资源在组织间迁移本阶段不做。
  • 组织成员：列出本组织的用户及其角色。要把其他组织的用户调进来，在用户管理中修改其所属组织。

10.4 资源权限（可见范围与协作者）

已定：知识库、入库方案、应用等所有资源用同一套规则；模型除外，只由系统管理员管理（见 3.3）。
  • 每个资源记录所属组织（创建人创建时所在的组织）和创建人，数据按组织隔离。
  • 可见范围三档：仅自己、本组织、全平台。“本组织”包含下级组织，例如公司级知识库设为“本组织”，下面各部门都能看到。入库方案的可见范围固定为全平台。
  • 协作者：资源可以添加任意组织的用户为协作者，协作者能查看和编辑资源内容。协作者只有这一档，不细分。
操作谁能做
查看、在应用中引用可见范围内的人、协作者，以及下面能编辑、能管理的人
编辑内容创建人、协作者、管理范围内的组织管理员、系统管理员
修改可见范围、增减协作者、停用、删除创建人、管理范围内的组织管理员、系统管理员
  • 搭建者、组织管理员、系统管理员可以创建资源；终端用户不能。
  • 缩小可见范围或移除协作者时，如果有应用因此不能再引用该资源，禁止操作，列出这些应用，需先解除引用（知识库见 4.2）。
  • 一套部署只服务一家公司（集团），多个顶级组织是同一集团下的子公司；“全平台”即集团内共享，不另设“本公司”一档。
  • 创建人调走、停用后，资源由所属组织的组织管理员管理；把资源转交给其他创建人本阶段不做。

10.5 登录与账号安全

已定：因为不做 SSO，平台账号密码是唯一认证方式；密码与登录策略按业内主流做法，下列数值为默认值，管理员可调整。
  • 密码强度：长度不少于 8 位，包含大写字母、小写字母、数字、符号中的至少 3 类；不得与用户名相同；拒绝常见弱密码。
  • 密码存储：使用加盐的慢哈希（如 bcrypt 或 argon2），不可逆。
  • 首次登录以及管理员重置密码后，强制用户修改密码。
  • 登录防护：同一用户名从同一来源 IP 连续失败 5 次，锁定该用户名在该 IP 的登录 15 分钟，其他 IP 不受影响，防止他人故意输错把账号锁住；管理员可手动解锁。登录失败统一提示“用户名或密码错误”，不提示剩余次数，避免暴露用户名是否存在。登录成功与失败都记录。
  • 会话：使用短期访问令牌加刷新令牌，两者有效期可配置（默认访问令牌 15 分钟、刷新令牌 7 天）。停用用户、修改密码、管理员重置密码后，不要求立即失效：刷新令牌随即作废，已签发的访问令牌最迟在到期时失效。
  • 不强制定期更换密码（遵循 NIST 建议），但提供管理员强制重置的能力。
  • 传输必须使用 HTTPS。

10.6 审计日志

  • 记录事件：登录成功与失败；用户、组织的增删改，用户角色和所属组织的调整；可见范围变更、协作者增减；资源发布、删除；模型密钥与 API Key 的创建、修改、吊销；系统设置的修改。
  • 每条记录包含：时间、操作人、操作人所属组织、动作、对象、对象所属组织、结果、来源 IP。系统管理员不属于任何组织，其“操作人所属组织”为空。
  • 日志只增不改。可按时间、操作人、动作、对象、组织筛选。
  • 查看范围：系统管理员看全部；组织管理员看“操作人所属组织”或“对象所属组织”在其管理范围内的记录。这样其他组织的协作者修改了本组织的资源，本组织的管理员也能看到。
  • 永久保存，不做自动清理。日志导出本阶段不做。

10.7 管理员资源总览

已定：参考万悟管理员中心，为管理员提供跨资源的全局列表。
  • 系统管理员可查看全平台的资源列表；组织管理员可查看本组织及下级组织的资源列表。
  • 覆盖资源类型：知识库、入库方案、应用、提示词、工具、MCP 等，随各模块上线逐步纳入。模型不属于任何组织，在模型管理页统一查看，不进资源总览。
  • 列表显示名称、类型、所属组织、创建人、可见范围、创建时间，可按这些条件筛选。
  • 系统管理员和组织管理员（管理范围内）都可以在总览中查看、编辑、停用、删除资源，调整可见范围、增减协作者。

10.8 系统设置

已定：文档中所有“管理员可调”的平台参数集中在系统设置页，只有系统管理员可见。
  • 密码与登录：密码最小长度、需包含的字符类别数、登录失败锁定次数和锁定时长（见 10.5）。
  • 会话：访问令牌、刷新令牌的有效期（见 10.5）。
  • 上传与解析：单个文件大小上限、同时解析的文档数、每个知识库最多占用的解析并发数（见 4.2、4.10）。
  • 模型调用：入库占用模型限额的比例、模型接口地址白名单（见 3.4、3.5）。
  • 解析引擎：PaddleOCR、MinerU 的自建服务地址或云端 API 密钥，可测试连接；未配置的引擎在入库方案中不可选（见 4.4）。
  • 修改写入审计日志。

10.9 本阶段不做

  • SSO / 统一登录对接。
  • 组织树从 HR 或通讯录同步。
  • 批量导入用户。
  • 删除用户（只做停用）。
  • 一个用户属于多个组织；自定义角色。
  • 组织停用。
  • 资源在组织之间迁移；修改组织的上级组织（移动子树）；资源转交创建人。
  • 只读协作者（协作者只有“可编辑”一档）。
  • 审计日志导出。
  • 资源发布到全平台的审批流程。
  • OAuth 应用管理（万悟有，给第三方系统对接用，与 API Key 重叠）。
  • 知识库内的文档级权限。

10.10 系统管理待定问题

  • 终端用户是不是平台账号（讨论 M3 时确定）：已发布的 Web 对话页是否要求登录平台账号；能否匿名访问；嵌入组件如何认证。初步想法：默认要求平台账号登录，是否允许匿名访问作为每个应用的开关。“终端用户”目前是四个固定角色之一，确定后再看是否调整。
