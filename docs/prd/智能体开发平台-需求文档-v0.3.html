智能体开发平台 需求文档

v0.3 · 2026-10-21 · 草稿

读者：研发团队。本版只列出大的功能模块，并说明每个模块需要做什么。优先级、详细功能和验收标准在后续版本中逐个补充。

1. 功能模块一览

编号模块一句话说明
M1模型服务统一接入和管理平台使用的各类模型
M2资源库沉淀知识库、工具、提示词等可被应用复用的资源
M3应用开发用资源和模型搭建知识问答、工作流、智能体，并发布给使用者
M4探索广场浏览和复用平台内已发布的应用、模板与共享资源

M6通用智能体面向全员、开箱即用的通用助手
M7API Key 管理让外部程序以受控方式调用已发布应用

2. 各模块需要做的事情

M1 模型服务

目标：让平台能统一使用各类模型，使用者不用关心接入细节。
  • 接入对话（Chat）、向量化（Embedding）、重排（Rerank）、OCR/视觉（VLM）等类型的模型。
  • 系统管理员配置全平台共享的模型；组织管理员可追加本组织自己的模型与密钥。
  • 模型密钥加密保存，界面和接口不暴露明文。
  • 可测试模型是否可用；可启用、停用模型。
  • 提供在线对话体验，并支持多个模型对比效果。

M2 资源库

目标：把应用开发要用的素材集中管理，一次建好、多处引用。
  • 知识库（重点）：上传、更新、删除文档并查看解析进度与失败原因；配置解析与分块方式；查看和编辑分块；配置检索并用命中测试验证召回效果；按用户授权。后续补充问答对与同义词、入库时的上下文增强、外部数据源同步。
  • MCP 服务：接入外部 MCP Server，并按工具粒度启用。
  • 插件工具：提供内置工具，并支持导入 OpenAPI 描述的自定义工具。
  • 提示词：管理提示词模板与版本，并支持对提示词做评测。
  • Skills：管理技能包，并在沙箱中执行。
  • 安全护栏：对输入输出做过滤，支持敏感词与提示词注入检测。
  • 所有资源可见范围分三档：仅自己、本组织、全平台，并能被应用以统一方式引用。

M3 应用开发

目标：让搭建者把模型和资源组合成可用的应用，并发布出去。
  • 知识问答（重点）：基于知识库的问答应用；检索策略按应用配置；支持多轮对话；回答带引用，点击可定位到原文；每次问答可调试回放。
  • 工作流（重点）：可视化编排，支持分支、循环、并行、人工介入与断点续跑。
  • 智能体：组合模型、知识库、工具、MCP 与记忆，支持多步检索与推理。
  • 应用发布：发布为 Web 对话页（含手机浏览器）、嵌入组件和 API；终端用户可查看历史会话，并对回答点赞、点踩、纠错。

M4 探索广场

目标：让大家发现并复用已有成果，减少重复搭建。
  • 应用广场：浏览并使用发布到全平台的应用。
  • 模板、MCP、Skill 广场：复用模板和共享资源。

M5 应用观测

目标：让运行情况和问答效果可见、可衡量。
  • 统计看板：展示调用量、Token 用量与活跃度（仅统计，不计费）。
  • 链路追踪（重点）：回放每次对话的查询改写、召回、重排、上下文与模型调用。
  • 效果评测（重点）：评测集可来自人工导入、大模型按文档生成、终端用户点踩转入；衡量召回、答案正确性、引用准确性与拒答；同一评测集可对比两套检索配置。

M6 通用智能体

目标：给全体员工一个开箱即用的助手，不需要自己搭建。
  • 提供面向全员的通用 AI 助手入口。

M7 API Key 管理

目标：让外部系统安全地调用平台上的应用。
  • 创建、吊销 API Key，并绑定到具体应用。
  • 后续支持细分权限范围。

M8 系统管理

目标：管好谁能用、能用什么，并留下可追溯的记录。
  • 用户与组织：多级组织树，对应子公司、部门；一个用户可属于多个组织并切换当前组织。
  • 角色与权限：组织内可自定义角色；系统管理员可建全局角色；功能权限与资源权限按角色和授权控制。
  • 资源归属与隔离：所有资源与应用记录所属组织和创建人，数据按组织隔离。
  • 登录与账号安全：用户由平台创建，使用平台账号密码登录（本阶段不对接 SSO）。
  • 审计：对权限变更、发布、删除、密钥操作等关键动作留日志。

详细需求见第 3 节。

3. 系统管理（详细需求）

功能组织、用户与角色模型参考联通万悟（wanwu）管理员中心的实现。以下“已定”表示已与产品负责人确认，“待定”表示尚未决定。

3.1 角色与边界

角色范围能做什么
系统管理员全平台创建顶级组织；创建全局角色并跨组织分配；管理全平台共享模型；查看全部审计日志
组织管理员所在组织及其下级组织创建下级组织；在本组织内创建用户、邀请已有用户加入；创建组织内角色并分配；管理本组织的模型与资源；查看本组织审计日志
普通成员按所属角色由角色权限和资源授权决定

每个组织创建时自带一个“组织管理员”角色，不可删除。

3.2 用户管理

已定：用户全部由本平台创建，不对接 SSO；用户管理方式参考万悟。
  • 管理员创建用户：用户名、初始密码、姓名、邮箱、手机、备注；创建时指定所属组织与角色。
  • 用户列表：按组织、角色、状态、关键字筛选。
  • 编辑用户信息；启用、停用（停用后已有登录会话立即失效）。
  • 管理员重置密码；用户本人修改密码。
  • 用户只做停用，不提供删除；停用后其账号、创建的资源和审计记录都保留。批量导入用户本阶段不做。
  • 记录创建人、创建时间、最后登录时间。
  • 已有用户可被邀请加入其他组织，并在该组织分配角色。

3.3 组织管理

已定：组织树先由管理员手工维护。
  • 多级树结构，对应子公司、部门。系统管理员建顶级组织；组织管理员在自己的组织下建、改、停用、删除下级组织。
  • 组织属性：名称、备注、状态（启用/停用）。
  • 一个用户可属于多个组织，在界面上切换当前组织；所有操作按“当前组织”下的角色判断权限。
  • 删除组织的前提：无下级组织、无成员、无资源。组织内只要还有资源（知识库、应用、模型等），就禁止删除，需先逐个删除资源。资源在组织间迁移本阶段不做。
  • 组织成员管理：添加、移除成员，修改成员在本组织的角色。

3.4 角色与权限

已定：权限做到资源级；同一用户在同一组织只有一个角色，在不同组织可以有不同角色。

角色

  • 全局角色：系统管理员创建，可分配给任意组织的用户。
  • 组织角色：组织管理员在本组织内创建、编辑、启停、删除。
  • 角色删除前需先移除其关联用户。

功能权限：按模块和操作组成权限树（如：知识库→创建、编辑、删除），创建角色时勾选。创建者只能授予自己已有的权限，防止越权。系统管理类权限默认不对普通角色开放。

资源权限

  • 知识库：按用户授权，分查看、编辑、授权三档，只到知识库级，不做文档级。
  • 其他资源（应用、提示词、工具、MCP 等）：本阶段靠三档可见范围控制；权限模型预留扩展，后续可按同样方式支持按用户授权。
  • 服务端对所有接口做权限校验，不依赖前端隐藏入口。

3.5 资源归属与可见范围

  • 所有资源和应用记录所属组织与创建人，数据按组织隔离。
  • 可见范围分三档：仅自己、本组织、全平台。
  • 下级组织不自动继承上级组织的资源，需显式发布到全平台。
  • 创建人离职或被停用后资源如何交接：本阶段不考虑。

3.6 登录与账号安全

已定：因为不做 SSO，平台账号密码是唯一认证方式；密码与登录策略按业内主流做法，下列数值为默认值，管理员可调整。
  • 密码强度：长度不少于 8 位，包含大写字母、小写字母、数字、符号中的至少 3 类；不得与用户名相同；拒绝常见弱密码。
  • 密码存储：使用加盐的慢哈希（如 bcrypt 或 argon2），不可逆。
  • 首次登录以及管理员重置密码后，强制用户修改密码。
  • 登录防护：连续失败 5 次锁定 15 分钟；登录成功与失败都记录。
  • 会话：登录有效期和空闲超时可配置；修改密码、停用用户后旧会话失效。
  • 不强制定期更换密码（遵循 NIST 建议），但提供管理员强制重置的能力。
  • 传输必须使用 HTTPS。

3.7 审计日志

  • 记录事件：登录成功与失败；用户、组织、角色的增删改；权限与授权变更；资源发布、可见范围变更、删除；模型密钥与 API Key 的创建、修改、吊销。
  • 每条记录包含：时间、操作人、所属组织、动作、对象、结果、来源 IP。
  • 日志只增不改。可按时间、操作人、动作、对象筛选。
  • 查看范围：系统管理员看全部，组织管理员看本组织。
  • 永久保存，不做自动清理。日志导出本阶段不做。

3.8 管理员资源总览

已定：参考万悟管理员中心，为管理员提供跨资源的全局列表。
  • 系统管理员可查看全平台的资源列表；组织管理员可查看本组织及下级组织的资源列表。
  • 覆盖资源类型：知识库、模型、应用、提示词、工具、MCP 等，随各模块上线逐步纳入。
  • 列表显示名称、类型、所属组织、创建人、可见范围、创建时间，可按这些条件筛选。
  • 系统管理员对所有资源拥有全部操作权限（查看、编辑、停用、删除、调整可见范围等）。
  • 组织管理员在总览中本阶段只能查看；对本组织资源的操作按其角色权限与资源授权执行。

3.9 本阶段不做

  • SSO / 统一登录对接。
  • 组织树从 HR 或通讯录同步。
  • 批量导入用户。
  • 删除用户（只做停用）。
  • 资源在组织之间迁移。
  • 审计日志导出。
  • 资源发布到全平台的审批流程。
  • OAuth 应用管理（万悟有，给第三方系统对接用，与 API Key 重叠）。
  • 知识库内的文档级权限。
  • 用户离职或停用后的资源交接。
