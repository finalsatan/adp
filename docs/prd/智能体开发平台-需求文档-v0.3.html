1. 功能模块一览

编号模块一句话说明
M1模型服务统一接入和管理平台使用的各类模型
M2资源库沉淀知识库、工具、提示词等可被应用复用的资源
M3应用开发用资源和模型搭建知识问答、工作流、智能体，并发布给使用者
M4探索广场浏览和复用平台内已发布的应用、模板与共享资源

2. 各模块需要做的事情

M1 模型服务

目标：让平台能统一使用各类模型，使用者不用关心接入细节。
  • 接入对话（Chat）、向量化（Embedding）、重排（Rerank）、OCR/视觉（VLM）等类型的模型。
  • 系统管理员配置全平台共享的模型；组织管理员可追加本组织自己的模型与密钥。
  • 模型密钥加密保存，界面和接口不暴露明文。
  • 可测试模型是否可用；可启用、停用模型。
  • 提供在线对话体验，并支持多个模型对比效果。

详细需求见第 3 节。

M2 资源库

目标：把应用开发要用的素材集中管理，一次建好、多处引用。
  • 知识库（重点）：分文档库和问答库；上传、更新、删除文档并查看入库进度与失败原因；用可复用的入库方案配置解析、分块和分块增强；查看和修改解析结果与分块；维护问答对；配置检索并用命中测试验证召回效果；引用定位到原文；按用户授权。后续补充同义词、外部数据源同步。
  • MCP 服务：接入外部 MCP Server，并按工具粒度启用。
  • 插件工具：提供内置工具，并支持导入 OpenAPI 描述的自定义工具。
  • 提示词：管理提示词模板与版本，并支持对提示词做评测。
  • Skills：管理技能包，并在沙箱中执行。
  • 安全护栏：对输入输出做过滤，支持敏感词与提示词注入检测。
  • 所有资源可见范围分三档：仅自己、本组织、全平台，并能被应用以统一方式引用。

详细需求见第 4 节（目前已细化知识库和入库方案）。

M3 应用开发

目标：让搭建者把模型和资源组合成可用的应用，并发布出去。
  • 知识问答（重点）：基于知识库的问答应用；检索策略按应用配置；支持多轮对话；回答带引用，点击可定位到原文；每次问答可调试回放。
  • 工作流（重点）：可视化编排，支持分支、循环、并行、人工介入与断点续跑。
  • 智能体：组合模型、知识库、工具、MCP 与记忆，支持多步检索与推理。
  • 应用发布：发布为 Web 对话页（含手机浏览器）、嵌入组件和 API；终端用户可查看历史会话，并对回答点赞、点踩、纠错。

M4 探索广场

目标：让大家发现并复用已有成果，减少重复搭建。
  • 应用广场：浏览并使用发布到全平台的应用。
  • 模板、MCP、Skill 广场：复用模板和共享资源。

M5 系统观测

目标：让运行情况、问答效果和模型用量可见、可衡量。下设两个子菜单：应用观测、用量统计。
  • 用量统计：按模型、应用、组织、用户统计调用量与 Token 用量，含模型体验页的调用（仅统计，不计费）。
  • 应用观测：包含下面三项。
  • 统计看板：展示应用的调用量与活跃度。
  • 链路追踪（重点）：回放每次对话的查询改写、召回、重排、上下文与模型调用。
  • 效果评测（重点）：评测集可来自人工导入、大模型按文档生成、终端用户点踩转入；衡量召回、答案正确性、引用准确性与拒答；同一评测集可对比两套检索配置。

M6 通用智能体

目标：给全体员工一个开箱即用的助手，不需要自己搭建。
  • 提供面向全员的通用 AI 助手入口。

M7 API Key 管理

目标：让外部系统安全地调用平台上的应用。
  • 创建、吊销 API Key，并绑定到具体应用。
  • 后续支持细分权限范围。

M8 系统管理

目标：管好谁能用、能用什么，并留下可追溯的记录。
  • 用户与组织：多级组织树，对应子公司、部门；一个用户可属于多个组织并切换当前组织。
  • 角色与权限：组织内可自定义角色；系统管理员可建全局角色；功能权限与资源权限按角色和授权控制。
  • 资源归属与隔离：所有资源与应用记录所属组织和创建人，数据按组织隔离。
  • 登录与账号安全：用户由平台创建，使用平台账号密码登录（本阶段不对接 SSO）。
  • 审计：对权限变更、发布、删除、密钥操作等关键动作留日志。

详细需求见第 10 节。

3. M1 模型服务（详细需求）

原型：prototype/style-a1-antd.html。接入方式、范围与可见性参考联通万悟（wanwu）的模型管理。以下均为已与产品负责人确认的结论。

3.1 接入方式

  • 平台所有模型调用统一经由 LiteLLM 转发，由它屏蔽各供应商的协议差异，平台不自写各家 SDK 适配。
  • 只接云端模型供应商，不做本地部署模型的托管。
  • 管理员添加模型时填写：显示名称、供应商/模型 ID、类型、接口地址（可选）、密钥、能力参数。
  • LiteLLM 以 Python SDK 方式嵌入后端，不单独部署 proxy 服务（见技术方案）。

3.2 模型类型与能力参数

  • 类型：对话（Chat）、向量化（Embedding）、重排（Rerank）、OCR/视觉（用于文档解析）。语音识别、文生图本阶段不做。
  • “支持视觉输入”是 Chat 模型的能力开关，不单列类型。
  • Chat 模型声明：上下文长度、最大输出、是否支持视觉、是否支持函数调用、是否支持深度思考开关，以及默认参数（温度、top_p 等）。
  • Embedding 模型声明：向量维度。
  • 应用开发选模型时按能力过滤，例如只列出支持函数调用的模型。
  • 系统提示词不在模型上配置，由应用决定。

3.3 范围与权限

  • 可见范围只有两档：全平台共享（仅系统管理员可设置）和本组织（组织管理员设置）。不做“仅自己”，因为密钥属于组织资产。
  • 用户只能选择自己有权看到的模型；看不到密钥明文。
  • 密钥加密保存，界面和接口均不返回明文，只显示末几位。
  • 创建、修改、停用、删除模型及密钥变更，都写入审计日志。

3.4 模型管理

  • 列表：按类型、范围、状态、所属组织、关键字筛选。
  • 测试连通：保存前后均可测试，发送一条简短请求，显示成功/失败、耗时和返回内容；失败时显示原因，如密钥无效、模型不存在、连接超时（10 秒）。
  • 启用、停用：停用允许，界面提示受影响的应用清单；应用运行时提示“模型不可用”。
  • 删除：被应用或知识库引用时禁止删除，需先解除引用。
  • 知识库创建后不允许更换 Embedding 模型，只能新建知识库。
  • 批量替换应用里的模型：本阶段不做。

3.5 调用稳定性

  • 可配置调用超时和失败重试次数。
  • 对全平台共享模型按模型设置限流（QPS 与并发），防止单个应用占满共享额度。
  • 不做组织或用户级配额；用量在 M5 用量统计中按组织查看，事后可追溯。
  • 主模型失败后自动切换备用模型：本阶段不做。

3.6 模型体验

  • 所有登录用户可用，只能选自己有权限看到的模型。
  • 可调整温度、最大输出等参数；支持多模型对比，最多同时 4 个。
  • 对话记录不保存。
  • 体验页的调用计入用量统计。

3.7 本阶段不做

  • 本地部署模型的托管。
  • 语音识别、文生图模型。
  • 组织、用户级的用量配额与计费。
  • 备用模型自动切换。
  • 应用内模型批量替换。

3.8 模型服务待定问题

  • 暂无。

4. M2 资源库（详细需求）

原型：prototype/style-a1-antd.html。本节先细化知识库和入库方案；MCP 服务、插件工具、提示词、Skills、安全护栏待细化。参考万悟（wanwu）和 WeKnora，调研见 docs/research/知识库模块调研-万悟与WeKnora.html。术语以仓库根目录 GLOSSARY.md 为准。以下均为已与产品负责人确认的结论。

4.1 概念与范围

概念说明
知识库可被应用引用的资源，分文档库和问答库两种类型，创建后类型不可改。
文档上传到文档库中的一个文件。
入库方案针对一种文件类型的解析设置、分块设置和分块增强开关。可跨知识库复用，上传时选用。
解析结果文档经解析引擎转换得到的带结构的文本，分块由它切出。
分块解析结果切出的一段内容，是检索和引用的最小单位。
问答对问答库中的一条知识：一个标准问、若干相似问、一个答案。

菜单位置：资源库 → 知识库、入库方案。

4.2 知识库管理

  • 创建时填写：类型（文档库 / 问答库）、名称、描述、向量化模型、可见范围。类型和向量化模型创建后不可修改；要换向量化模型只能新建知识库。
  • 创建后可设置：各文件类型的默认入库方案（仅文档库）、默认检索配置。
  • 列表：按类型、可见范围、所属组织、关键字筛选；显示文档数或问答对数、分块数、更新时间。
  • 停用：引用它的应用检索不到其内容，但应用本身不报错。
  • 删除：被应用引用时禁止删除，需先解除引用；删除前列出引用它的应用。
  • 容量默认值（管理员可调）：单个文件不超过 200MB；单个知识库文档数不设上限；同时解析的文档数由管理员配置。

上传

  • 可一次上传多个文件，也可上传整个本地文件夹（保留目录结构）。
  • 混合类型上传时按文件类型分组，每组选一个入库方案，默认选中知识库为该类型设的默认方案；未设置时用平台内置的该类型通用方案。
  • 同名文件：让用户选择“替换”（覆盖原文档并重新入库，不保留历史版本）或“保留两份”。
  • 内容重复：按文件内容哈希判断，同一文档库内提示“与已有文档 X 内容相同”，让用户选择“跳过”或“仍然上传”。不同文档库之间不检查。
  • 上传后直接走完整个入库流程，中间不停下来等确认。

文件夹

  • 多级文件夹；一个文档只属于一个文件夹；可在文件夹间移动文档。
  • 文件夹不单独设权限。检索时可按文件夹过滤（含下级）。

元数据

  • 每个文档库自定义元数据字段，类型：文本、数字、日期、单选。
  • 可对单个文档设值，也可批量设值。
  • 系统字段（只读）：文件名、文件类型、上传人、上传时间、所在文件夹。
  • 检索时可按元数据过滤，条件可用“且 / 或”组合。

文档状态与操作

  • 入库状态依次为：排队中 → 解析中 → 分块中 → 向量化中 → 已完成；任一步出错为“失败”，显示失败原因。
  • 失败文档可单个或批量重试。
  • 文档可启用、停用；停用的文档不参与检索，但保留不删。
  • 删除文档同时删除原文件、解析结果、分块和索引，不可恢复。
  • 有人工修改（解析结果或分块）的文档在列表中加标记。
  • 查看文档详情时显示所用入库方案的名称和参数快照。

4.4 入库方案

  • 一个方案只针对一种文件类型，包含三部分：解析设置、分块设置、分块增强。
  • 入库方案是资源，可见范围分仅自己、本组织、全平台三档，不做按用户授权；只有创建人和管理员能修改。
  • 平台为每种文件类型内置至少一个通用方案（全平台可见、只读），如“PDF · 通用”“PDF · 扫描件”“Excel · 表格”。
  • 文档入库时记录所用方案，并保存一份完整参数快照。修改方案不影响已入库的文档。
  • 重新解析时默认使用该方案的当前参数，也可以改选其他方案。
  • 删除方案：被任一知识库设为默认方案时禁止删除；只被文档用过的可以删除（文档有快照）。
  • 方案编辑页可上传一个样例文件试运行，查看解析结果和分块效果后再保存。
  • 导入导出：方案可导出为 JSON 文件，并在其他环境导入。导入时按模型 ID 自动匹配当前环境的模型，找不到的提示重新选择；与已有方案重名时自动改名（加“（导入）”），可再修改。

解析设置：界面直接显示解析引擎名称；未部署的引擎不出现在选项中。

文件类型可选解析引擎
PDFpypdfium（只读文字层，最快）、Docling、MinerU（可选组件）、OCR 模型、视觉模型
Word、PPTDocling、MarkItDown
Excel、CSV内置表格解析
Markdown、TXT、HTML内置解析
图片OCR 模型、视觉模型
  • “OCR 模型”“视觉模型”调用 M1 中登记的 OCR/视觉模型，需在方案中选定具体模型。
  • MinerU、本地 PaddleOCR 为可选部署组件，部署环境有 GPU 时才启用。
  • 预处理规则：合并多余空白、删除页眉页脚、删除链接和邮箱等，可逐项开关。
  • 表格：Excel、CSV 不使用分块方式，按行分块，每块带表头；可设每块行数（默认 20）、表头所在行（默认 1）、处理哪些工作表（默认全部，仅 Excel）；PDF、Word 中的表格整表作为一个分块，过长时按行拆分，每块带表头。
  • 图片：文档中的图片提取保存，分块中保留图片位置，回答和引用预览时可显示原图；方案开启 OCR 时，图片中的文字并入所在分块。

按长度按分隔符逐级切分，仍超长时按长度截断分隔符（段落、换行、句号、分号，可多选，可自定义，按顺序逐级尝试）；最大长度（800）；重叠长度（80）无结构的长文本
按规则用正则表达式定义切分点（如“第X条”），超长再按长度细分切分规则（可多条，任一条匹配即切分）；匹配文字作为分块标题（开）；最大长度（800）合同、法规
按页按页切分（仅 PDF、PPT），单页超长时再细分每块页数（1）；最大长度（800）幻灯片、版式固定的文件
整篇不切分，超长时退回按长度最大长度（8000）短通知、一页纸制度
语义按相邻句子的语义相似度在话题变化处断开；使用文档所在知识库的向量化模型，方案中不单独选择；入库较慢断开灵敏度（低、中、高，默认中）；最小长度（100）；最大长度（800）无标题、话题跳跃的长文
  • 长度均按 token 计。界面上只显示所选分块方式的参数。
  • 父子分块：可叠加在任一分块方式之上的开关，默认关闭。检索用子块匹配，命中后返回所在父块。
    • 父块：按所选分块方式切分；该方式的最大长度、重叠长度改用“父块最大长度”（默认 4096），超过时按长度拆开。
    • 子块：在每个父块内按分隔符逐级切分（默认段落、句号，可自定义），仍超长时按长度截断；可设子块最大长度（默认 384）、子块重叠长度（默认 40）。
  • 分块开头可附带标题路径（如“第三章 > 3.2 差旅”），默认开启。
  • 表格按上面的表格规则处理，不受分块方式影响。

分块增强：均为可选开关，默认关闭；开启时需选择一个对话模型，会消耗 token、增加入库时间。

  • 上下文说明：为每个分块生成一句说明其在全文中位置和含义的文字，与分块一起向量化（Contextual Retrieval）。
  • 假设问题：为每个分块生成几个它能回答的问题，参与检索。
  • 摘要、关键词：为每个分块生成摘要和关键词，参与检索。
  • 表格摘要：为表格生成文字摘要，作为单独的分块。

4.5 解析结果与分块

解析结果

  • 原文与解析结果并排对照查看。
  • 可人工修改解析结果；修改后标记“已人工修改”，记录最后修改人和时间，不保留完整历史；可一键恢复为原始解析结果（原始结果始终保留）。
  • 保存修改时提示：“将按入库方案重新分块并重建索引，N 处分块手工修改将被覆盖”，确认后执行。

分块

  • 查看、编辑、新增、删除、启用、停用分块；不需要审核。新增分块时选择插入在哪个分块之后。
  • 保留完整修订历史（版本号、编辑人、时间），可回滚到任一版本；编辑后自动重建该分块的索引。
  • 父子分块时父块、子块分别维护。

重新解析

  • 文档有人工修改时，弹窗列出“解析结果有人工修改”和“N 处分块有人工修改”，提供三个选择：
    • 重新解析：解析结果和分块全部按方案重新生成，覆盖所有人工修改；
    • 仅重新分块：保留人工修改过的解析结果，只覆盖分块上的修改；
    • 取消。
  • 重新入库期间，旧分块在被替换前仍可被检索。

4.6 问答库

  • 问答对包含：一个标准问、多个相似问、一个答案（Markdown，可含图片和链接）、所属分类、启用状态。
  • 分类为问答库内的分类树。
  • 手工增、删、改、启停问答对。
  • Excel 批量导入导出：提供模板下载；导入时可选“追加”或“覆盖全部”；导入后逐行给出失败原因。
  • 检索：用户问题同时与标准问、相似问匹配（向量 + 关键词），返回命中的问答对和得分。
  • 本阶段不做：反例问、多答案随机返回、由大模型从文档自动生成问答对。
  • “命中分数足够高时直接返回答案、不经过大模型”以及“问答库优先于文档库”属于问答应用的配置，在 M3 中定义。

4.7 检索配置与命中测试

检索配置：知识库上保存一套默认值；应用引用知识库时可以覆盖。

  • 检索方式：向量、全文、混合；混合时两路的权重。
  • 召回数量（Top K）、分数阈值。
  • 重排：开关、重排模型、重排后保留条数。
  • 元数据过滤、文件夹过滤。
  • 父子分块不设开关：文档使用父子分块时，命中子块一律返回所在父块（见 4.4）。
  • 相邻分块扩展：命中分块时一并返回前后 N 个分块，N 取 0–3，默认 0。
  • 查询改写、多轮对话问题合并属于问答应用，在 M3 中定义。

命中测试

  • 输入问题，按步骤分别展示向量召回、全文召回、融合、重排的结果和得分。
  • 可临时调整检索配置再测，满意后“保存为默认配置”。
  • 点击结果可查看分块在原文中的位置。测试记录不保存。
  • 文档库与问答库共用同一命中测试页面。

4.8 引用定位与原文

文件类型定位方式
PDF打开原文预览，跳到对应页并高亮对应区域
Word、PPT转换为 PDF 预览，按页定位并高亮
Excel、CSV显示对应工作表和行范围
Markdown、TXT、HTML高亮对应段落
图片显示原图
  • 对知识库有“查看”权限的用户可下载原文件。
  • 终端用户在问答应用中点击引用，可预览被引用的页或段，不能下载整份原文件；是否允许下载由应用开关决定，在 M3 中定义。

4.9 权限

权限能做什么
查看浏览文档、解析结果、分块和问答对；命中测试；在自己搭建的应用中引用；下载原文件
编辑上传、删除、移动文档；修改解析结果、分块、问答对；修改元数据字段、默认入库方案、默认检索配置
授权给其他用户授权；修改可见范围；停用、删除知识库
  • 可见范围为“本组织”或“全平台”时，范围内所有人自动拥有“查看”权限；“编辑”“授权”只能单独授予。创建人拥有全部权限。
  • 终端用户使用已发布的问答应用时，不需要对知识库有任何权限。
  • “创建知识库”“创建入库方案”是功能权限，可以授予普通角色。
  • 问答时不按文档做权限过滤。

4.10 处理队列与存储

  • 解析任务在各知识库之间轮流处理，每个知识库同时占用的并发数有上限（管理员可配置），大批量上传只会拖慢自己的知识库。
  • 文档解析由独立部署的解析服务完成。
  • 原文件、解析结果和图片存储在 S3 兼容的对象存储中；部署包附带 RustFS，也可接客户已有的对象存储。

4.11 审计与用量

  • 写入审计日志：创建、删除知识库；修改可见范围；授予、收回授权；停用、启用知识库；删除和批量删除文档；创建、修改、删除入库方案。
  • 上传文档、编辑分块和解析结果不写审计日志（分块有修订历史）。
  • 入库时调用 OCR、视觉、向量化和对话模型（分块增强）产生的用量计入模型用量统计，来源记为“入库”。

4.12 本阶段不做

  • 同义词 / 关键词映射。
  • 图片描述（用视觉模型为图片生成文字描述）。
  • 知识图谱、Wiki 自动生成。
  • 外部数据源同步、对接外部知识库（如 Dify）。
  • 音视频、wps、ofd、epub。
  • 按文件夹路径自动识别元数据。
  • Late Chunking、命题分块、由大模型决定切分。
  • 文档历史版本；知识库内容（文档与分块）导出。
  • 文档级权限。

10. M8 系统管理（详细需求）

原型：prototype/style-a1-antd.html。功能组织、用户与角色模型参考联通万悟（wanwu）管理员中心的实现。以下“已定”表示已与产品负责人确认，“待定”表示尚未决定。

10.1 角色与边界

角色范围能做什么
系统管理员全平台创建顶级组织；创建全局角色并跨组织分配；管理全平台共享模型；查看全部审计日志
组织管理员所在组织及其下级组织创建下级组织；在本组织内创建用户、邀请已有用户加入；创建组织内角色并分配；管理本组织的模型与资源；查看本组织审计日志
普通成员按所属角色由角色权限和资源授权决定

每个组织创建时自带一个“组织管理员”角色，不可删除。

10.2 用户管理

已定：用户全部由本平台创建，不对接 SSO；用户管理方式参考万悟。
  • 管理员创建用户：用户名、初始密码、姓名、邮箱、手机、备注；创建时指定所属组织与角色（可多选）。
  • 用户列表：按组织、角色、状态、关键字筛选。
  • 编辑用户信息；启用、停用（停用后不要求立即踢下线，已登录的会话最迟在访问令牌到期时失效，见 10.6）。
  • 管理员重置密码；用户本人修改密码。
  • 用户只做停用，不提供删除；停用后其账号、创建的资源和审计记录都保留。批量导入用户本阶段不做。
  • 记录创建人、创建时间、最后登录时间。
  • 已有用户可被邀请加入其他组织，并在该组织分配角色（可多个）；可选的组织只限操作人有管理权限的组织。

10.3 组织管理

已定：组织树先由管理员手工维护。
  • 多级树结构，对应子公司、部门。系统管理员建顶级组织；组织管理员在自己的组织下建、改、停用、删除下级组织。
  • 组织属性：名称、备注、状态（启用/停用）。
  • 一个用户可属于多个组织，在界面上切换当前组织；所有操作按“当前组织”下的角色判断权限，有多个角色时取权限并集。
  • 删除组织的前提：无下级组织、无成员、无资源。组织内只要还有资源（知识库、应用、模型等），就禁止删除，需先逐个删除资源。资源在组织间迁移本阶段不做。
  • 组织成员管理：添加、移除成员，修改成员在本组织的角色（可多个）。

10.4 角色与权限

已定：权限做到资源级；同一用户在同一组织可以有多个角色，权限取并集；在不同组织可以有不同角色。

角色

  • 全局角色：系统管理员创建，可分配给任意组织的用户。
  • 组织角色：组织管理员在本组织内创建、编辑、启停、删除。
  • 角色删除前需先移除其关联用户。

功能权限：按模块和操作组成权限树（如：知识库→创建、编辑、删除），创建角色时勾选。创建者只能授予自己已有的权限，防止越权。系统管理类权限默认不对普通角色开放。

资源权限

  • 知识库：按用户授权，分查看、编辑、授权三档，只到知识库级，不做文档级。
  • 其他资源（应用、提示词、工具、MCP 等）：本阶段靠三档可见范围控制；权限模型预留扩展，后续可按同样方式支持按用户授权。
  • 服务端对所有接口做权限校验，不依赖前端隐藏入口。

10.5 资源归属与可见范围

  • 所有资源和应用记录所属组织与创建人，数据按组织隔离。
  • 可见范围分三档：仅自己、本组织、全平台。
  • 下级组织不自动继承上级组织的资源，需显式发布到全平台。
  • 创建人离职或被停用后资源如何交接：本阶段不考虑。

10.6 登录与账号安全

已定：因为不做 SSO，平台账号密码是唯一认证方式；密码与登录策略按业内主流做法，下列数值为默认值，管理员可调整。
  • 密码强度：长度不少于 8 位，包含大写字母、小写字母、数字、符号中的至少 3 类；不得与用户名相同；拒绝常见弱密码。
  • 密码存储：使用加盐的慢哈希（如 bcrypt 或 argon2），不可逆。
  • 首次登录以及管理员重置密码后，强制用户修改密码。
  • 登录防护：连续失败 5 次锁定 15 分钟；登录成功与失败都记录。
  • 会话：使用短期访问令牌加刷新令牌，两者有效期可配置（默认访问令牌 15 分钟、刷新令牌 7 天）。停用用户、修改密码、管理员重置密码后，不要求立即失效：刷新令牌随即作废，已签发的访问令牌最迟在到期时失效。
  • 不强制定期更换密码（遵循 NIST 建议），但提供管理员强制重置的能力。
  • 传输必须使用 HTTPS。

10.7 审计日志

  • 记录事件：登录成功与失败；用户、组织、角色的增删改；权限与授权变更；资源发布、可见范围变更、删除；模型密钥与 API Key 的创建、修改、吊销。
  • 每条记录包含：时间、操作人、所属组织、动作、对象、结果、来源 IP。
  • 日志只增不改。可按时间、操作人、动作、对象筛选。
  • 查看范围：系统管理员看全部，组织管理员看本组织。
  • 永久保存，不做自动清理。日志导出本阶段不做。

10.8 管理员资源总览

已定：参考万悟管理员中心，为管理员提供跨资源的全局列表。
  • 系统管理员可查看全平台的资源列表；组织管理员可查看本组织及下级组织的资源列表。
  • 覆盖资源类型：知识库、模型、应用、提示词、工具、MCP 等，随各模块上线逐步纳入。
  • 列表显示名称、类型、所属组织、创建人、可见范围、创建时间，可按这些条件筛选。
  • 系统管理员对所有资源拥有全部操作权限（查看、编辑、停用、删除、调整可见范围等）。
  • 组织管理员在总览中本阶段只能查看；对本组织资源的操作按其角色权限与资源授权执行。

10.9 本阶段不做

  • SSO / 统一登录对接。
  • 组织树从 HR 或通讯录同步。
  • 批量导入用户。
  • 删除用户（只做停用）。
  • 资源在组织之间迁移。
  • 审计日志导出。
  • 资源发布到全平台的审批流程。
  • OAuth 应用管理（万悟有，给第三方系统对接用，与 API Key 重叠）。
  • 知识库内的文档级权限。
  • 用户离职或停用后的资源交接。
