# P3-10 分块

状态：待验收

## 目标

把 DoclingDocument 按方案的解析设置和分块设置切成分块，写 `chunks`（含位置、标题路径、token 数），并做超长检查。

## 依据

- P3-01 契约（chunks 字段）；X04 完成记录里 Excel 行号的存放约定

## 要做

### 1. 元素流与位置映射 `app/kb/chunking.py`

- 用 docling-core 的 `HierarchicalChunker` 把 DoclingDocument 拆成元素流：每个段落、列表、表格、图片是一个元素，带标题路径和来源元素（含页码和坐标）。表格序列化为 Markdown 表格（docling-core 默认的“行, 列 = 值”三元组要换成 Markdown 表格序列化器）。
- 把元素按顺序拼成全文，同时记录每个元素在全文中的起止位置；切分器返回的每块起止位置按这张表映射回覆盖到的元素，得到分块的 `positions`。五种方式共用这一机制，不在各方式里各写一遍（9.1）。

### 2. 五种分块方式（9.2）

- 自动：解析结果有标题元素时按标题（切到 2 级）；文件类型为 PPT 时按页；否则按长度。
- 按标题：按标题路径截到第 N 级分组；短于最小长度的组并入下一组；超长的组在元素边界上累积切分，单个元素仍超长时交给 `RecursiveCharacterTextSplitter`。
- 按长度：整篇文本交给 `RecursiveCharacterTextSplitter`（方案里的分隔符按顺序逐级尝试、最大长度、重叠长度，tiktoken 计长度，`add_start_index` 取起始位置）。
- 按页：docling-core 的 `PageChunker` 按页分组，每 N 页合成一块；超长再按长度。
- 整篇：整篇一块；超过最大长度时退回按长度。

### 3. 表格（9.3）

- 文档中的表格：整表一块；超过最大长度时按行拆分，每块带表头。
- Excel、CSV：不使用分块方式，每 N 行一块，每块带表头；位置记录工作表和行范围（取 X04 约定的“表格行 → 原始行号”映射）。

### 4. 标题路径与位置

- `title_path` 单独存一列，取自元素的标题拼成（如“第三章 > 3.2 差旅”）。本卡只存；向量化时是否作为前缀由方案开关决定（P3-11）。
- `positions` 按知识库技术方案 13：PDF `{page,bbox,origin}` 列表、图片 `{bbox}`、Word 元素引用（如 `#/texts/12`）、Excel/CSV `{sheet,rows:[起,止]}`、Markdown/TXT/HTML 元素引用。

### 5. 分块写库

- 写 `chunks`：`kb_id`、`doc_id`、`generation`、`seq`、`kind`（本卡只写 `normal`、`table`；`parent` / `child` 是第五期）、`title_path`、`content`、`token_count`、`positions`、`source='auto'`、`enabled=true`、`version=1`、`updated_by=run_by`。
- token 计数用平台固定的分词器（P2-05 的 `app/gateway/tokens.py`，`cl100k_base`），与知识库选用的模型无关（需求 4.1.4）。

### 6. 超长检查（9.4）

- 向量化文本 = 标题路径 + 上下文说明 + 分块内容；它的 token 数超过知识库向量化模型 `embedding_max_input` 的 90% 时，文档入库失败，`error_message` 写明是第几个分块、在第几页，不再继续后续步骤（需求 4.1.4）。
- 分块后先按上下文说明的预留长度检查一次；增强后再按实际内容检查是第六期的事。

### 和卡片不一致 / 自己补充的地方

1. **按页分块没有直接用 `PageChunker`**：卡片 9.2 写“docling-core 的 `PageChunker` 按页分组”。为满足 9.1“五种方式共用同一元素流与位置映射”，实现改为把元素流按元素的 `prov.page_no` 分组、每 N 页合成一块，位置仍从元素映射得到。若必须用 `PageChunker`，它返回的 `meta.doc_items` 也能映射，但会丢标题路径，建议保持现状。
2. **图片元素**：`HierarchicalChunker` 只对序列化出文字的项产元素；没有说明文字的图片不产元素，图片的说明（caption）作为文字元素产出，位置用 caption 自己的 `prov`，图片本身的 `bbox` 不进 `positions`。这是 docling-core 的行为（X03 也把 caption 建为 body 下的文字项），本卡未绕开。
3. **`title_path` 取值**：按标题方式用“截到第 N 级的组路径”（如 `第二章 报销 > 2.1 差旅报销`）；按长度 / 按页 / 整篇一个分块可能跨多个元素，取覆盖到的第一个元素的完整标题路径。
4. **超长检查的预留长度**：按 9.4 给上下文说明预留 100 tokens（`CONTEXT_RESERVED_TOKENS`），标题路径按方案开关 `chunk.title_path` 决定是否计入；上限取 `embedding_max_input` 的 90%（`int()` 向下取整）。
5. **短组并入**：9.2 只写“并入下一组”，最后一组没有下一组可并入，单独保留，没有并入上一组（避免标题路径错位）。
6. **`overlap` 兜底**：`ChunkLength` / `ChunkAuto` 允许 `overlap >= max_tokens`，`RecursiveCharacterTextSplitter` 会直接报错，实现里收窄为 `min(overlap, max_tokens - 1)`。
7. **自动方式的判断顺序**：按卡片 / 需求 4.1.4 原文“有标题层级按标题；PPT 按页；否则按长度”，先判断标题，再判断 PPT。
8. **Excel / CSV 的行范围**：`rows: [起, 止]` 只记数据行（不含每块重复的表头行），取 X04 的 `adp__row_numbers`。
9. **`tree-sitter` 依赖**：`docling-core` 的 chunker 包在 import 时就要 `tree_sitter`（属 `docling-core[chunking]` 的依赖，但不带 `transformers` 等重依赖），所以直接加了 `tree-sitter`，没有装完整 `docling` 或 `docling-core[chunking]`。
