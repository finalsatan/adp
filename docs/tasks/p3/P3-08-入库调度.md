# P3-08 入库调度（Celery 骨架、按库公平、并发令牌、心跳、排队位次、beat 补发与恢复）

状态：已验收

## 目标

建 Celery 应用与三类队列，实现按知识库公平的调度（`dispatch`）、全局解析并发令牌、心跳与排队位次、beat 定时补发和恢复心跳超时的文档。入库的具体步骤由 P3-09 起实现。

## 要做

### 1. Celery 应用 `app/worker/celery_app.py`

- Celery 应用，broker 用 `CELERY_BROKER_URL`（Redis 的另一个库号，P3-02 已加）。P3-02 若已建占位入口，本卡在其上补全。
- 队列：`ingest`、`maintenance` 由 worker 消费；`interactive` 由 worker-interactive 消费（知识库技术方案 18）。
- 用默认的 prefork 进程池。`worker_process_init` 在子进程里建一个常驻事件循环，并在该循环里建本进程自己的数据库引擎和 Redis 客户端；`worker_process_shutdown` 关闭它们（8.2 补充）。任务函数用 `loop.run_until_complete()` 执行异步步骤，**不用** `asyncio.run()`（连接池绑定在创建它的循环上）。
- 开启 `acks_late`、`task_reject_on_worker_lost`：worker 崩溃时任务被重新投递（8.3）。

### 2. 任务 `app/worker/tasks.py`

- `ingest_document(doc_id, run_id)`（`ingest` 队列）：调用 `app.kb.pipeline.run_pipeline(sessionmaker, redis, doc_id, run_id)`。本卡 `app/kb/pipeline.py` 的 `run_pipeline` 先留空实现（记日志后返回），P3-09 起实现步骤。
- `dispatch_kb(kb_id)`：调用 `dispatch(kb_id)`（见第 3 条）。
- `requeue_stale()`（beat 每分钟）与 `redispatch_queued()`（beat 每 30 秒）。
- `maintenance` 队列的任务骨架（删除清理等由 P3-12 起补）。

### 3. 按知识库公平的调度 `app/worker/dispatch.py`

- `dispatch(kb_id)`：先取该知识库的事务级咨询锁 `pg_advisory_xact_lock`；统计该库处理中的文档数；小于“每个知识库最多占用的解析并发”时，按 `queued_at` 用 `FOR UPDATE SKIP LOCKED` 取排队中的文档，改为处理中并投递 `ingest_document`（8.2）。
- 触发时机（8.2）：上传后（P3-07 调用）、一个文档处理结束时（成功或失败，P3-09 起调用）、beat 每 30 秒对所有有排队文档的知识库补发一次（兜底）。
- 投递在事务提交之后执行，避免任务读到未提交的状态（补充）。

### 4. 全局解析并发令牌 `app/worker/tokens.py`

- 转换和解析两步开始前，先拿 Redis 中的全局解析并发令牌（租约方式，与 P2-04 的模型并发限流同思路，用独立的键）；上限取系统设置的“同时解析的文档数”（8.2）。
- 拿不到令牌时任务 10–30 秒后重试，**不算失败、不计自动重试次数**（8.2、8.3）。
- 进程崩溃时不续约，租约到期后自动失效（沿用 P2-04 的到期清理方式，补充）。

### 5. 排队位次

- `queued_position(session, doc)`：按 `queued_at` 计算该文档在本库排队文档中的名次（1 开始），供 P3-12 的列表接口返回“排队中（本库第 N 位）”（8.2）。

### 6. 心跳与恢复

- `touch_heartbeat(session, doc_id)`：写 `documents.heartbeat_at`（P3-09 起每步调用）。
- beat 每分钟 `requeue_stale()`：把 `heartbeat_at` 超过阈值（补充：取 5 分钟）且状态为处理中的文档重新放回调度（改排队中、清 `started_at`），再投递（8.3）。

### 7. 取消检查

- `check_run_id(session, doc_id, run_id)`：每步开始前调用；文档的 `run_id` 与任务携带的不一致时抛 `RunCancelled`，任务退出（8.3，P3-09 起在步骤边界使用）。

### 8. 系统设置

- 在 `app/settings/service.py` 增加“上传与解析”分组的解析并发两项：全局“同时解析的文档数”和“每个知识库最多占用的解析并发数”（需求 10.8；P1-09 留到第三期）。字段名以 P3-01 契约为准：`upload.parse_concurrency`（默认 4，1–32）、`upload.kb_parse_concurrency`（默认 2，1–16）；单文件大小上限属 P3-07。
