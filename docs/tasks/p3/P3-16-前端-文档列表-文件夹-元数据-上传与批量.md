# P3-16 前端：文档列表、文件夹、元数据、上传与批量操作

状态：待开始
前置：P3-01（联调需要 P3-05、P3-07、P3-08、P3-12）
被依赖：P3-19

## 目标

做出知识库的文档页：文件夹树、筛选、状态与进度刷新、上传（多文件/文件夹、预检确认）、文档元数据设置、批量操作、重新解析。

## 依据

- 需求 4.1.3、4.1.4、4.1.5、4.1.9
- 知识库技术方案 8.1（步骤与界面状态）、8.2（排队位次）、8.5（重新解析与批量）、9.4（超长预检）、11.2（documents 字段）、16（接口清单）
- 原型 `#v-kb`、`#d-upload`、`#d-docmeta`、`#m-reparse`
- P3-01 契约

## 要做

### 1. 页面框架

- 路由 `/kb/:id`（文档页签，知识库详情默认页）；页头与页签复用 P3-15 的 `KbHeader`。
- 页头下操作区：有编辑权限时显示“上传文档”。

### 2. 文件夹树（照原型 `#v-kb` 左侧）

- 顶部“全部文档 N”“未分类 N”；多级文件夹（含各自文档数）、“+ 新建”。
- 点击文件夹筛选（含下级，后端按物化路径匹配）；文件夹重命名、删除用 P3-05 的接口。
- 选中的文件夹作为上传的默认“放到文件夹”。

### 3. 文档列表

- 筛选：全部状态、失败、有人工修改、全部入库方案、元数据过滤（单条件，2026-10-25 用户决定）。
- 列：勾选框、文件名（含“已人工修改”标记）、入库方案、状态、分块、元数据、启用开关、操作。
- 状态文案按知识库技术方案 8.1：排队中（本库第 N 位）、解析中、分块中、增强中、向量化中 x%、已完成、失败（显示失败原因 + “重试”）。
- 状态刷新：列表中存在处理中（排队中/解析中/分块中/增强中/向量化中）的文档时每 5 秒轮询一次，没有则停止（需求 4.1.3、知识库技术方案 8.1）。
- 底部统计照原型“共 N 条 · 失败 N · 处理中 N”；分页。
- 操作：查看（P3-18）、重新解析（`#m-reparse`）、`···`（设置元数据、移动到文件夹、启用/停用、删除）。

### 4. 上传弹窗（照原型 `#d-upload`）

- 拖入文件或文件夹（保留目录结构）、点击选择；说明“单个文件不超过 200MB；上传文件夹时保留目录结构”；“放到文件夹”默认当前文件夹。
- 按文件类型分组，每组选一个入库方案；默认选中知识库为该类型设的默认方案，没有时用平台内置方案（P3-06）；组内文件数超过一定数量时折叠展示（补充）。
- 上传前调 P3-07 的预检接口（同名、内容重复、超长）：展示超长预检结论与“需要确认 N 项”；同名给“替换/保留两份”，重复给“跳过/仍然上传”，超长给“换方案/仍然上传”。文案照原型。
- 上传用 multipart，带多文件、相对路径和各组方案；显示上传进度；上传后直接走入库流程，前端不等待（需求 4.1.3）。

### 5. 文档元数据

- 批量设置：勾选多个文档 → “批量操作 → 设置元数据”，弹窗 `#d-docmeta`（每字段“保持不变/值/清空”，只提交填写了的字段）。
- 单个设置：行内 `···` 打开同一弹窗，只对一个文档。
- 系统字段（文件名、文件类型、上传人、上传时间、所在文件夹）只读展示。字段定义在 P3-15 的设置页维护（P3-05 接口）。

### 6. 批量操作

- 勾选后“批量操作”菜单：设置元数据、移动到文件夹、重试失败的、重新解析、启用、停用、删除。
- 删除二次确认，说明“删除文档同时删除原文件、解析结果、分块和索引，不可恢复”。
- 调 P3-12 的 `POST /documents:batch`。

### 7. 重新解析弹窗（照原型 `#m-reparse`）

- 两种方式：重新解析、仅重新分块，说明照原型；可改选方案（默认当前方案快照）；显示文档当前使用的方案快照。
- 有人工修改时先列出“解析结果有人工修改（人、时间）”“N 处分块有人工修改”；批量时统一选方式、确认弹窗汇总列出（需求 4.1.5）。
- 调 `POST /documents/{doc}:reparse` 或批量。
