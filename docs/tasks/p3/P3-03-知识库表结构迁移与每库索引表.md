### 2. 每库索引表 `app/kb/index_table.py`

- 常量 `INDEX_SCHEMA_VERSION = 1`，函数 `index_table_name(kb_id) -> str`（`kb_index.kb_{kb_id}`）、`create_index_table(conn, kb_id, dim)`、`drop_index_table(conn, kb_id)`、`index_table_exists(conn, kb_id)`。
- DDL 照 `scripts/paradedb_check/REPORT.md` 第 2、3、4 节实测通过的写法：

```sql
CREATE TABLE kb_index.kb_{id} (
    id bigserial PRIMARY KEY,
    entry_type text NOT NULL,
    chunk_id bigint,
    qa_id bigint,
    doc_id bigint,
    generation int NOT NULL,
    active boolean NOT NULL,
    embedding vector({d}),          -- d > 2000 时用 halfvec({d})
    title text,
    body text NOT NULL,
    keywords text
);
CREATE INDEX ON kb_index.kb_{id} USING hnsw (embedding vector_cosine_ops);   -- halfvec 用 halfvec_cosine_ops
CREATE INDEX ON kb_index.kb_{id} USING paradedb (
    id, (title::pdb.jieba), (body::pdb.jieba), (keywords::pdb.jieba), entry_type, doc_id, active
);
-- 另有 doc_id、chunk_id 的 B-tree
```

- 维度：`dim <= 2000` 用 `vector(dim)`，`2000 < dim <= 4000` 用 `halfvec(dim)`，超过 4000 直接报错（技术方案 9.1 在模型登记时就拒绝，这里再兜底）。
- `kb_id`、`dim` 是整数，拼 SQL 前做 `int()` 校验；表名不用参数占位（DDL 不能参数化），注释里写明这一点。
- 建表 / 删表用应用账号执行（初始化脚本已给 `adp_app` 对 `kb_index` schema 的 `CREATE` 权限，P1-01）。

### 和卡片不一致 / 自己补充的地方

1. **全文召回参数的写法要加一个空格**：卡片注意里让写 `:q::text::pdb.boost(2)`，但 SQLAlchemy 的 `text()` 在 `:q` 紧跟 `::` 时**不会**把 `:q` 当绑定参数（`_bind_params_regex` 的 `(?!:)` 负向前瞻），原样发给 asyncpg 会报语法错。测试里写成 `:q ::text::pdb.boost(2)`（`:` 与 `::` 之间加空格，等价于 `:q::text`），显式转 text 的要求不变。P3-13 写检索时照此处理。
2. **`documents.metadata` 的 ORM 属性名用 `doc_metadata`**：`metadata` 是 SQLAlchemy `DeclarativeBase` 的保留属性，不能作映射属性名；数据库列名仍是 `metadata`（`mapped_column("metadata", ...)`）。
3. **用户 ID 列不加外键**（`documents.uploaded_by` / `run_by`、`document_parses.created_by`、`chunks.updated_by`、`chunk_revisions.editor`）：卡片只对部分列写了外键，这几列照卡片未写外键，保持最小改动；`uploaded_by` / `run_by` 为 NOT NULL，其余可空。
4. **未明确写出的 `ondelete`**：`documents.folder_id` 用 `SET NULL`（删知识库时 `documents` 与 `kb_folders` 同批级联，避免删除顺序冲突）、`chunks.parent_id` 用 `CASCADE`（删父块级联子块）、`ingest_schemes.resource_id` 用 `CASCADE`（自定义方案随资源删）。卡片明确写出的三个外键（`knowledge_bases.id` CASCADE、`kb_default_schemes.scheme_id` RESTRICT、`documents.scheme_id` SET NULL）照卡片。
5. **每库索引表的索引名**取 `kb_{id}_hnsw` / `kb_{id}_bm25` / `kb_{id}_doc_id` / `kb_{id}_chunk_id`（卡片只写“另有 doc_id、chunk_id 的 B-tree”，未定名；同 schema 内需唯一）。
6. **向量召回测试用非零向量**：全零向量与任何向量的余弦距离是 NaN，HNSW 索引扫描会返回空结果（无索引的 Seq Scan 才会返回）。测试里存 0.1、查 0.2，避开 NaN；这不是实现问题，写在这里供后续检索测试参考。
7. 枚举 CHECK 约束、`status` 不加 server_default 等卡片未写死的地方按最简单做法处理。

### 留下的问题 / 建议后续处理

- `ingest_schemes` 的唯一索引 `(file_type, name)` 是**全库**唯一，自定义方案（第五期）在不同组织里同名同类型会被拒；需求 4.1.4 是“方案名称在所属组织内唯一”。本卡照卡片“补充”实现，建议第五期做自定义方案 CRUD 时改为：内置方案用 `(file_type, name) WHERE builtin` 的部分唯一索引，自定义方案靠 `resources` 的 `(type, org_id, name)` 保证组织内唯一。
- `kb_folders` 的唯一索引 `(kb_id, parent_id, name)` 中 `parent_id` 为空（根文件夹）时按 PG 默认“NULL 互不相等”，同名根文件夹不被拦截；卡片没要求 `NULLS NOT DISTINCT`（只有 `documents` 明确要求），照卡片实现。若 P3-05 需要根文件夹同名也报错，再补部分唯一索引。
- P3-11 写向量与两代切换时用本卡的建表函数；P3-13 写全文召回时注意上面第 1 条的空格写法。
