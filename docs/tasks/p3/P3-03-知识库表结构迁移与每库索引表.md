### 2. 每库索引表 `app/kb/index_table.py`

- 常量 `INDEX_SCHEMA_VERSION = 1`，函数 `index_table_name(kb_id) -> str`（`kb_index.kb_{kb_id}`）、`create_index_table(conn, kb_id, dim)`、`drop_index_table(conn, kb_id)`、`index_table_exists(conn, kb_id)`。
- DDL 照 `scripts/paradedb_check/REPORT.md` 第 2、3、4 节实测通过的写法：

```sql
CREATE TABLE kb_index.kb_{id} (
    id bigserial PRIMARY KEY,
    entry_type text NOT NULL,
    chunk_id bigint,
    qa_id bigint,
    doc_id bigint,
    generation int NOT NULL,
    active boolean NOT NULL,
    embedding vector({d}),          -- d > 2000 时用 halfvec({d})
    title text,
    body text NOT NULL,
    keywords text
);
CREATE INDEX ON kb_index.kb_{id} USING hnsw (embedding vector_cosine_ops);   -- halfvec 用 halfvec_cosine_ops
CREATE INDEX ON kb_index.kb_{id} USING paradedb (
    id, (title::pdb.jieba), (body::pdb.jieba), (keywords::pdb.jieba), entry_type, doc_id, active
);
-- 另有 doc_id、chunk_id 的 B-tree
```

- 维度：`dim <= 2000` 用 `vector(dim)`，`2000 < dim <= 4000` 用 `halfvec(dim)`，超过 4000 直接报错（技术方案 9.1 在模型登记时就拒绝，这里再兜底）。
- `kb_id`、`dim` 是整数，拼 SQL 前做 `int()` 校验；表名不用参数占位（DDL 不能参数化），注释里写明这一点。
- 建表 / 删表用应用账号执行（初始化脚本已给 `adp_app` 对 `kb_index` schema 的 `CREATE` 权限，P1-01）。

## 注意

- 建表函数放在 `app/kb/index_table.py`（P3-11 会新建 `app/kb/indexing.py` 做向量写入与两代切换，两个文件不要混）。
- **全文召回的参数要写 `:q::text::pdb.boost(2)`**（`REPORT.md` 6a、X09 完成记录第 1 条）：同一个参数同时出现在带 boost 和不带 boost 的位置时，服务端类型推断会报 `invalid typemod -1`，必须显式 `::text`。本卡不写检索代码，但测试和注释里按这个写，P3-13 照做。
