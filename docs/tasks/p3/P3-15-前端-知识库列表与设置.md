## 目标

做出知识库列表、新建，以及知识库的设置（基本信息、默认入库方案、元数据字段）和权限（可见范围与协作者）页面，含停用与删除。

- 原型 `#v-kbs`、`#d-newkb`、`#v-kbset`、`#d-field`、`#v-kbperm`、`#d-collab`、`#m-kbstop`
- P3-01 契约

## 要做

### 1. 菜单与路由

- 在 `frontend/src/lib/menu.ts` 的“资源库”分组加“知识库” `/kb`，权限 `console.use`（补充：技术方案 7.1 没有知识库专属的查看权限码，知识库的查看靠资源权限判断，接口权限码以 P3-04 为准）。
- 路由（补充）：`/kb` 列表；`/kb/:id/settings` 设置；`/kb/:id/permissions` 权限。文档、命中测试页分别由 P3-16、P3-17 挂到同一知识库页头下。
- 新建 `frontend/src/pages/kb/KbHeader.tsx`：知识库页头（名称、类型、可见范围、文档数/分块数、向量化模型、创建人）+ 页签“文档 / 检索与命中测试 / 设置 / 权限”，供 P3-16、P3-17 复用。

### 2. 列表页（照原型 `#v-kbs`）

- 页头说明照原型；有 `resource.create` 权限时显示“新建知识库”按钮。
- 筛选：类型（全部/文档库/问答库）、可见范围、所属组织、状态、关键字；右侧“我能查看的 N 个”。
- 列：名称（含描述）、类型、文档/问答对数、分块、向量化模型、可见范围、所属组织、状态、更新时间、操作。
- 操作：进入、命中测试、`···`（设置、权限、停用/启用、删除）。按资源权限显示（P1-12/P3-04 返回的 `can_*`），安全以后端为准。
- 分页与空状态。
- 停用弹窗 `#m-kbstop`：先取引用它的应用清单（P3-04 的 refs），列出应用与负责人，文案照原型；无引用时只有确认文字。
- 删除：被引用时后端返回 409 `RESOURCE_IN_USE`，弹窗列出引用应用（需求 4.1.2）。

### 3. 新建弹窗（照原型 `#d-newkb`）

- 字段：类型（文档库/问答库）、名称、描述、向量化模型（只列已启用的向量化模型）、可见范围（仅自己/本组织/全平台）。
- 文案照原型：“类型和向量化模型创建后不可修改”“默认入库方案、元数据字段和检索配置可在创建后到设置中修改”。
- 名称在同一组织内唯一，重名返回 409 `NAME_CONFLICT`，显示在名称输入框下。

### 4. 设置页（照原型 `#v-kbset`）

- 基本信息：名称、描述可改；类型、向量化模型只读并提示“创建后不可修改；要更换请新建知识库”。
- 默认入库方案：按文件类型列出，选项来自 P3-06 的方案列表；未设置时显示“平台默认：{内置方案名}”。保存调 P3-04 的 `GET/PUT /kbs/{kb}/default-schemes`。
- 元数据字段：表格（字段名、类型、选项、已设值文档数、操作）+ 系统字段只读一行；添加/编辑用弹窗 `#d-field`（P3-05 的接口），删除二次确认。
- 停用与删除区块：说明文案照原型。

### 5. 权限页（照原型 `#v-kbperm`）

- 可见范围单选（仅自己/本组织/全平台），说明“本组织包含下级组织”“缩小可见范围前会检查引用它的应用”；后端返回 409 时列出受影响的应用。
- 协作者列表（用户、所属组织、添加人、时间、移除）+ 添加协作者弹窗 `#d-collab`（搜索用户名或姓名，可选任何组织的用户，文案照原型）。
- 管理权限说明照原型。

### 6. 权限与显示

- 用 `GET /api/v1/me` 的权限码和资源权限返回的 `can_*` 控制按钮显示；问答库在第三期只创建、可显示，不进入问答对功能。

### 联调中发现并修复的前端问题

1. **新建弹窗默认类型未生效**（`KbCreateModal.tsx`）：真实浏览器里打开弹窗后“类型”为空（“可见范围”却已是“本组织”），点“创建”报“请选择类型”。原因是默认值在 `useEffect` 里 `setFieldsValue`，弹窗内容挂载时序下 `kind` 丢失。改为在 `Form` 上用 `initialValues={{ kind: "doc", visibility: "org" }}`，`useEffect` 只保留 `resetFields` 与清错误。
2. **非组织管理员打开知识库页会弹“没有权限执行该操作”**（`KbListPage.tsx`、`KbCreateModal.tsx`、`frontend/src/api/orgs.ts`）：`useOrgs` 请求 `GET /orgs` 需要 `org.manage`，搭建者打开列表页/新建弹窗时会 403 并弹全局错误提示。给 `useOrgs` 加 `{ enabled }` 选项；列表页按 `org.manage` 决定是否请求与显示组织筛选，新建弹窗仅系统管理员请求组织树。

以上两处修复均补了 Vitest（`KbCreateModal.test.tsx` 默认类型与是否请求组织、`KbListPage.test.tsx` 组织筛选显隐与是否请求组织）。
