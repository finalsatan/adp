# P3-05 文件夹与元数据字段接口

状态：已验收
前置：P3-03
被依赖：P3-07、P3-12、P3-13、P3-16

## 目标

实现知识库的文件夹（物化路径、含下级过滤）和元数据字段（文本 / 数字 / 日期 / 单选）的增删改查，并提供元数据取值校验（供上传与文档列表复用）。

## 依据

- 知识库技术方案 11.2（`kb_folders`、`kb_metadata_fields`）、12.3（文件夹按物化路径前缀、元数据“且 / 或”条件树）
- 需求 4.1.3（文件夹、元数据、系统字段）、4.1.4（元数据字段定义）
- 原型 `#v-kb`（文件夹树）、`#v-kbset`（元数据字段表）、`#d-field`（添加字段）、`#d-docmeta`（批量设置值）
- P1-03 的 `{id:int}`、`RequestModel` 约定；P3-01 的 `FolderOut`、`MetadataFieldOut`、`MetadataFilter`；P3-03 的表

## 要做

### 1. 文件夹 `app/kb/folders.py`

- 物化路径：`path` 为 `/{祖先 id}/.../{自身 id}/`，与组织（技术方案 6.1）同一套写法；根文件夹的 path 为 `/{id}/`。插入时先 flush 拿 id，再写 `path`（同事务）。
- `create_folder(session, ctx, kb_id, parent_id, name)`：校验知识库可编辑（`access.get_for(EDIT, type="kb")`）；`parent_id` 必须属于同一知识库；同级重名返回 409 `NAME_CONFLICT`。
- `list_folders(session, ctx, kb_id)`：按 `path` 排序返回平铺列表，前端拼树；`doc_count` 为该文件夹**直接**包含的文档数（补充）。
- `rename_folder(session, ctx, folder_id, name)`：只改 `name`，同级查重。
- `delete_folder(session, ctx, folder_id)`：有下级文件夹返回 409 `FOLDER_HAS_CHILDREN`、有文档返回 409 `FOLDER_NOT_EMPTY`，message 提示先清空（移走文档 / 删除下级文件夹）再删；不自动搬走文档（2026-10-25 用户决定）。
- `folder_scope_clause(folder)`：返回“该文件夹含下级”的 WHERE 条件（`KbFolder.path.like(folder.path + "%")`，因为 `path` 以 `/` 结尾，`LIKE` 也会匹配自身），供文档列表与检索复用。

### 2. 元数据字段 `app/kb/metadata.py`

- `list_fields(session, ctx, kb_id)`、`create_field`、`update_field`、`delete_field`：
  - 名称在知识库内唯一（冲突 409 `NAME_CONFLICT`）；名称 1–50 字。
  - `type=select` 必须给 `options`（1–100 个，去重、非空）；其他类型忽略 / 拒绝 `options`（补充）。
  - `doc_count` 为该字段已被设值的文档数（`documents.metadata ? :name`）。
  - 删除字段时，在同一个事务里从该知识库所有文档的 `metadata` 里删掉该键（`documents.metadata - :name`）（2026-10-25 用户决定）。
- `validate_metadata(session, kb_id, metadata: dict) -> None`：校验提交的键都是已定义字段、值符合字段类型（文本 string、数字 int/float、日期 `YYYY-MM-DD`、单选必须在 `options` 内），不合法返回 422 `METADATA_VALUE_INVALID`（`detail` 带字段名和原因）。批量设置元数据（P3-12）和上传时（P3-07）都用它。
- 元数据 / 文件夹过滤的 SQL 翻译（P3-01 契约里的 `MetadataFilter`）不在本卡，P3-12 的列表和 P3-13 的检索各自实现（避免与那两张卡重复）。

### 3. 路由 `app/kb/folders_router.py`

实现 P3-01 契约里的文件夹与元数据字段接口（占位换成实现）：

- 权限：列表走资源“查看”；增删改走资源“编辑”；先按 `folder.kb_id` / `field.kb_id` 找到知识库再 `access.get_for`。
- 不写审计（需求 4.1.11 没有把改文件夹、元数据字段列入审计清单）。

### 和卡片不一致 / 自己补充的地方

1. **两个列表路由补了 `ctx: CurrentCtx`**：卡片要求列表走资源“查看”，service 需要 `ctx` 调 `access.get_for`；原占位签名没有 ctx。不影响接口契约（依赖不出现在 OpenAPI）。
2. **`options` 去重是静默处理**：单选选项去空白、去重（保留顺序），去重后为空或超过 100 个报 422；非单选类型忽略提交的 `options`（卡片写“忽略 / 拒绝”，取忽略）。
3. **`MetadataFieldUpdate` 只传 `name` 时不动 `options`；传了 `options` 且字段是单选才校验并覆盖**。显式传 `null` 视为未提供，不用于清空选项。
4. **`validate_metadata` 对值为 `null` 一律判为类型不符**（卡片只列了 string / number / date / options，没有“清空”语义）。
5. **删除元数据字段的测试放在 `test_folders.py`**，照卡片验收标准里的分组写。

### 留下的问题 / 建议后续处理

- 原型 `#d-docmeta` 有“清空”选项，说明批量设置元数据（P3-12）需要支持把某个字段的值清掉。本卡按卡片实现为“值必须是合法类型”，`null` 会报 422；建议 P3-12 清空时用“从 `documents.metadata` 删掉该键”的方式处理，或在 P3-12 卡片里明确 `null` 的语义。
- 文件夹列表按 `path` 文本排序，同一父下 id 为 10 的会排在 id 为 2 的前面（如 `/1/10/` < `/1/2/`）。前端用 `parent_id` 拼树、同级顺序以列表为准，如需按名称排序请在 P3-16 或后续卡片明确。
