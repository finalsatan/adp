# P3-18 前端：原文预览与段落高亮

状态：已验收
前置：P3-01（联调需要 P3-13、P3-14）
被依赖：P3-19

## 目标

做出文档详情页：PDF 原文预览并跳到引用页、按坐标叠加高亮框；Word 等文本类文档在只读的解析结果视图中高亮对应段落；从命中测试点击“原文位置”能直接定位。

## 依据

- 需求 4.1.5、4.1.8
- 知识库技术方案 7（统一的解析结果）、9.1（元素流与位置映射）、13（引用定位与原文预览）
- 原型 `#v-doc`
- P3-01 契约

## 要做

### 1. 文档详情页（照原型 `#v-doc`）

- 路由 `/kb/:id/documents/:docId`；页头：文件名、状态、页数与分块数、入库方案（快照：方案名、时间、引擎、分块方式）、已人工修改标记（第三期只读）。
- 操作：下载原文件（P3-14，`download=1`）、重新解析（复用 P3-16 的 `#m-reparse` 弹窗）。
- 页签：只做“解析结果对照”（本卡）；“分块”页签第五期和分块编辑一起做（2026-10-25 用户决定）。

### 2. PDF 原文预览与高亮

- 用 `react-pdf`（pdf.js）渲染：优先 `GET /documents/{doc}/file?variant=preview`，没有预览 PDF 时用 `variant=original`（原文件就是 PDF）；两者都没有时不显示预览，提示“该文档没有可预览的 PDF，可下载原文件”（需求 4.1.8、知识库技术方案 13）。
- 页码切换“第 N / 总页数”，支持跳到引用所在页；大文件靠 P3-14 的 HTTP Range 分段加载。
- 高亮：把命中结果或分块里的位置数据 `{page, bbox, origin}`（PDF 点坐标、原点左下，知识库技术方案 7、13）换算成画布像素，叠加高亮框，支持同页多个框；扫描件用 OCR 识别出的区域坐标，同一套处理。
- 高亮样式与“已人工修改”标注照原型。

### 3. 解析结果视图（只读）

- 用 P2-10 的 `SafeMarkdown` 渲染 `GET /documents/{doc}/parse` 返回的 Markdown。
- Word、Markdown、TXT、HTML、EPUB、OFD：按元素引用（如 `#/texts/12`，来自位置数据）高亮对应段落（知识库技术方案 13）；位置数据由 P3-14 提供。
- PDF 也显示解析结果，但定位只用原文预览（知识库技术方案 13）。
- 没有解析结果（处理中/失败）时显示状态说明。

### 4. 从命中测试定位

- 命中测试结果点“原文位置”跳本页并带定位参数（分块 id 或位置，见 P3-17）；页面加载后滚到对应页/段落并高亮。
- 切换页码、切换页签后保持当前定位；提供“清除高亮”（补充）。

### 5. 依赖 Docling 的效果

- Word 的元素引用定位依赖 Docling 输出的 DoclingDocument（元素顺序与引用，知识库技术方案 7、13）。第三期用固定样例（P3-19 的假解析结果）测试；真实 Docling 的 Word 元素引用效果待解析服务的 Docling（X06）接入后验证，完成记录里写明。

## 问题

- 已定（2026-10-25）：第三期文档详情页只做“解析结果对照”页签，不做只读“分块”页签；分块页签第五期和分块编辑一起做。
- PDF 高亮的坐标换算细节（`origin` 的含义、是否处理页面旋转）技术方案和原型都没写。本卡按 pdf.js viewport 换算、暂不处理旋转（补充）；真实效果待 Docling/PDF 样例验证。
- 解析结果视图的高亮用“元素引用 → Markdown 段落”的匹配，取决于 P3-14 返回的块数据形态（见 P3-14 的“问题”）；契约确定后按契约实现。
- 第三期没有分块位置接口（`GET /documents/{doc}/chunks` 第五期才做），P3-17 的“原文位置”链接只带 `?chunk={id}`，页面无法只凭分块 id 拿到 positions。本卡让 P3-17 的链接通过 react-router `state` 把 `page_no` 和 `positions` 带过来（对卡片文件清单的最小偏离，见完成记录）；刷新页面或分享链接会丢失高亮，待第五期分块接口或后续调整。
- `DocumentOut` 只有 `scheme_snapshot_name`，没有方案快照的时间、引擎、分块方式，页头只显示方案名；原型 `#v-doc` 里的“快照 10-20 14:02，引擎 Docling，按标题分块”待契约补字段后再显示。
- PDF `origin` 后端实际可能返回 `BOTTOMLEFT` 或 `TOPLEFT`（P3-10），本卡两种都换算，缺省按左下；页面旋转仍未处理。
- 元素引用高亮按归一化文本包含关系匹配渲染后的段落，表格元素（元素文本是整张 Markdown 表）暂不高亮；第三期只要求段落，真实 Word 效果待 Docling（X06）接入后验证。
