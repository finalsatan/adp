# P3-06 内置入库方案、引擎列表与知识库默认方案

状态：已验收
前置：P3-02、P3-03（依赖补齐已定，见“问题”）
被依赖：P3-07、P3-15、P3-16

## 目标

用迁移写入每种文件类型的内置入库方案（只读），实现方案列表 / 详情、解析引擎列表、知识库按文件类型的默认方案读写，并把 `scheme` 注册进资源类型。

## 依据

- 知识库技术方案 14（方案配置、内置方案、校验、快照、引用关系）、6.1（`GET /v1/engines`）、6.2（各引擎支持的文件类型）、11.2（`ingest_schemes`、`kb_default_schemes`）
- 需求 4.1.4（入库方案）、4.1.2（创建后设置默认方案）
- 原型 `#v-schemes`、`#v-scheme`、`#v-schemenew`、`#m-schemedel`、`#m-schemeimport`、`#v-kbset`（默认入库方案表）
- P3-01 的 `SchemeOut`、`SchemeConfig`、`ParseEngineOut`、`DefaultSchemeOut`；P3-03 的表；P3-02 的 `PARSER_URL` / `PARSER_TOKEN`（P3-09 会建完整的 `parser_client`）

### 2. 方案读取 `app/kb/schemes.py`

- `list_schemes(session, file_type, builtin, keyword, pagination)`：第三期只有内置方案（`builtin=true`），返回 `Page[SchemeOut]`；按 `file_type`、`name` 排序（补充）。
- `get_scheme(session, scheme_id)`：不存在或（第五期起）已删除 → 404。
- `scheme_out(session, scheme)`：拼 `SchemeOut`；`org` / `owner` 内置方案为 null；`default_kb_count` 用 `kb_default_schemes` 计数。
- `validate_scheme_config(config)`：用 P3-01 的 `SchemeConfig` 校验，再按需求 4.1.4 的表检查“引擎支持该文件类型”（引擎 → 文件类型对照表写在这里，`builtin` 支持 `excel`/`csv`/`markdown`/`txt`/`html`，`docling` 支持 `pdf`/`word`/`ppt`/`image`，`markitdown` 支持 `word`/`ppt`，`mineru` 支持 `pdf`/`image`/`word`/`ppt`/`html`/`epub`/`ofd`，`pypdfium` 支持 `pdf`，`paddleocr` 支持 `pdf`/`image`）。第三期内置方案在迁移里已校验；这个函数给测试和第五期的自定义方案用。
- `resolve_scheme_id(session, kb_id, file_type)`：先取知识库默认方案，没有就取该文件类型的第一个内置方案（需求 4.1.3）；给上传（P3-07）复用，返回 `None` 表示没有可用方案。

### 3. 解析引擎列表 `GET /parse-engines`

- 用 P3-02 的 `app/kb/parser_client.py` 调解析服务 `GET /v1/engines`（复用，不自己写 httpx），带 `Authorization: Bearer {PARSER_TOKEN}`，映射成 `ParseEngineOut`：`name`、中文 `label`（`docling` Docling、`pypdfium` pypdfium、`markitdown` MarkItDown、`mineru` MinerU、`paddleocr` PaddleOCR、`builtin` 内置解析）、`file_types`、`available`、`reason`。
- 解析服务不可达：不返回 502，而是返回全部引擎 `available=false`、`reason="解析服务不可用"`（入库方案页据此禁用选项，知识库技术方案 6.1；补充）。
- MinerU 的档位：`tiers` 返回 `flash`、`basic`（可用性跟随 `mineru`）、`standard`、`advanced`（第三期固定 `available=false`、`reason="未配置"`；系统设置里的引擎配置第六期做）。
- 未在 `parser` 注册的引擎（如 `paddleocr`）也要出现在列表里并标不可用，保证方案编辑页的选项齐全（补充）。

### 4. 知识库默认方案 `GET/PUT /api/v1/kbs/{id:int}/default-schemes`

- `get_default_schemes(session, ctx, kb_id)`：按 `FileType` 全部 11 种返回 `DefaultSchemeItem`；`scheme_id` / `scheme_name` 为知识库显式设置的，`fallback_*` 为该类型第一个内置方案。
- `set_default_schemes(session, ctx, kb_id, items)`：要求资源“编辑”权限；全量替换：`scheme_id` 为 null 表示清除该类型的默认；校验方案存在、`file_type` 与条目一致（不符 422 `SCHEME_TYPE_MISMATCH`）、未删除；用 upsert / delete 实现，不动其他类型。

### 5. 资源类型注册

- `app/kb/__init__.py` 里注册 `scheme`：code `scheme`、label `入库方案`、`fixed_visibility="platform"`（技术方案 6.2、需求 4.1.4）。内置方案不登记资源（知识库技术方案 14），所以第三期没有 scheme 资源行；第五期自定义方案才用得上。
- `app/audit/actions.py` 的 `TARGET_TYPE_LABELS` 加 `scheme`（入库方案）。

### 6. 路由 `app/kb/schemes_router.py`

实现 P3-01 契约里的方案、引擎、默认方案接口（占位换成实现）。方案列表与详情 `console.use`；默认方案列表走资源“查看”、PUT 走资源“编辑”。本卡不写审计（方案增删改是第五期，需求 4.1.11）。

### 和卡片不一致 / 自己补充的地方

1. **Excel / CSV 的「按行」分块**：P3-01 的 `SchemeConfig` 没有「按行」这个 `chunk.mode`（只有 auto / heading / length / rule / page / whole / semantic），按行分块由 `table.rows_per_chunk=20`、`header_row=1` 表达，`chunk` 用 `auto`；知识库技术方案 9.3 也说表格不受分块方式影响。
2. **EPUB / OFD 的 `parse.mineru_tier` 显式写 `flash`**（需求 4.1.4：MinerU 档位只对 PDF、图片有效，其他类型固定 flash）。图片方案不写 `scan_mode`（扫描页判断只对 PDF）。
3. **内置方案数据放 `app/kb/schemes.py` 的 `BUILTIN_SCHEMES`，迁移 import 它**：`conftest` 每个测试后 `TRUNCATE`，迁移写入的数据在测试里会丢；`test_schemes.py` / `test_default_schemes.py` 的 autouse fixture 用同一份数据补种（先按固定 ID 删除再插，幂等）。迁移本身在 adp_test（0003 → 0004）上跑过并核对过数据。
4. **`get_parser_client` 放在 `schemes_router.py`**：卡片只列了这几个文件，没在 `parser_client.py` 加依赖工厂；测试用 `app.dependency_overrides[get_parser_client]` 注入 `httpx.MockTransport`。
5. **`app/main.py` 未改**：`register_kb_types` 已在 `create_app` 调用，`scheme` 的注册合并进 `app/kb/__init__.py` 的 `register()`（卡片允许）。
6. **`validate_scheme_config` 的错误码**：结构/参数越界与「增强未选对话模型」抛 `VALIDATION_ERROR`；引擎不支持该文件类型抛 `ENGINE_UNAVAILABLE`。
