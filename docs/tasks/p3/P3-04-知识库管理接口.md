# P3-04 知识库管理接口

状态：待开始
前置：P3-02、P3-03（依赖补齐已定，见“问题”）
被依赖：P3-07、P3-09、P3-13、P3-15

## 目标

实现知识库的列表、详情、新建、编辑、删除、停用启用、可见范围、协作者，并把 `kb` 注册进资源类型；创建知识库时建好每库索引表。

## 依据

- 知识库技术方案 11.1（对象存储路径）、11.2（`knowledge_bases`）、11.3（建索引表）、17（权限、审计）
- 技术方案 6.2（resources、协作者、引用）、7.3（资源权限）
- 需求 4.1.2（知识库管理）、4.1.9（权限）、4.1.11（审计）
- 原型 `#v-kbs`、`#d-newkb`、`#v-kbset`、`#v-kbperm`、`#m-kbstop`、`#d-collab`
- P1-12 的 `resources/service.py`、`resources/access.py`；P3-01 的知识库接口契约；P3-03 的 `create_index_table` / `drop_index_table`

## 要做

### 1. 资源类型注册

- 在 `app/kb/__init__.py` 里注册资源类型 `kb`：code `kb`、label `知识库`、`fixed_visibility=None`。
- `on_delete(session, resource)`：调用 P3-03 的 `drop_index_table` 删除 `kb_index.kb_{id}`，删除 `knowledge_bases` 行（外键级联删文件夹、元数据字段、文档、分块、解析记录），并用 P3-02 的 `Storage.delete_prefix` 删除 `kb/{id}/` 前缀下的对象。
- 在 `app/main.py` 启动时调用注册（`app.kb.register()` 之类，纯内部细节）。
- 知识库停用不删索引（检索时按资源状态跳过，知识库技术方案 12.1），所以不注册 `on_status_change`。

### 2. 业务逻辑 `app/kb/service.py`

路由只做参数接收、权限依赖、调用这里、写审计。

- `list_kbs(session, ctx, pagination, kind, visibility, org_id, include_sub, status, keyword)`：join `resources` + `orgs`，用 `resources.access.get_for` 同源的 `access_clause(ctx, VIEW)` 过滤（不查出来再内存过滤）；按 `resources.created_at` 倒序；返回 `Page[KbOut]`。
- `get_kb(session, ctx, kb_id)`：`access.get_for(session, ctx, kb_id, VIEW, type="kb")`。
- `create_kb(session, ctx, body)`：
  - `body.kind` 接受 `doc` 和 `qa`（原型 `#d-newkb` 两种都提供）；第三期 `qa` 只建库，没有问答对功能（问答对在第六期），`doc_count` / `chunk_count` 为 0。
  - `embedding_model_id` 必须是存在、未删除、`status=enabled`、`model_type=embedding` 的模型，否则 `EMBEDDING_MODEL_UNAVAILABLE`；`embedding_dim`、`embedding_max_input` 从模型取。
  - 用 `resources.service.create_resource(session, ctx, "kb", name, visibility, description, org_id)` 建资源（名称唯一、系统管理员必须给 `org_id` 的规则复用 P1-12）。
  - 插 `knowledge_bases` 行：`index_table=index_table_name(id)`、`index_schema_version=INDEX_SCHEMA_VERSION`、`retrieval_config={}`（默认值由 P3-13 解释）、计数为 0。
  - 调 `create_index_table`（维度按模型的 `embedding_dim`，>2000 自动用 halfvec）。建表失败要回滚，不能留下没有索引表的知识库。
- `update_kb(session, ctx, kb_id, body)`：只改 `name`、`description`；`name` 的唯一性用资源表的规则（改名前查重，冲突 409 `NAME_CONFLICT`）。带 `kind` / `embedding_model_id` 时由路由或这里返回 422 `KB_KIND_IMMUTABLE` / `KB_EMBEDDING_MODEL_IMMUTABLE`（`KbUpdate` 结构里有这两个字段，见 P3-01）。
- `kb_out(session, kb)`：拼 `KbOut`（`org`、`owner`、`embedding_model`、`doc_count`、`chunk_count`、`editable`、`manageable`）。`editable` / `manageable` 用 `resources.access` 的同一套规则算（与 `get_for` 结论一致）。
- `list_refs(session, ctx, kb_id)`：从 `resource_refs` 取引用该知识库、且未删除的资源，返回 `KbRefOut` 列表（第三期没有应用，返回空列表；给 P3-15 的停用 / 删除确认弹窗用，需求 4.1.2）。
- 删除、停用启用、可见范围、增减协作者分别调 `resources.service.delete_resource` / `set_status` / `change_visibility` / `add_member` / `remove_member`，不要另写一套权限判断。

### 3. 路由 `app/kb/router.py`

实现 P3-01 契约里的知识库接口（占位换成实现）：

- 权限：列表和详情 `console.use` + 资源“查看”；新建 `resource.create`；编辑内容走资源“编辑”（本卡只有改基本信息）；可见范围、协作者、停用、删除走资源“管理”（由 `resources.service` 内部判断）。
- 实现 `GET /kbs/{id}/refs`（P3-01 契约）：返回引用该知识库的应用清单，第三期为空列表。
- 停用 / 启用的引用清单：第三期没有应用，`resource_refs` 为空，停用弹窗的清单就是空（补充；前端 P3-15 按空列表处理）。
- 写审计：路由用 `audited("kb.xxx")`，成功调 `audit_success(request, target, detail)`，`AuditTarget("kb", resource.id, resource.name, resource.org_id)`。

### 4. 审计动作 `app/audit/actions.py`

加动作与中文名：`kb.create` 创建知识库、`kb.update` 修改知识库、`kb.delete` 删除知识库、`kb.change_visibility` 调整可见范围、`kb.add_member` 添加协作者、`kb.remove_member` 移除协作者、`kb.disable` 停用知识库、`kb.enable` 启用知识库；`TARGET_TYPE_LABELS` 加 `kb`（知识库）。detail 里不含密钥、Token 等（本卡没有）。

## 验收标准

- [ ] 测试 `test_kb_api.py`：
  - 搭建者能建文档库和问答库（qa 只建库、计数为 0）、列表、看详情。
  - 向量化模型不存在 / 已停用 / 类型不是 embedding 时返回 `EMBEDDING_MODEL_UNAVAILABLE`。
  - 同一组织内重名返回 409；不同组织可以同名。
  - 改 `kind` 或 `embedding_model_id` 返回 422；改名称、描述成功并写 `kb.update` 审计。
  - 停用 / 启用返回新状态并写审计；可见范围变更、增减协作者写审计；这些操作对“能看不能管”的用户返回 403，对看不到的用户返回 404（技术方案 7.3）。
  - 搭建者不能建知识库时（没有 `resource.create`）——终端用户访问列表 / 详情返回 403。
- [ ] 测试 `test_kb_delete.py`：创建知识库后 `kb_index.kb_{id}` 存在；删除后表不存在、`kb/{id}/` 前缀下的对象被删、`resources` 软删除；再建同名知识库成功。
- [ ] `GET /kbs/{id}/refs` 返回空列表（第三期没有应用）。
- [ ] 创建知识库时索引表建的维度与模型一致（1024 → `vector`，2560 → `halfvec`）。
- [ ] `make backend-lint backend-test` 通过；`make gen-api` 后提交生成的类型。

## 注意

- 权限一律复用 `resources/access.py`（P1-12），不要再写一套；列表过滤拼进 SQL 的 WHERE。
- 建表和插 `knowledge_bases` 行要在同一个事务里；建索引表用的是应用账号（`kb_index` schema 已授权）。
- 删除知识库是软删除资源 + 硬删 `knowledge_bases` 行；对象存储前缀删除失败要记 ERROR 日志但不让接口 500（下次维护任务再清，补充）。
