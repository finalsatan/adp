### 和卡片不一致 / 自己补充的地方

1. **`Makefile` 未改**：`fake-parser` 目标 P3-09 已加（默认 59010、`FAKE_PARSER_PORT` 可覆盖），本卡复用。
2. **假解析服务用工厂启动**：`backend/tests/fake_parser/server.py` 只有 `create_app()` / `main()`，没有模块级 `app`，所以 webServer 用 `uvicorn --factory tests.fake_parser.server:create_app`。
3. **Celery worker 没有 HTTP 端口**：Playwright 1.64 的 webServer 支持 `wait: { stderr: /ready\./ }`，用 Celery 启动日志里的 `celery@… ready.` 判断就绪；`--loglevel=INFO` 显式指定，否则默认可能不打印该行。
4. **对象存储用独立桶 `adp-e2e`**：避免和开发库 `adp`、单测桶 `adp-test-p1` 互相覆盖对象（P3-11 的测试隔离思路）；桶在 `e2e-prepare.sh` 里建。
5. **Celery broker 用 Redis 13 号库**：应用仍用 12 号库；broker 显式指到 13，避免和开发环境的 1 号库串。`e2e-prepare.sh` 同时清空 12、13。
6. **重排步骤在端到端里没有真实结果**：本地假模型服务（`fake_llm`）没有重排接口，而本卡文件清单不含 `backend/tests/fake_llm/` 的改动，未给假模型服务加重排；端到端里重排保持关闭，四步的“重排”步骤仍渲染（计数 0），向量/全文/融合有结果。重排算法与阈值在 P3-13 的单测里用模拟的重排模型覆盖。
7. **端到端未覆盖重试、重新解析、权限、平级组织**：原因见下。
