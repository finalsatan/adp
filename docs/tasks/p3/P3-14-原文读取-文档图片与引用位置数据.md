# P3-14 原文读取、文档图片与引用位置数据

状态：待开始
前置：P3-07（联调需要 P3-03、P3-09）
被依赖：P3-18

## 目标

实现文档原文件与预览 PDF 的读取（HTTP Range、variant、下载）、文档图片读取，以及解析结果与引用位置数据接口，让前端能打开原文并定位到引用位置。

## 依据

- 需求 4.1.5、4.1.8、4.1.9
- 知识库技术方案 11.1（对象存储路径）、11.2（document_parses、chunks 的 positions）、13（引用定位与原文预览）、16（接口清单）、17（权限、审计与用量）
- 技术方案 v0.1 7.3（资源权限）、10（接口约定）
- P3-01 契约

## 要做

### 1. 文件读取 `GET /api/v1/documents/{doc}/file`

- 参数：`variant=original|preview`（默认 original）、`download=1` 时强制下载（2026-10-25 用户决定）。请求与返回结构以 P3-01 契约为准。
- 权限：知识库“查看”权限（技术方案 7.3；看不到的资源返回 404，能看不能改返回 403，P1-12 的资源权限判断）。
- 路径按知识库技术方案 11.1：`original` 读 `kb/{kb_id}/docs/{doc_id}/original.{ext}`；`preview` 读 `kb/{kb_id}/docs/{doc_id}/preview.pdf`。
- `preview` 不存在（转换失败、或该类型不生成预览）→ 404，message 为中文说明（如“该文档没有可预览的 PDF，可下载原文件或查看解析结果”），前端据此降级。
- 支持 HTTP Range：解析 `Range: bytes=start-end`，用 S3 `get_object` 的 `Range` 取对应片段，返回 206、`Content-Range`、`Accept-Ranges: bytes`、正确的 `Content-Length`；越界返回 416（补充）；不带 Range 或无法处理的多段 Range 按 200 全量返回（补充）。
- `Content-Type` 按扩展名映射（PDF、各图片类型、Office 原文件等）；`download=1` 时加 `Content-Disposition: attachment; filename*=UTF-8''{urlencode(文件名)}`，否则 inline（知识库技术方案 13）。
- 用 `StreamingResponse` 流式返回，不把整份文件读进内存（nginx 侧透传 Range，知识库技术方案 18）。
- 对象存储读取复用 P3-02 的封装；本卡只在其上做 Range 与响应头处理。

### 2. 图片读取 `GET /api/v1/documents/{doc}/images/{name}`

- 读 `kb/{kb_id}/docs/{doc_id}/images/{name}.png`（知识库技术方案 11.1）；权限同上。
- 返回 `Content-Type: image/png`，可加 `Cache-Control: private, max-age=...`（补充）。
- 校验 `name` 只是文件名（不含 `/`、`\`、`..`），防路径穿越（补充）；不合法返回 404。

### 3. 解析结果与引用位置数据 `GET /api/v1/documents/{doc}/parse`

- 参数 `kind=original|edited`（知识库技术方案 16）。返回该文档的解析结果 Markdown、引擎与版本、页数、OCR 页数、修改人和时间（来自 `document_parses`，知识库技术方案 11.2）。
- 位置数据：从对象存储里的 DoclingDocument JSON（`parsed/{kind}/doc.json`，知识库技术方案 11.1）按阅读顺序取出文字、表格、图片等元素，返回有序列表（每项含元素引用 `ref`，形如 `#/texts/12`、类型、文本），供 P3-18 在解析结果视图里按 `chunks.positions` 的元素引用高亮段落（知识库技术方案 7、13）。PDF 的页码/坐标由检索结果或分块里的 positions 提供，本卡不重复计算。
- `kind=edited` 且没有修改版 → 404（前端回落到 original）；文档还没有解析结果（处理中或失败）→ 按 P3-01 契约返回 404 或空，前端显示状态。
- 本卡只读，不提供保存修改（第五期）。

### 4. 错误码

- 优先用 P1 已有错误码；需要新错误码时按 P3-01 契约在 `backend/app/core/errors.py` 增加，不要另起一套。
