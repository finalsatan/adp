# P3-12 文档操作

状态：待开始
前置：P3-11
被依赖：P3-16（联调）、P3-19

## 目标

实现文档列表与状态、详情与编辑、重试、启停、删除、批量操作、重新解析（可改方案），并写审计。

## 依据

- 知识库技术方案 8.3（失败、重试与取消）、8.4（处理中拒绝编辑、启停更新 active）、8.5（重新解析、批量）、11.1（对象存储清理）、11.2（documents）、13（位置数据）、16（接口清单）、17（权限、审计）、19.3（流水线测试要点）
- 需求 4.1.3（文档状态与操作）、4.1.5（重新解析）、4.1.9（权限）、4.1.10
- 原型 `#v-kb`（文档列表）、`#d-upload`、`#m-reparse`
- P3-01 契约（请求 / 返回、错误码）；P3-08 的调度与排队位次；P3-09~P3-11 的流水线

## 要做

### 1. 列表与详情（知识库“查看”权限）

- `GET /api/v1/kbs/{kb}/documents`：分页；筛选状态、文件夹（含下级）、元数据、入库方案、有人工修改、关键字（文件名）。返回文件名、文件类型、大小、入库方案名与参数快照摘要、状态、步骤、进度、排队位次（P3-08 的 `queued_position`，形如“排队中（本库第 N 位）”）、分块数、元数据、启用、人工修改标记、失败原因、上传人、时间。
- `GET /api/v1/documents/{doc}`：详情含方案快照、`document_parses` 两份、`parse_records`、处理中标记、`current_generation`。
- 权限用 `app/resources/access.py`（P1-12）判断知识库的“查看”。

### 2. 编辑（知识库“编辑”权限）

- `PATCH /api/v1/documents/{doc}`：移动到文件夹、设置元数据、启停。元数据按 `kb_metadata_fields` 校验类型和选项。
- 不做重命名：需求 4.1.3 只列了移动、元数据、启停、删除、重试、重新解析，没有重命名（P3-16 也建议不做）。
- 文档处理中（`status='processing'`）时拒绝编辑解析结果和分块（8.4；本阶段没有编辑接口，先在详情里返回处理中标记，供第五期用）。

### 3. 重试（知识库“编辑”权限）

- `POST /api/v1/documents/{doc}:retry`：只对失败文档。从 `failed_step` 继续，不重复前面已完成的步骤（8.3）。`run_id` 换新、清失败信息、改排队中，触发 `dispatch`（P3-08）。

### 4. 重新解析（知识库“编辑”权限）

- `POST /api/v1/documents/{doc}:reparse`：`mode` 为 `reparse` / `rechunk`，可选 `scheme_id`（可改选其他方案）。
  - `reparse`：从步骤 1 开始，快照中的解析设置和分块设置都更新（8.5）。
  - `rechunk`：从步骤 3 开始，沿用当前解析结果（有人工修改版时用修改版），不调用解析引擎；快照中的解析设置不变，只更新分块设置（8.5）。
- `run_id` 换新，正在跑的任务在步骤边界退出并取消解析服务上的作业（8.3、P3-09）。
- 返回人工修改计数（解析结果是否被修改、被修改的分块数），供前端 `#m-reparse` 弹窗列出会覆盖哪些修改（需求 4.1.5）。本阶段没有编辑功能，计数为 0，字段照常返回（补充）。

### 5. 删除（知识库“编辑”权限）

- `DELETE /api/v1/documents/{doc}`：删除文档行（不可恢复，需求 4.1.3）；对象存储按前缀 `kb/{kb_id}/docs/{doc_id}/` 删除；索引表中该文档的条目删除。写审计 `document.delete`（知识库技术方案 17：删除和批量删除文档要审计）。
- 删除前若有正在跑的任务，先换 `run_id` 让它退出（8.3）。

### 6. 批量操作（知识库“编辑”权限）

- `POST /api/v1/documents:batch`：`action` 为 `set_metadata`、`move`、`enable`、`disable`、`delete`、`retry`、`reparse`，`ids` 为文档 ID 列表。
- 批量删除写一条审计 `document.batch_delete`（17）。
- 批量重试、批量重新解析由 maintenance 任务把选中的文档改为排队中，再触发 `dispatch`；**不一次性投递**，仍受按库并发上限约束（8.5）。
- 一次批量只能操作同一知识库的文档（补充）；跨库时返回 422。

### 7. 启停与索引 active

- 启停文档时更新该文档索引条目的 `active`（8.4，调用 P3-11 的 `set_doc_active`）；停用的文档不参与检索，但保留不删（需求 4.1.3）。
