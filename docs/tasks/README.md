把需求文档 v0.3、A1 原型和三份技术方案拆成可以交给编程智能体逐张完成的任务卡。分期按技术方案 v0.1 的 13.1。

- 开发前先读 `docs/tasks/开发约定.md`。
- 每张卡一个文件，状态写在卡片顶部（待开始 / 进行中 / 待验收 / 已验收）。查看全部状态：`grep -H '^状态' docs/tasks/*/*.md`
- 读文档和原型的小工具：`docs/tasks/tools/doc.py`（按章节取文档）、`docs/tasks/tools/proto.py`（按 id 取原型页面）。
- 这次拆细的是并行轨道、第一至四期；第五、六期只列任务名，等前一期快做完时再拆细。

## 拆任务时补充的内容（文档里没有，待确认）

卡片里标了“（补充）”的都是这类内容。下面只列用户看得到、或影响安全和数据的几条，纯实现细节不列。

1. 第一期还没有应用，终端用户登录后先进入空的“我的应用”占位页。
2. 弱密码表用 SecLists 的常见 1 万条密码（MIT）。
3. 已停用账号输对密码时提示“账号已停用，请联系管理员”；密码错误和用户名不存在仍统一提示。
4. 原型没画系统管理员的任命和撤销：用户管理的组织树顶部加一个“系统管理员”分组；任命放在编辑用户的角色选项里，撤销时选择所属组织和角色。
5. 首次登录改密不需要输入原密码（照原型）；个人中心改密需要。
6. 用户本人改密、管理员解锁用户也写审计日志。
7. resources 表增加 description、updated_at、deleted_at（应用软删除后，用量统计仍要显示名称）。
8. 看不到的资源返回 404，能看不能改返回 403。
9. 还没上线的模块，菜单先隐藏。
10. 未保存模型的连通测试，用量记在“未保存的模型”名下。
11. 用量统计的图表用 Recharts；按天趋势补齐没有调用的日期。
12. 每张卡完成后，开发模型在开发分支上提交（不推送），方便逐张看改动。
13. 管理员在用户管理里不能对自己停用、改角色、改所属组织、重置密码（自己的资料和密码走个人中心）；系统管理员可以撤销自己的系统管理员身份，只要不是最后一个。
14. 接口的请求带了多余字段时返回 422，不悄悄忽略。
15. 已停用的模型也能测试连通（方便排查）；连通测试不重试，整体 10 秒超时。
16. 重排模型的表单不显示能力参数和默认参数。
17. 本地开发的数据库、Redis 端口用 55432、56379，避开本机已有的服务。
18. 删除仍有下级文件夹或文档的文件夹时拒绝，提示先清空（不自动搬走、不级联删除）；删除元数据字段时同时从所有文档的 metadata 里删掉该键；元数据字段不允许改类型，只能改名称和选项。
19. 第三期不做文档重命名。
20. 问答库类型第三期可以建空库（0 个问答对），问答对功能第六期。
21. 第三期文档详情页不做只读“分块”页签，第五期和分块编辑一起做。
22. 相邻分块扩展属于第五期：P3-01 契约保留 adjacent_n，后端接收但不生效，P3-17 命中测试页暂时隐藏该控件。
23. 新增 P3-20“前端：系统设置的上传与解析分组”（前置 P3-01，联调需要 P3-07、P3-08，被 P3-19 依赖），照 P1-17 的结构写。
24. 同名文件“保留两份”命名为 原名(1).扩展名，序号从 1 递增取第一个不冲突的。
25. 上传预检的 sha256 由浏览器计算（Web Crypto）。
26. 内置方案默认引擎先按需求 4.1.4 写，等引擎接入和 H2 实测后再调。
27. 元数据过滤：文档列表只支持单条件，命中测试支持一层“且/或”多条件、不嵌套。
28. 单选元数据字段删掉某个选项后，已有文档上的该取值保留（照常显示、参与过滤），之后不能再选（2026-10-26 用户确认）。
29. 第四期默认值（记忆轮数、直答阈值、问答库召回阈值、文档库分数阈值）先用占位值并标“待实测”，应用技术方案 17.1 的实测由人做（2026-10-26 用户确认）。
30. 第四期端到端做到“点踩并填写纠错”为止；纠错加入问答库、问答库直答、追问建议、深度思考属第六期（2026-10-26 用户确认）。
31. 第四期引用预览只用假解析服务的 PDF、Word 固定样例验证，真实效果待 Docling 接入（2026-10-26 用户确认）。
