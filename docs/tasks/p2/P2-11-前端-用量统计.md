状态：待验收
前置：P2-01（联调需要 P2-08）
被依赖：P2-12

## 目标

做出用量统计页：筛选、四个汇总数字、按天趋势图、按维度汇总表。

## 依据

- 需求 7.2
- 技术方案 9.7
- 原型 `#v-usage`
- 接口：`GET /usage/summary`、`GET /usage/daily`、`GET /usage/meta`、`GET /models`、`GET /orgs`

## 要做

- 菜单：“系统观测”分组下“用量统计” `/observe/usage`，要求 `usage.view`。
- 页头说明和提示条照原型（按身份显示系统管理员 / 组织管理员两种文案）。
- 筛选：时间范围（默认最近 30 天，需求 7.2.2）、模型（全部模型 + 列表，含已停用的）、组织（TreeSelect，含下级）、应用（第二期没有应用：只显示“全部应用”且禁用，第四期再接）、来源（来自 meta）。改任一筛选项同时重查汇总和趋势。
- 四个数字卡片：调用次数、失败（数字 + 占比）、输入 Token、输出 Token。大数字用“万”为单位显示（如 6,120 万），小于 1 万时显示原数（补充：照原型）。
- 按天趋势：柱状图，可切换“调用次数 / Token”；悬停显示当天数值。图表库用 Recharts（补充：文档没有指定，选它是因为体积小、用法简单）。请求时 `tz` 传浏览器时区（`Intl.DateTimeFormat().resolvedOptions().timeZone`）。
- 汇总表：维度切换（模型、组织、应用、用户、来源），选“应用”时显示提示“按应用汇总时只统计来源为‘应用’‘应用调试’的调用”。列：名称（带 `sub_label` 时第二行灰字）、调用次数、占比（该行调用次数 ÷ totals.calls，前端计算）、失败、输入 Token、输出 Token。点表头排序（服务端排序）；分页。底部“共 N 行 · 合计 X 次”。

### 和卡片不一致 / 自己补充的地方

1. “万”只用于 Token：原型 `#v-usage` 里调用次数显示 48,216（原数），输入 Token 显示 6,120 万，所以拆成 `formatCount`（原数）和 `formatToken`（≥ 1 万用“万”）；卡片验收里的 61,200,000 → “6,120 万”由 `formatToken` 覆盖。
2. 身份文案按角色二选一（卡片要求两种文案）：系统管理员“当前身份：系统管理员，可查看全部记录。”；组织管理员“当前身份：组织管理员，只看到本组织及下级组织发起的调用。”。
3. 趋势图下方只保留“悬停柱子可查看当天数值。”，未照抄原型里“10-01 至 10-08 为国庆假期”这段示例数据说明。
4. 汇总默认维度取“组织”（照原型默认选中）。
5. 日期范围按整天处理：`from` 取开始日 00:00，`to` 取结束日次日 00:00（接口按 `at < to` 过滤）。
6. `frontend/src/pages/observe/api.ts` 是卡片“UsagePage.tsx 及子组件”之外、放在同一目录的挂钩子文件。
