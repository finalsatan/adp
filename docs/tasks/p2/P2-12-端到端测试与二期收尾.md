## 要做

### 1. 本地假模型服务 `backend/tests/fake_llm/server.py`

- 一个小的 FastAPI 应用，实现 OpenAI 兼容的 `POST /v1/chat/completions`（支持 `stream: true`，按固定文本逐字输出，最后一个片段带 usage；请求里带特定内容时可以模拟慢速首字或报错，便于以后测试）和 `POST /v1/embeddings`（返回固定维度的向量）。
- 只用于测试和本地联调，不进生产镜像。
- Makefile 增加 `fake-llm`（在 9999 端口启动）。

### 2. 端到端用例（加到 `frontend/e2e/`）

Playwright 的 `webServer` 增加假模型服务。用例：

1. 系统管理员登录 → 系统设置的模型接口地址白名单加入 `127.0.0.1` → 添加两个对话模型（`openai/fake-a`、`openai/fake-b`，接口地址 `http://127.0.0.1:9999/v1`，任意密钥）→ 保存前测试连通成功 → 保存。
2. 列表中“测试”显示连通成功。
3. 模型体验页添加对比模型，两列分别选两个模型 → 发送 → 两列都流式出现回答和统计行。
4. 再发一个问题并在输出中途点“停止生成”。
5. 用量统计页：按来源汇总能看到“模型体验”“连通测试”的调用次数。
6. 搭建者登录：模型管理只有“测试”操作；能进入模型体验；侧栏没有“用量统计”。

### 3. 部署变更

- `deploy/.env.example`、`deploy/gen-secrets.sh`：`MASTER_KEY`（P2-02 已加的话核对一遍）；`LITELLM_LOCAL_MODEL_COST_MAP=True`；`HTTPS_PROXY` 的说明。
- `backend/Dockerfile`：tiktoken 编码文件已在构建时下载（P2-05），确认容器断网时 `api` 仍能启动、能估算 token。
- `deploy/README.md` 更新：
  - `MASTER_KEY` 必须备份，丢失后所有模型密钥无法解密，只能重新录入（技术方案 9.2、15）。
  - api 容器需要能访问所用云模型供应商的 HTTPS 地址；需要代理时设置 `HTTPS_PROXY`。
  - 客户内网的模型网关要先加入系统设置的接口地址白名单。
  - 最低配置不变。
