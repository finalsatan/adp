# P2-09 前端：模型管理

状态：待验收
前置：P2-01（联调需要 P2-03、P2-06）
被依赖：P2-12

## 目标

做出模型管理页：列表、添加和编辑抽屉（含测试连通）、测试弹窗、停用确认弹窗、删除。

## 依据

- 需求 3.2–3.4
- 原型 `#v-models`、`#d-newmodel`、`#d-editmodel`、`#m-modeltest`、`#m-disable`
- 接口：`GET/POST /models`、`GET/PATCH/DELETE /models/{id}`、`GET /models/{id}/refs`、`:disable`、`:enable`、`:test`、`POST /models:test`

## 要做

### 1. 菜单和路由

在 P1-02 的菜单配置里加“模型服务”分组：“模型管理” `/models`、“模型体验” `/models/playground`，都要求 `console.use`。根路径 `/` 的默认落点随之变为“模型管理”（第一个可见菜单）。

### 2. 列表页（照原型 `#v-models`）

- 页头说明“所有模型调用经由 LiteLLM 统一转发。密钥加密保存，界面和接口不显示明文。”；系统管理员有“添加模型”按钮。
- 身份提示条：系统管理员显示“模型由系统管理员统一添加和维护，添加后全平台可用，不按组织区分。当前身份：系统管理员。”；其他角色显示“……搭建者和组织管理员在此只能查看和测试。”
- 筛选：关键字、类型（全部、对话、向量化、重排）、状态；右侧“共 N 个模型”。
- 列：名称 / 模型 ID（两行）、类型、能力（对话：上下文长度如“128K”、视觉、函数调用、深度思考标签；向量化：“1024 维”；重排：“—”）、状态、被引用（如“应用 12”“知识库 8”，多个类型用顿号，都为 0 时显示 0）、最近测试（✓ 连通 / ✕ 失败 + 时间，失败时第二行显示原因）、操作。
- 操作：系统管理员为 编辑、测试、停用或启用、删除；其他角色只有 测试。

### 3. 添加、编辑抽屉（`#d-newmodel`、`#d-editmodel`）

- 分组：基本信息（类型、显示名称、模型 ID、接口地址、API Key、描述）、能力参数、默认参数（温度、Top P）、调用设置（首字超时、总超时、失败重试次数、限流 QPS、最大并发），提示文字照原型。
- 类型为向量化时，能力参数换成 向量维度、最大输入长度、单次请求最多条数；为重排时不显示能力参数和默认参数（补充）。
- 编辑时：类型只读；`fields_locked` 为真时模型 ID 和向量维度只读并提示“向量化模型被知识库引用后，模型 ID 和向量维度不可修改”；API Key 显示 `sk-••••{last4}` 和“更换密钥”按钮，点了才出现输入框，提示“密钥不回显明文，更换会写入审计日志；不更换时测试连通使用已保存的密钥”。
- 底部按钮：取消、测试连通、保存。测试连通调用 `POST /models:test`（编辑时带 `model_id`），结果显示在按钮上方：成功“✓ 连通成功 · 首字 0.71s · 返回模型 xxx”，失败“✕ 连通失败：{说明}”。
- 后端字段错误显示在对应输入框下（`NAME_CONFLICT`、`MODEL_HOST_NOT_ALLOWED`、`MODEL_FIELD_LOCKED`）。

### 4. 测试弹窗（`#m-modeltest`）

列表中点“测试”调用 `POST /models/{id}:test`，弹窗显示结果、耗时、模型 ID、测试请求说明（对话类：发送“你好”，最多输出 16 tokens，测试时关闭深度思考）、返回内容、测试时间；底部“重新测试”。失败时显示原因。测完刷新列表的“最近测试”。

### 5. 停用弹窗（`#m-disable`）与删除

- 停用前先调 `GET /models/{id}/refs`，弹窗列出“引用它的资源 / 类型 / 负责人”，说明“停用后，以下 N 个资源调用该模型时会提示‘模型不可用’。可稍后重新启用。”；没有引用时只显示确认文字。
- 删除：Popconfirm；返回 `RESOURCE_IN_USE` 时弹窗列出引用清单，说明需先解除引用（需求 3.4）。
