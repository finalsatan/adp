# P2-08 用量统计接口

状态：待开始
前置：P2-02
被依赖：P2-11

## 目标

实现用量统计的汇总、按天趋势和来源列表三个接口。

## 依据

- 需求 7.2（统计口径、页面与权限）
- 技术方案 9.7（**逐条照做**）、13.2 的“用量统计”
- 原型 `#v-usage`
- P2-01 用量接口

## 要做

全部要求 `usage.view`。直接对 model_usage 做汇总查询，不预先汇总（技术方案 9.7）。

### 1. 公共筛选

- `from`、`to` 必填，`to` 晚于 `from`，跨度不超过 366 天，否则 422 `INVALID_TIME_RANGE`。按 `at >= from AND at < to` 过滤。
- `model_id`、`source` 直接过滤。
- `org_id`：先按 orgs.path 前缀取出该组织及下级的全部 id（**含已删除组织**），再 `org_id IN (...)`。组织管理员筛选范围外的组织 → 403。
- `app_id`：`source IN ('app', 'app_debug') AND source_id = app_id`。
- 权限范围：系统管理员不加条件；组织管理员加 `org_id IN (管理范围内的组织)`，因此看不到系统管理员发起的调用（org_id 为空）（技术方案 9.7）。

### 2. `GET /usage/summary`

- `totals`：筛选后全部记录的调用次数、失败次数（`ok = false`）、输入和输出 token 之和。
- 按 `group_by` 分组：
  - `model`：按 model_id；名称取 models.name（已删除的也取得到）；model_id 为空的一组标签为“未保存的模型”（P2-06 的表单测试）。
  - `org`：按 org_id，每个组织单独一行（不把下级并入上级）；为空的一组标签“系统管理员”；`sub_label` 写上级组织名，如“研发中心下级”（照原型，补充）。
  - `app`：只统计 `source IN ('app','app_debug')`，按 source_id，名称取 resources（已删除的也显示）。第二期没有应用，结果为空。
  - `user`：按 user_id，标签为“用户名 姓名”。
  - `source`：按 source，标签为中文名。
- 排序：按 `sort_by` 和 `order`；分页；`total` 为分组数。

### 3. `GET /usage/daily`

- `tz` 必须是合法的 IANA 时区名（用 `zoneinfo` 校验），否则 422。
- `date_trunc('day', at AT TIME ZONE :tz)` 分组，返回每天的调用次数、失败次数、输入和输出 token。
- 范围内没有调用的日期补 0（补充），按日期升序。日期范围按 `tz` 换算 from、to 的本地日期。

### 4. `GET /usage/meta`

返回来源代码和中文名：模型体验、连通测试、应用、应用调试、入库、命中测试、方案试运行、API（需求 7.2.1）。

## 验收标准

- [ ] 测试（直接往 model_usage 插造好的数据）：
  - 各维度的汇总与逐条记录手算一致（技术方案 13.2）；`totals` 不受分页影响。
  - 筛选组织时包含下级组织；用户调到其他组织后，他以前的记录仍算在原组织（记录里是快照，不随用户变）。
  - 组织管理员只看到范围内的记录，看不到系统管理员发起的调用；筛选范围外的组织返回 403。
  - 搭建者、终端用户调用返回 403。
  - 时间范围超过 366 天返回 422。
  - 按天汇总按传入时区分日：同一条 `2026-10-21T17:00:00Z` 的记录，`tz=UTC` 时算 10-21，`tz=Asia/Shanghai` 时算 10-22；没有调用的日期为 0。
  - 已删除的模型、组织在结果中仍显示名称；model_id 为空的记录显示“未保存的模型”。
- [ ] `make backend-lint backend-test` 通过。
