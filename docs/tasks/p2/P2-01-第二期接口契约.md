### 3. 错误码（加到 `core/errors.py`）

| code | HTTP | message |
| --- | --- | --- |
| `MODEL_UNAVAILABLE` | 409 | 模型不可用（已停用或已删除） |
| `MODEL_RATE_LIMITED` | 429 | 当前调用的人较多，请稍后再试 |
| `MODEL_FIELD_LOCKED` | 409 | 该向量化模型已被知识库引用，模型 ID 和向量维度不能修改 |
| `MODEL_TYPE_IMMUTABLE` | 422 | 模型类型创建后不能修改 |
| `MODEL_TYPE_MISMATCH` | 422 | 该模型的类型不支持这个操作（如对向量化模型发起对话） |
| `MODEL_HOST_NOT_ALLOWED` | 422 | 接口地址指向内网或本机，不允许使用；如需使用请在系统设置中加入白名单 |
| `MODEL_CALL_FAILED` | 502 | 模型调用失败（`detail.error_code` 为下面的调用错误代码） |
| `INVALID_TIME_RANGE` | 422 | 时间范围不正确或超过 366 天 |

模型调用错误代码（记在 `model_usage.error_code`，也用于 RUN_ERROR 事件和连通测试结果）：`UPSTREAM_AUTH`（密钥无效）、`UPSTREAM_NOT_FOUND`（模型不存在）、`UPSTREAM_BAD_REQUEST`（请求参数不被接受）、`UPSTREAM_RATE_LIMITED`（供应商限流）、`UPSTREAM_ERROR`（供应商 5xx 或其他错误）、`CONNECT_ERROR`（连接失败）、`FIRST_TOKEN_TIMEOUT`（首字超时）、`TOTAL_TIMEOUT`（总超时）、`CONTEXT_TOO_LONG`（超出上下文长度）、`CANCELLED`（调用方取消）、`DIM_MISMATCH`（向量维度与登记的不一致，只在连通测试中出现）。

### 4. 模型接口 `app/models/router.py`（tag：模型）

| 接口 | 请求 | 返回 | 权限 |
| --- | --- | --- | --- |
| `GET /api/v1/models` | `type?`、`status?`、`keyword?`（名称或模型 ID）、分页 | `Page[ModelOut]` | console.use |
| `POST /api/v1/models` | `ModelCreate` | 201 `ModelOut` | model.manage |
| `GET /api/v1/models/{id}` | — | `ModelOut` | console.use |
| `PATCH /api/v1/models/{id}` | `ModelUpdate` | `ModelOut` | model.manage |
| `GET /api/v1/models/{id}/refs` | — | `list[ModelRefOut]` | console.use |
| `POST /api/v1/models/{id}:disable`、`:enable` | — | `ModelOut` | model.manage |
| `DELETE /api/v1/models/{id}` | — | 204 | model.manage |
| `POST /api/v1/models/{id}:test` | — | `ModelTestResult` | console.use |
| `POST /api/v1/models:test` | `ModelTestIn` | `ModelTestResult` | model.manage |
| `POST /api/v1/models/{id}/chat` | `PlaygroundChatIn` | `text/event-stream` | console.use |

- `ModelOut`：`id`、`name`、`model_type`、`litellm_model`、`api_base`、`api_key_last4`（只有末 4 位，没有密钥时为 null）、`description`、`context_length`、`max_output`、`cap_vision`、`cap_tools`、`cap_thinking`、`embedding_dim`、`embedding_max_input`、`embedding_batch_size`、`default_params: {temperature?, top_p?}`、`first_token_timeout_s`、`total_timeout_s`、`max_retries`、`rate_qps`、`rate_concurrency`、`status`、`ref_counts: {app, kb, scheme}`、`fields_locked: bool`（向量化模型被知识库引用后为真）、`last_test_at`、`last_test_ok`、`last_test_message`、`created_at`、`updated_at`。**没有任何密钥字段**。
- `ModelCreate`：`name`（1–50 字）、`model_type`、`litellm_model`（`供应商/模型`，含一个 `/`）、`api_base?`、`api_key?`、`description?`；对话类：`context_length`、`max_output`、`cap_vision`、`cap_tools`、`cap_thinking`；向量化类：`embedding_dim`（1–4000）、`embedding_max_input`、`embedding_batch_size`；`default_params?`；调用设置 `first_token_timeout_s`（默认 30）、`total_timeout_s`（默认 300）、`max_retries`（默认 2，0–5）、`rate_qps?`、`rate_concurrency?`（留空不限流）。不同类型不需要的字段可以省略；需要的字段缺失时 422（用校验器按类型检查）。
- `ModelUpdate`：除 `model_type` 外都可选；`api_key` 为空或省略表示沿用已保存的密钥，非空表示更换（技术方案 9.4）。带 `model_type` 返回 422 `MODEL_TYPE_IMMUTABLE`。
- `ModelRefOut`：`resource_id`、`type`、`type_label`、`name`、`owner: UserBrief`、`org: OrgBrief`（停用弹窗 `#m-disable` 用）。
- `ModelTestIn`：与 `ModelCreate` 相同字段，另加 `model_id?`：编辑已有模型、表单里没填密钥时用已保存的密钥测试。
- `ModelTestResult`：`ok`、`latency_ms`、`first_token_ms?`、`reply?`（对话类的返回文字）、`returned_model?`、`dims?`（向量化）、`error_code?`、`error_message?`、`tested_at`。
- `PlaygroundChatIn`：`messages: list[{role: "user" | "assistant", content: str}]`（1–100 条）、`params: {temperature?, top_p?, max_tokens?, thinking?: bool}`。

### 5. SSE 事件（技术方案 9.6，D9）

每条事件只用 `data:` 一行，内容是带 `type` 字段的 JSON；心跳是注释行 `: ping`。

| type | 字段 |
| --- | --- |
| `RUN_STARTED` | `run_id` |
| `TEXT_DELTA` | `delta` |
| `REASONING_DELTA` | `delta` |
| `RUN_FINISHED` | `input_tokens`、`output_tokens`、`first_token_ms`、`total_ms` |
| `RUN_ERROR` | `code`（调用错误代码或 `MODEL_UNAVAILABLE`、`MODEL_RATE_LIMITED`）、`message` |

- 用 Pydantic 定义这些事件模型，用判别联合 `SseEvent`。SSE 内容不会自动进 OpenAPI，要通过自定义 `app.openapi()` 把 `SseEvent` 加到 components 中（补充），前端据此生成类型。
- 以后第四期会加 `STEP_STARTED`、`STEP_FINISHED`、`CITATIONS`、`SUGGESTIONS`、`TRACE`，前端遇到不认识的 type 忽略。

### 6. 用量统计接口 `app/usage/router.py`（tag：用量，要求 usage.view）

| 接口 | 请求 | 返回 |
| --- | --- | --- |
| `GET /api/v1/usage/summary` | `from`、`to`（必填，ISO 时间）、`model_id?`、`org_id?`（含下级）、`app_id?`、`source?`、`group_by`（model / org / app / user / source）、`sort_by`（calls / failures / input_tokens / output_tokens，默认 calls）、`order`（desc / asc）、分页 | `UsageSummaryOut` |
| `GET /api/v1/usage/daily` | 同上的筛选参数，另加 `tz`（IANA 时区名，如 `Asia/Shanghai`） | `{items: [{date, calls, failures, input_tokens, output_tokens}]}` |
| `GET /api/v1/usage/meta` | — | `{sources: [{code, label}]}` |

`UsageSummaryOut`：`totals: {calls, failures, input_tokens, output_tokens}`（按筛选条件的全部记录，不受分页影响）、`items: [{key, label, sub_label?, calls, failures, input_tokens, output_tokens}]`、`total`（分组数）。`key` 为分组值（字符串，空值为 null），`label` 为名称，`sub_label` 用于“研发中心下级”这类补充说明（可选）。
