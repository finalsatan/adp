# P2-03 模型管理接口

状态：待验收
前置：P2-02
被依赖：P2-06、P2-09

## 目标

实现模型的列表、详情、新建、编辑（含更换密钥）、引用清单、停用启用、删除，并写审计。

## 依据

- 需求 3.1–3.4
- 技术方案 6.3、9.1、9.2、9.5、13.2（权限、密钥、模型调用中的 409 两条）
- 原型 `#v-models`、`#d-newmodel`、`#d-editmodel`、`#m-disable`
- P2-01 模型接口

## 要做

### 1. 审计动作（加到 `audit/actions.py`）

`model.create` 添加模型、`model.update` 编辑模型、`model.change_key` 更换模型密钥、`model.disable` 停用模型、`model.enable` 启用模型、`model.delete` 删除模型；对象类型 `model`（模型），desc 为显示名称，对象组织为空（模型不属于组织）。写操作的路由依赖第一个放 `audited(...)`。

### 2. 列表与详情（console.use）

- 排除已删除。筛选类型、状态、关键字（名称或模型 ID）。按创建时间倒序。
- `ref_counts`：按 resource_refs（`target_type='model'`）联 resources（未删除）按资源类型分组计数，键为 `app`、`kb`、`scheme`。
- `fields_locked`：向量化模型且被类型为 `kb` 的资源引用。
- 搭建者、组织管理员能看列表和详情（需求 3.4），只有系统管理员能改，由接口权限码保证。

### 3. 新建（model.manage）

- 校验：名称在未删除模型中唯一 → 409 `NAME_CONFLICT`；`litellm_model` 形如 `供应商/模型`；`api_base` 过 P2-02 的 `check_model_host`（白名单取系统设置 `model_call.model_host_allowlist`）；按类型检查必填字段（对话：上下文长度、最大输出；向量化：维度、最大输入长度、单次条数）；维度 1–4000（技术方案 9.1）；`first_token_timeout_s ≤ total_timeout_s`（补充）。
- 有 `api_key` 时加密存 `api_key_cipher`，存 `api_key_last4`。
- 审计 `model.create`（detail 不含密钥）。

### 4. 编辑（model.manage）

- 带 `model_type` → 422 `MODEL_TYPE_IMMUTABLE`。
- `fields_locked` 为真时修改 `litellm_model` 或 `embedding_dim`（值有变化）→ 409 `MODEL_FIELD_LOCKED`（需求 3.4）。名称、密钥、调用设置等仍可改。
- `api_key` 非空：重新加密保存，另写一条审计 `model.change_key`；为空或省略：沿用原密钥。
- 改了 `api_base` 时重新校验地址。
- 其他字段有变化时审计 `model.update`，detail 为变化的字段名列表（不含值也可以，但绝不含密钥）。

### 5. 引用清单 `GET /models/{id}/refs`（console.use）

resource_refs 中引用该模型、且未删除的资源，带类型中文名、创建人、所属组织（停用确认弹窗用，技术方案 9.5）。第二期表里没有数据，返回空列表。

### 6. 停用、启用、删除（model.manage）

- 停用：直接停用并审计（影响清单由前端先调 `refs` 展示，需求 3.4）。启用同理。
- 删除：有引用 → 409 `RESOURCE_IN_USE`，`detail.refs` 为引用清单；无引用 → 软删除（写 deleted_at），审计。删除后名称可以被新模型使用。

### 7. 不泄露密钥

所有响应模型都不含密钥字段；日志里不打印请求体中的 `api_key`（检查访问日志和错误日志的实现，校验错误的 `detail.errors` 里不能回显 `api_key` 的值——Pydantic 的错误项含 `input`，要把这个字段的 input 去掉）。
