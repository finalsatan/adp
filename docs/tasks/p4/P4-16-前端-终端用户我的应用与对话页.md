# P4-16 前端：终端用户“我的应用”与对话页

状态：待验收
前置：P4-01（联调需要 P4-09、P4-10、P4-13；对话组件复用 P4-15 的 `components/chat`）
被依赖：P4-18

## 目标

做出终端用户的“我的应用”列表和对话页：新建/重命名/删除会话、流式提问、停止与重新生成、引用角标与预览下载、点赞点踩与纠错；替换第一期的“我的应用”占位页。

## 依据

- 需求 5.1.2（引用与下载）、5.4.4（终端用户使用）、5.4.5（用户反馈）
- 应用技术方案 8（引用：角标、快照、终端用户预览与下载）、9（流式输出与生成控制）、11（使用范围与终端用户入口）、13（接口清单）、14（权限）、15（前端）
- 原型 `#v-myapps`、`#v-chat`
- P4-01 契约；P4-15 的 `components/chat`（对话组件）；P3-18 的 `PdfPreview` / `ParseResultView`（引用预览复用）

## 要做

### 1. “我的应用”（照原型 `#v-myapps`）

- 替换 `frontend/src/pages/myapps/MyAppsPage.tsx` 的占位实现；调 `GET /my/apps`，卡片显示名称、描述、所属组织、类型、开场白；“开始提问”进入 `/chat/{app_id}`。
- 空状态；只显示使用范围包含本人、已发布且未停用的应用（应用技术方案 11）。
- 入口：终端用户登录后进入“我的应用”；其他角色从控制台顶栏进入（在控制台顶栏加“我的应用”入口，应用技术方案 11；补充）。
- 打开对话页时不在使用范围显示“你没有使用该应用的权限”，未发布或已停用显示“应用暂不可用”（应用技术方案 11）。

### 2. 对话页（照原型 `#v-chat`）

- 路由 `/chat/:appId` 与 `/chat/:appId/:conversationId`（补充，照应用技术方案 11）；新建会话：第一次提问后由 `RUN_STARTED` 拿到会话 ID，用 `history.replaceState` 改写地址，不重新加载页面。
- 左侧会话列表：新建会话、按“今天 / 更早”分组、重命名、删除（`PATCH/DELETE /conversations/{conv}`）；删除确认框写明“只从你的列表中移除，对话日志仍保留”。
- 开场白与开场推荐问题（`GET /chat/apps/{app}` 返回）；点击推荐问题填入输入框。
- 提问：新会话先 `POST /chat/apps/{app}/conversations`，再 `POST /conversations/{conv}/turns` 读取 SSE，流式渲染回答；复用 P4-15 的 `ChatPanel`（含角标解析、停止、复制、重新生成）。
- 停止生成：中止 fetch；后端把回答状态记为 `stopped` 并保存已输出部分。`CONVERSATION_BUSY`（409）提示“上一个回答还在生成”。
- 重新生成：只能对最后一问，调 `POST /turns/{turn}:regenerate`（SSE）；旧回答在日志中可见（P4-17）。
- 回答用 `SafeMarkdown` 渲染；回答下方引用列表只显示实际引用的条目（`cited`），没有角标时不显示。
- 追问建议第六期，本期不显示（用户决定）。

### 3. 引用预览与下载（照原型 `#v-chat` 抽屉）

- 点击角标打开引用预览抽屉：调 `GET /answers/{answer}/citations/{n}/preview`，按 `citations` 快照里的 `file_type` 选择渲染方式（应用技术方案 8.3）：
  - PDF：只含被引用页的 PDF，复用 P3-18 的 `PdfPreview`（按快照坐标高亮）。
  - Word 等文本类：Markdown 片段，复用 P3-18 的 `ParseResultView`（高亮被引用元素）。
  - 文档已重新入库或人工修改：只显示快照片段并注明“原文已更新”/“人工修改内容”。
- 下载原文件：应用当前发布版本开启“允许下载原文件”时显示按钮，调 `GET /answers/{answer}/citations/{n}/file`；未开启显示“本应用未开启下载”（照原型）。
- 本期只支持 PDF、Word 的引用预览（用户决定：解析服务搁置，用 `backend/tests/fake_parser` 的固定样例验证），其余文件类型随知识库第五期。

### 4. 点赞、点踩与纠错（照原型 `#v-chat`）

- 每条回答点赞/点踩：`PUT /answers/{answer}/feedback`；再次点击为更新，取消调 `DELETE`。
- 点踩展开原因（答案错误/没有回答问题/引用不对/其他，选项照原型）和纠错内容输入；提交后调 `PUT`（带 `reasons`、`correction`）。
- 只能对自己的会话中的回答反馈，且仍在使用范围内（应用技术方案 12.3）。

### 5. 会话与权限

- 终端用户接口不要求控制台权限码，只要求登录且通过使用范围判断；每次提问、读取会话、预览引用都重新判断（应用技术方案 11）。
- 用户删除会话后，对话日志仍保留（P4-17）。

### 与卡片不一致 / 实现说明

- **开场白**：见“问题”。
- **`ChatPanel.tsx` 的扩展**：卡片文件清单没有列它，但卡片要求复用 P4-15 的对话组件、并要历史、逐回答引用列表、点赞点踩、按最后一问重新生成。为此只加了向后兼容的可选参数：`initialMessages`（历史消息，id 用负数避免与内部自增冲突）、`renderAnswerActions`（反馈插槽）、`ChatRunRequest.mode`（区分提问 / 重新生成）、`ChatMessage.answerId`；`onCitationClick` 追加 `answerId` 参数。调试预览（P4-15）不传这些参数，行为不变，原测试通过。
- 新会话第一次提问先 `POST /chat/apps/{app}/conversations`，再由 `RUN_STARTED` 的 `conversation_id` 用 `window.history.replaceState` 改写地址（不刷新），并让 `ChatPanel` 不重挂、继续流式渲染。
- 会话历史：打开 `/chat/{appId}/{conv}` 时 `GET /conversations/{conv}/turns` 加载，转成 `initialMessages` 灌入共用组件；重新生成按 `POST /turns/{turn}:regenerate` 走 SSE（只对最后一问）。
- 引用列表按回答全文角标编号（`citedNumbers`）过滤 `citations`，没有角标时不显示。
- 反馈：点赞点击即 `PUT`，再点取消 `DELETE`；点踩展开原因（答案错误/没有回答问题/引用不对/其他）与纠错输入，提交 `PUT`；已点踩时再点打开面板即为更新，面板“取消”在已点踩时 `DELETE`。
- 引用预览：PDF 用只含被引用页的 PDF，复用 P3-18 的 `PdfHighlightLayer` / `pageRects`，并把返回 PDF 的页序号映射回快照原始页码高亮；Word 复用 `ParseResultView` 高亮被引用元素；快照降级显示后端 `note`（原文已更新 / 人工修改内容）。下载按钮按 `AppChatInfoOut.allow_download` 显示 / 隐藏。
- 本期不显示追问建议（`ChatPanel` 不渲染 `suggestions`）。
