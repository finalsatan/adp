# P4-05 使用范围与“我的应用”、终端用户入口与权限

状态：待验收
前置：P4-03
被依赖：P4-09（会话与提问）、P4-10（引用预览）、P4-14、P4-16（前端）；P4-05 完成前，P4-06～P4-08 只用服务内函数，不经过使用范围判断

## 目标

实现使用范围的读取与修改、“我的应用”列表、终端用户打开对话页需要的应用信息，以及统一的“用户能否使用应用”判断函数（后续所有终端用户接口和引用预览都调它）。

## 要做

### 1. 使用范围判断 `app/apps/usage.py`

- `app_usable_by_user(session, app, user) -> bool`：应用已发布（`published_version_id` 非空）、未停用、未删除；用户状态启用；并满足使用范围之一（应用技术方案 11）：
  - `platform`：所有登录用户；
  - `orgs`：用户所属组织的 path 以 `app_usage_targets` 中任一组织（`target_type='org'`）的 path 开头（含下级）；
  - `users`：用户在名单中（`target_type='user'`）。
  - 不看角色。系统管理员不属于任何组织，只有 `platform` 或被列入用户名单时才在范围内。
- `get_chat_app(session, ctx, app_id) -> (app, resource)`：终端用户打开对话页用；不存在或已删除 → 404；未发布 → 403 `APP_NOT_PUBLISHED`；已停用 → 403 `APP_DISABLED`；不在范围 → 403 `APP_NOT_IN_SCOPE`。**每次提问、读取会话、预览引用都重新调用**（使用范围修改后立即生效，应用技术方案 11）。
- 每次实时计算，不做缓存。

### 2. “我的应用” `GET /api/v1/my/apps`

- 把上面的条件拼成一条 SQL 的 WHERE（应用已发布、未停用、未删除、用户启用、使用范围匹配），join `resources` + `orgs`，按名称排序；返回 `list[MyAppOut]`。数据量小，不做缓存（应用技术方案 11）。
- 权限：只要求已登录（`CurrentCtx`），不要求任何控制台权限码。

### 3. 使用范围接口 `app/apps/router.py`

- `GET /api/v1/apps/{id:int}/usage-scope`：资源“查看”权限；返回 `UsageScopeOut`（`platform` 时两个列表为空）。
- `PUT /api/v1/apps/{id:int}/usage-scope`：资源“管理”权限；按 `UsageScopeIn` 全量替换 `apps.usage_scope` 和 `app_usage_targets`（先删后插，同一事务）；校验 `platform` 时两个列表为空、`orgs` 时组织非空、`users` 时用户非空；组织、用户必须存在且未删除；写审计 `app.change_usage_scope`（`detail` 含 `from`、`to`）。修改不需要重新发布（需求 5.4.3）。
- 终端用户入口：`GET /api/v1/chat/apps/{id:int}` 在 P4-01 契约里，本卡实现为调 `get_chat_app` 并返回 `AppChatInfoOut`（`opening`、`opening_questions`、`suggestions`、`allow_download` 取自当前发布版本的 `reply` 配置；`suggestions` 第六期生效）。权限：已登录 + 使用范围。

### 4. 登录后去向与前端入口（说明，不在本卡改前端）

- 终端用户登录后进入“我的应用”，其他角色进入控制台；控制台顶栏加“我的应用”入口（需求 5.4.4，应用技术方案 11）。`GET /me` 已返回角色（P1-06），后端不需要新接口；前端在 P4-16 做。
- 对话页链接 `/chat/{app_id}`、`/chat/{app_id}/{conversation_id}`；打开时未登录跳登录页、登录后回原链接；不在范围显示“你没有使用该应用的权限”，未发布或已停用显示“应用暂不可用”（前端 P4-16 做，文案以原型为准）。

### 5. 审计动作

`app/audit/actions.py` 加 `app.change_usage_scope` 调整使用范围。

### 和卡片不一致 / 自己补充的地方

1. **使用范围服务函数也放在 `usage.py`**：卡片“文件”一节只列了 `usage.py` 给 `app_usable_by_user` / `get_chat_app`，但第 2、3 节的“我的应用”和使用范围读写没有指定 service 文件；都放 `usage.py`，避免再动 `service.py`。
2. **`set_usage_scope` 的组织 / 用户不存在返回 404 `NOT_FOUND`**：卡片只写“必须存在且未删除”，没给错误码；按引用实体缺失处理（与 `create_resource` 找不到组织一致），测试也覆盖了。
3. **终端用户对私有应用 `PUT /apps/{id}/usage-scope` 返回 404 而不是 403**：`PUT` 按卡片只做资源“管理”判断（未加 `console.use`，与 P4-03 的编辑接口一致），看不到的资源先 404；`GET` 有 `console.use`，终端用户返回 403。验收标准只明确要求 `GET` 返回 403，测试按此断言。
4. **`get_chat_app` 的 `reply` 解析复用 P4-04 的 `validation.parse_config`**：终端用户入口从当前发布版本的 `config` 取 `reply`，容错 `{}`。
5. **`app_usable_by_user` 额外读一次 `Resource`**：卡片入参只有 `app` / `user`，停用与软删在 `resources` 表，需要按 `app.id` 取一次。
