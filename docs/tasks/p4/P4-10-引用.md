# P4-10 引用

状态：已验收

## 目标

生成引用快照、解析并记录实际引用的角标，提供终端用户的引用预览与下载（第四期先支持 PDF 和 Word）。

- P3-14 的原文读取与解析结果、P3-13 的 `positions`、P3-09 的假解析服务固定样例（`backend/tests/fake_parser`）、P4-01 契约、P4-09 的落库与事件

## 要做

### 1. 引用模块 `app/chat/citations.py`

集中放：从检索候选生成引用快照、提取实际引用的角标、以及预览与下载的实现（P4-11、P4-12 复用预览函数）（补充）。

### 2. 角标与引用快照（8.1、8.2）

- 生成开始前由 P4-09 发 `CITATIONS`，列出本次全部参考内容的编号、类型、来源名、片段（不含位置）。
- 每条回答的 `chat_answers.citations`（jsonb）保存本次全部参考内容，字段照 8.2：
  - 问答对（`type="qa"`）：`n`、`type`、`kb_id`、`kb_name`、`qa_id`、`question`、`answer`、`score`（第六期，本卡只留结构）。
  - 文档分块（`type="doc"`）：`n`、`type`、`kb_id`、`kb_name`、`doc_id`、`doc_name`、`file_type`、`chunk_ids`、`generation`、`content`、`positions`、`edited`、`score`。
- `positions` 复制自分块（格式见知识库技术方案 13）；相邻分块扩展时合并各块位置（第五期）。
- 快照存完整的参考内容，PostgreSQL 会压缩存储。
- 生成结束后从全文提取实际出现过的编号存 `cited`（P4-09 落库）；前端渲染角标（P4-16）。`[1、2]` 跨两个片段按累积全文解析、全角 `【1】` 的识别都在前端，后端只负责 `cited`（8.1）。

### 3. 终端用户预览与下载（8.3）

接口（结构以 P4-01 契约为准）：

| 接口 | 说明 |
| --- | --- |
| `GET /api/v1/answers/{answer}/citations/{n}/preview` | 被引用的页或段落 |
| `GET /api/v1/answers/{answer}/citations/{n}/file` | 下载原文件（需开启下载） |

- 每次都检查：回答所在会话属于本人；应用已发布、未停用；本人仍在使用范围内（Q6）。只能访问快照中 `n` 对应的那个文档，不接受其他文档 ID。
- 下载额外要求应用**当前发布版本**开启了 `allow_download`，不看生成回答时的版本；搭建者关闭下载后立即生效。未开启返回 `DOWNLOAD_NOT_ALLOWED`。
- 服务端只返回被引用的部分，不把整份 PDF 发给前端（8.3 的核心约定）：
  - PDF（含扫描件）、PPT：只含被引用页的 PDF，用 pypdfium2 从原文件（PPT 从 `preview.pdf`）取出这些页另存，缓存在对象存储 `kb/{kb}/docs/{doc}/pages/{gen}/{页码}.pdf`，删除文档时随前缀一起删除；前端用 react-pdf 渲染，按快照坐标高亮（PPT 不高亮）。
  - Word（`doc`/`docx`）：从当前解析结果取被引用的元素，前后各带 3 个元素，返回 Markdown 片段并标出要高亮的部分。
  - 第四期先支持 PDF 和 Word；其余类型（Excel / CSV、图片、Markdown / TXT / HTML / EPUB / OFD）随知识库第五期开放（17.2）。本卡对不支持的预览类型只返回快照片段（与下面“原文已更新”同路径），并注明类型暂不支持（补充）。
- 人工修改内容、文档已删除或已重新入库：只显示快照中的内容片段，注明“人工修改内容”或“原文已更新”。
- 快照里的 `generation` 与文档当前代不同（已重新入库）时：PDF、PPT 仍按快照页码取页但不高亮；其他类型只显示快照片段。
- 搭建者在调试（P4-11）和日志（P4-12）里查看分块位置，走应用下的接口，按应用“编辑”权限判断，只放行该应用引用的知识库中的文档；搭建者能看整份原文还是只看被引用部分，按搭建者本人对知识库的查看权限决定（有权限返回整份，没有则与终端用户相同）。本卡提供公共预览函数供这两个接口复用。

### 4. 解析服务与固定样例

- 本服务器上解析服务搁置（X02/X06 未恢复），引用预览只用 P3-09 的假解析服务（`backend/tests/fake_parser`）的 PDF、Word 固定样例验证；真实效果待 Docling 接入（2026-10-26 用户确认）。

### 5. 权限与错误码

- 不在使用范围返回 403 `APP_NOT_IN_SCOPE`；未发布 `APP_NOT_PUBLISHED`；已停用 `APP_DISABLED`；下载未开启 `DOWNLOAD_NOT_ALLOWED`；`n` 不在快照或不属于本人回答返回 404（8.3）。错误码以 P4-01 契约为准。

### 和卡片不一致 / 自己补充的地方

1. **他人的会话返回 403**：见“问题”一节；按技术方案 17.3 与验收标准实现，未按卡片 §5 的 404。
2. **`extract_cited` 支持一个括号里写多个编号**（`[1、2]`）：卡片说 `[1、2]` 的前端渲染在 P4-16，但 `cited` 由后端提取；只认 `[n]` 会让“角标渲染了、引用列表却不显示”。实现为在同一括号内取所有数字，`[1]`、`【3】` 行为不变。
3. **`render_preview` 返回 `Response`（JSON 或 PDF 流）**：路由用 `response_class=Response` + `response_model=CitationPreviewOut`，直接返回 Pydantic 模型会被 `Response` 当字符串编码；公共函数内部统一包成 `JSONResponse`，P4-11 / P4-12 可直接复用。
4. **“整份 vs 被引用部分”由 `can_view_whole` + `render_preview(whole_document=...)` 决定**：日志、调试接口在 P4-11 / P4-12，本卡用函数级测试覆盖“协作者有 / 无知识库查看权限”两种结果。
5. **PPT 不在本卡支持范围**：按 17.2 与用户 2026-10-26 决定只支持 PDF、Word；PPT 走“该类型暂不支持预览”的快照片段路径（应用技术方案 8.3 虽提到 PPT，但分期与卡片“不做”都排在第五期）。
6. **PDF 缓存按快照代写入、返回时合并被引用页**：缓存路径按卡片为 `pages/{gen}/{页码}.pdf`（单页），返回时用 pypdfium2 把被引用页合成一份 PDF。
7. **PDF / Word 固定样例**：PDF 用 pypdfium2 生成的多页 PDF 验证页数；Word 用 `backend/tests/fake_parser/fixtures/word` 的固定样例（与 P3-09 一致），不依赖本服务器搁置的真实解析服务。
