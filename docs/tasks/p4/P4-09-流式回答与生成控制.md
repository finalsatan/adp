### 1. 会话与回答存储

### 2. 终端用户接口（结构以 P4-01 契约为准）

终端用户接口不要求控制台权限码，只要求已登录且通过使用范围判断（11、14）；每次提问、读取会话都重新判断（P4-05 提供判断函数）。

| 接口 | 说明 |
| --- | --- |
| `GET /api/v1/chat/apps/{app}/conversations` | 本人会话列表，按 `last_active_at` 排序 |
| `POST /api/v1/chat/apps/{app}/conversations` | 新建会话（不带轮次） |
| `PATCH /api/v1/conversations/{conv}` | 重命名 |
| `DELETE /api/v1/conversations/{conv}` | 软删除 |
| `GET /api/v1/conversations/{conv}/turns` | 按顺序返回每一问和当前显示的回答 |

| `POST /api/v1/turns/{turn}:regenerate` | 重新生成，SSE |

### 3. 提问流程（9.2、6.1）

- 先在一个事务里插入 `chat_turns` 和状态为 `generating` 的 `chat_answers`，再开始流程，刷新页面后能看到这一问（9.2）。
- 取会话生成锁 `conv_gen:{conversation_id}`：60 秒租约、生成期间每 20 秒续约、结束时删除，复用 P2-04 的并发租约脚本（技术方案 v0.1 9.3）。已被占用时返回 409 `CONVERSATION_BUSY`（前端提示“上一个回答还在生成”）。不同会话之间不限制。
- 调 P4-06 的流程函数，按 9.1 发事件：
  - `RUN_STARTED`：`run_id`、`conversation_id`、`turn_id`、`answer_id`（新会话第一问时前端由此拿到会话 ID）。
  - `STEP_STARTED` / `STEP_FINISHED`：步骤名（intent、rewrite、retrieve、rerank、generate、suggest）；终端用户只收到步骤名，详细内容只在调试中给出。
  - `CITATIONS`：本次全部参考内容的编号、类型、来源名、片段（不含位置）。
  - `TEXT_DELTA`；`REASONING_DELTA`（深度思考第六期，本卡不生成）。
  - `TRACE`：只在调试预览中发出（P4-11），本卡不发。
  - `RUN_FINISHED`：回答类型、状态、输入输出 token 数、首字耗时、总耗时。
  - `RUN_ERROR`：错误码和说明（6.5）。
- 回答类型 `kind`：`generated`、`fallback`、`chitchat`（`qa_direct` 第六期，2026-10-26 用户确认）。直接回答和兜底不调用对话模型；兜底用一个 `TEXT_DELTA` 发出整段话术（6.4）。闲聊用回答模型 + 系统提示词 + 固定闲聊要求，带历史、不带参考内容（P4-06 实现，本卡落库与发事件）。
- 事件模型：在 P2-01 的 `app/gateway/events.py`（或 P4-01 已定义的位置）加 `STEP_STARTED`、`STEP_FINISHED`、`CITATIONS`、`SUGGESTIONS`、`TRACE`，并给 `RUN_STARTED` 加 `conversation_id` / `turn_id` / `answer_id`；若 P4-01 已定义则复用，本卡负责发出（9.1）。
- 用量来源 `source="app"`、`source_id=应用 ID`；意图识别、改写、回答各一条（14）。

### 4. 停止与断开（9.2）

- 前端中止 fetch 后，后端检测断开，取消流程任务（gateway 随之取消上游请求、释放并发租约、记 `CANCELLED` 用量）。
- 在 `finally` 中用**独立的数据库会话** + `asyncio.shield` 写入已输出的文字、已有的引用和处理过程，状态记为 `stopped`，写入不被取消打断。
- 进程崩溃时状态停在 `generating`：读取会话时，`generating` 且超过 10 分钟没有更新的回答按“已中断”显示，不做定时任务修正。

### 5. 重新生成（9.2）

- 对同一问再走一遍流程，生成新的 `chat_answers`（`seq` 加 1），把 `chat_turns.current_answer_id` 指向它。
- 对话页只显示最新的回答，旧回答保留在日志中并标注“已重新生成”（P4-12 读取）。
- 只能重新生成会话的最后一问；使用最新发布的版本和当时的历史（这一问之前的轮次）。

### 6. 落库字段（10）

- `chat_answers`：`version_id`、`kind`、`status`（`generating` / `done` / `stopped` / `failed`）、`content`、`reasoning`、`citations`（jsonb，P4-10 生成）、`cited`（int[]）、`suggestions`（第六期，本卡为 null）、`error_code`、`input_tokens`、`output_tokens`、`first_token_ms`、`total_ms`、`updated_at`。
- `answer_traces`：主键 `answer_id`、`app_id`、`trace`（步骤数组，来自 P4-06 的记录器）。
- `cited`：生成结束后从全文提取实际出现过的编号（`[n]` 与全角 `【n】`）存入；没有标任何角标时为空（8.1，P4-10 的引用列表据此显示）。

### 7. 出错与降级（6.5）

- 提问开始时统一检查一次：应用引用的任一模型（回答、意图识别、改写、重排、向量化）已停用 → 返回 `MODEL_UNAVAILABLE`（`RUN_ERROR`，对话页显示“模型不可用”）。
- 回答模型被限流 → `MODEL_RATE_LIMITED`；回答模型报错或超时 → `RUN_ERROR`，已输出的部分保存，状态记为 `failed`。
- 检索失败 → `RETRIEVAL_FAILED`（不回复兜底话术，由 P4-07 抛出）。
