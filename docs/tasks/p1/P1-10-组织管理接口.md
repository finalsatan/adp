# P1-10 组织管理接口

状态：已验收
前置：P1-07
被依赖：P1-11、P1-15

## 目标

实现组织的列表、新建、修改、删除和成员列表。

## 依据

- 需求 10.1、10.3
- 技术方案 6.1（orgs）、7.2（管理范围）、13.2（权限、组织删除、名称）
- 原型 `#v-orgs`、`#d-neworg`、`#d-orgmembers`
- P1-03 组织接口

## 要做

全部接口要求 `org.manage`；写操作的路由依赖第一个放对应的 `audited(...)`。

### 列表 `GET /api/v1/orgs`

- 系统管理员：全部未删除组织；组织管理员：管理范围内的未删除组织（含本组织）。
- 每项返回 `OrgOut`：
  - `admins`：该组织（直属）中角色为组织管理员、状态启用的用户。
  - `user_count`：直属用户数（含停用）；`resource_count`：直属未删除资源数；`child_count`：未删除的直接下级数。用聚合子查询一次查出，不要逐个组织查询。
  - `editable`：系统管理员恒为真；组织管理员对严格下级为真、对本组织为假（需求 10.3：组织管理员在自己的组织下建、改、删下级组织）。
- 按 path 排序，前端据 parent_id 拼树。

### 新建 `POST /api/v1/orgs`

- `parent_id` 为空（顶级组织）：只有系统管理员可以，否则 403 `PERMISSION_DENIED`。
- `parent_id` 不为空：上级必须存在、未删除，且在操作人管理范围内（组织管理员可以在本组织及下级下面建）。
- 名称去掉首尾空格；同一上级下（顶级组织之间）未删除的组织重名 → 409 `NAME_CONFLICT`。
- 先 `SELECT nextval` 取 id，path = 上级 path + id + `/`（顶级为 `/id/`），再插入。
- 审计 `org.create`，对象为新组织（org_id 为新组织自己）。

### 修改 `PATCH /api/v1/orgs/{id}`

- 只能改名称和备注；上级不可修改（请求里带 parent_id 时按校验错误拒绝，契约里本来就没有这个字段）。
- 权限：`editable` 为真才可以，否则 403。
- 重名规则同新建。
- 改名后调用 `bump_perm_version`（缓存的用户上下文里有组织名）。
- 审计 `org.update`，detail 为变化的字段。

### 删除 `DELETE /api/v1/orgs/{id}`

- 权限同修改。
- 前提（需求 10.3）：没有未删除的下级组织；没有任何用户（含停用）以它为所属组织；没有未删除的资源。任一不满足 → 409 `ORG_NOT_EMPTY`，detail 带三个数。
- 软删除（写 deleted_at）。
- 审计 `org.delete`。

### 成员 `GET /api/v1/orgs/{id}/members`

- 组织必须在管理范围内。
- 只列直属该组织的用户（需求 10.3、原型 `#d-orgmembers`），按用户名排序分页。
- `manageable` 用 P1-06 的 `can_manage_account` 计算。

## 验收标准

- [x] 测试（用 `org_tree` 夹具）：
  - 系统管理员能建顶级组织；组织管理员建顶级组织返回 403。
  - 组织管理员能在本组织和下级下面建组织；在同级、上级组织下面建返回 403；改、删本组织返回 403；改、删下级组织成功。
  - 组织管理员的列表只含本组织及下级，`editable` 对本组织为假。
  - 同一上级下重名、两个顶级组织重名返回 409；不同上级下可以同名；删除后可以再建同名的。
  - 有下级、有用户（含停用用户）、有资源时删除返回 409 并带对应数字；都没有时删除成功，列表不再出现。
  - 成员列表只含直属用户；组织不在范围内返回 403。
  - 搭建者调用任一接口返回 403。
  - 新建、修改、删除各产生一条审计；被拒绝的操作产生 failure 审计。
- [x] `make backend-lint backend-test` 通过。

## 注意

- 判断“在管理范围内”一律用 path 前缀，不要递归查询上级。
