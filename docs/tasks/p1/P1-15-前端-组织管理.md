# P1-15 前端：组织管理

状态：待验收
前置：P1-14（复用 `UserEditDrawer` 和 `orgTree.ts`；联调需要 P1-10）
被依赖：P1-19

## 目标

做出组织管理页：组织树表格、新建（顶级或下级）、编辑、删除、成员抽屉。

## 依据

- 需求 10.3
- 原型 `#v-orgs`、`#d-neworg`、`#d-orgmembers`
- 接口：`GET/POST /orgs`、`PATCH/DELETE /orgs/{id}`、`GET /orgs/{id}/members`

## 要做

- 页头：标题“组织管理”、说明“组织为多级树，对应子公司、部门；由管理员手工维护。”；右侧按钮：系统管理员为“新建顶级组织”，组织管理员为“新建下级组织”。
- 提示条照原型：“删除组织的前提：无下级组织、无用户、无资源。不做组织停用。组织管理员由系统管理员或上级组织的组织管理员任命（在用户管理中把用户的角色设为组织管理员）。”
- 表格用 Ant Design Table 的树形数据，默认展开两级。列：组织名称、组织管理员（用户名用顿号连接，无则“—”）、用户数、资源数、下级组织、创建时间、操作。
- 操作（`editable` 为真时）：编辑、添加下级、成员、删除。`editable` 为假的本组织行只显示“添加下级”“成员”。没有用户的组织不显示“成员”（照原型）。
- 新建、编辑抽屉（`#d-neworg`）：上级组织（新建时 TreeSelect 只列出可在其下新建的组织；“添加下级”时预选当前行；编辑时只读）、名称、备注。`NAME_CONFLICT` 显示在名称字段下。
- 删除：Popconfirm 确认；返回 `ORG_NOT_EMPTY` 时弹出提示，写明“还有 N 个下级组织、N 个用户、N 个资源”。
- 成员抽屉（`#d-orgmembers`）：表格列用户（用户名 + 姓名）、角色、状态、操作；操作对 `manageable` 的行显示“编辑”，打开 P1-14 的 `UserEditDrawer`；本人行显示“个人中心”。底部说明照原型。

### 和卡片不一致 / 自己补充的地方

1. 多建了 `orgs/api.ts`（卡片只写了“`orgs/` 下的页面”，未列 api 文件），放在卡片列出的目录内，避免碰 `src/api/` 下别的卡的文件。

4. 编辑时上级组织用只读的 TreeSelect 展示，符合原型“编辑组织时此项只读”。
