# P1-16 前端：审计日志、资源总览

状态：已验收
前置：P1-02、P1-03（联调需要 P1-07、P1-12）
被依赖：P1-19；第三期起的资源页面复用本卡的协作者和可见范围组件

## 目标

做出审计日志页和资源总览页，并做出所有资源共用的“可见范围”弹窗和“协作者”抽屉。

## 依据

- 需求 10.4、10.6、10.7
- 原型 `#v-audit`、`#v-overview`、`#d-collab`
- 接口：`GET /audit-logs`、`GET /audit-logs/meta`、`GET /orgs`、`GET /resources`、`GET /resource-types`、`PATCH /resources/{id}/visibility`、`GET/POST/DELETE /resources/{id}/members`、`:disable`、`:enable`、`DELETE /resources/{id}`、`GET /users:search`

## 要做

### 1. 审计日志 `/system/audit`

- 页头和说明照原型；提示条：“日志只增不改，永久保存。系统管理员可查看全部；组织管理员可查看操作人或对象属于本组织及下级组织的记录……”（原型原文）。
- 筛选：时间范围（RangePicker，默认不限）、操作人关键字、动作（选项来自 meta）、对象类型（meta）、组织（TreeSelect，来自 `GET /orgs`，含下级）、结果。
- 列：时间（`MM-DD HH:mm:ss`）、操作人、操作人组织（为空显示“—（系统管理员）”，补充：照原型）、动作、对象（`target_desc`，有 detail.from/to 时拼成“名称：A → B”）、对象所属组织、结果（成功绿、失败红）、来源 IP。
- 点击一行展开显示 detail 的 JSON（补充，便于查看完整变更）。

### 2. 资源总览 `/system/overview`

- 页头和说明照原型；提示条按身份显示（系统管理员 / 组织管理员两种文案，照原型的写法）。
- 筛选：类型（来自 `/resource-types`，第一期为空，下拉只有“全部类型”）、组织（TreeSelect）、可见范围、创建人（用 `/users:search` 的远程搜索 Select）、关键字。
- 列：名称、类型、所属组织、创建人、可见范围、创建时间、操作。
- 操作：查看、编辑（跳到该类型的详情页，路由由前端的“资源类型 → 详情路径”映射表决定；第一期映射表为空，没有映射的类型不显示这两项）、可见范围、协作者、停用或启用、删除。类型带 `fixed_visibility` 时不显示“可见范围”。
- 第一期没有任何资源，列表显示 Empty“暂无资源。知识库、入库方案、应用上线后会出现在这里。”（补充）。

### 3. 共用组件（放 `frontend/src/components/resource/`，第三期起的资源页面直接复用）

- `VisibilityModal`：单选 仅自己 / 本组织（含下级组织）/ 全平台；保存调用 `PATCH /resources/{id}/visibility`。返回 `RESOURCE_IN_USE` 时在弹窗里列出 `detail.refs`（名称、类型），并说明“这些应用会因此不能再引用它，请先在应用中解除引用”。
- `CollaboratorsDrawer`：列出协作者（用户名、姓名、所属组织、添加人、添加时间、移除按钮），上方“添加协作者”打开 `#d-collab` 样式的弹窗：远程搜索用户（显示“用户名 姓名 · 组织”），提示文字由调用方传入（不同资源类型的说明不同；原型里是知识库的说明）。移除返回 `RESOURCE_IN_USE` 时同样列出引用方。
- 删除、停用用 Popconfirm；删除返回 `RESOURCE_IN_USE` 时列出引用方。

### 和卡片不一致 / 自己补充的地方

1. 卡片“文件”只列了两个页面目录和两个组件、`resourceRoutes.ts`；实际按既有模式补了 `pages/system/audit/api.ts`、`auditFormat.ts`、`pages/system/overview/api.ts`、`components/resource/api.ts`、`api/orgs.ts`（页面与接口 hook 分开，避免页面文件同时导出组件和函数触发 `react-refresh` warning；`api/orgs.ts` 供审计与总览共用 `GET /orgs`）。
2. `detail.from/to` 存的是代码（P1-11 的 `user.change_role` 是 `builder`/`org_admin`，P1-12 的可见范围是 `private`/`org`/`platform`），为对齐原型的“搭建者 → 组织管理员”“本组织 → 全平台”，`formatTarget` 用角色/可见范围/状态的中文名映射，认不出的值原样显示；`from/to` 不是字符串或数字（如 `user.change_org` 若存组织对象）时退回只用 `target_desc`。
3. 审计时间范围用 `RangePicker` 且 `showTime`（原型只显示到日期），因为审计按秒记录、后端接受 ISO 时间；默认不限。
4. 资源总览的提示条：原型只写了系统管理员那一段（末尾提到组织管理员），本卡按原型写法补了组织管理员视角的文案（`当前身份：{组织}的组织管理员，可对本组织及下级组织的资源执行…`）。
5. 总览的“创建人”列显示用户名（照原型“zhangsan”）；“添加人”显示姓名。`RESOURCE_IN_USE` 的引用方类型显示接口返回的代码（如 `app`），没有可用的类型中文名来源（`/resource-types` 第一期为空），第三期资源类型注册后可由调用方传入映射。
6. 删除资源返回 `RESOURCE_IN_USE` 时，在总览页顶部用 `Alert` 列出引用方（`VisibilityModal`/`CollaboratorsDrawer` 在各自弹窗/抽屉里列出）。
