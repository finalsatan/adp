## 目标

做出系统设置页的第一期部分：密码与登录、会话、模型调用。

## 依据

- 需求 10.8
- 原型 `#v-settings`
- 接口：`GET/PATCH /settings`

## 要做

- 页头：标题“系统设置”、说明“文档中所有‘管理员可调’的平台参数集中在这里，只有系统管理员可见；修改写入审计日志。”、右侧“保存”。
- 分组卡片（照原型的字段和提示文字）：
  - 密码与登录：密码最小长度；至少包含的字符类别（提示“大写、小写、数字、符号四类中”）；连续失败锁定次数（提示“按‘用户名 + 来源 IP’计数”）；锁定时长（分钟）。
  - 会话：访问令牌有效期（分钟）；刷新令牌有效期（天）。
  - 模型调用：入库占用模型限额的比例（提示“模型设了限流时才起作用；入库和在线合计不超过模型限额”）；模型接口地址白名单（多行文本，每行一个主机名、IP 或网段；提示“模型接口地址默认不允许指向内网、本机；这里列出的地址和网段除外”）。
- “上传与解析”“解析引擎”两组到第三、六期再加，本期不显示（补充）。
- 数字输入的上下限与 P1-03 的取值范围一致；保存时只提交改动过的字段；后端 422 时把错误显示在对应字段下。
- 有未保存的修改时离开页面弹确认（补充）。

### 和卡片不一致 / 自己补充的地方

1. 卡片“文件”只列了 `SettingsPage.tsx` 及测试；实际按既有模式补了 `frontend/src/api/settings.ts`（接口 hook）和 `settingsForm.ts`（纯函数，避免页面文件同时导出组件和函数触发 `react-refresh` warning）。
2. 入库占用比例：接口字段是 0.1–0.9 的小数，界面照原型显示成百分数（`InputNumber` 的 `formatter`/`parser`），表单值仍是小数；上下限用 P1-03 的 0.1–0.9。
3. 422 错误：按 P1-01 已定的统一结构 `detail.errors[].loc/msg` 映射（去掉 `body` 前缀和列表下标）到字段，用 `Form.Item` 的 `help`/`validateStatus` 显示；映射不到时退化为顶部 Alert。P1-09 未实现，`detail.errors` 的实际形状以 P1-09 为准，若不同需同步这里。
4. 未保存离开确认只做了 `beforeunload`（刷新/关闭弹确认）；应用内路由跳转的确认需要 data router 的 `useBlocker`，当前 `BrowserRouter` 不支持，本卡不改 `router.tsx`/`App.tsx`，故未实现应用内拦截。
5. 测试环境并行负载高时，`make frontend-check` 曾有两个别的卡测试（`ProfilePage`、`ChangePasswordPage`）因默认 5s 超时失败；负载下降后重跑全绿，与本卡改动无关。本卡组件测试显式放宽到 30s。
