## 要做

### 1. 密码 `app/core/security.py`

- 依赖：argon2-cffi、pyjwt。
- `hash_password(plain) -> str`：argon2id（argon2-cffi 的 `PasswordHasher` 默认参数）。
- `verify_password(hash, plain) -> bool`：不匹配返回 False，不抛异常。
- `DUMMY_HASH`：启动时生成的一个固定哈希。用户名不存在时也对它做一次 verify，让耗时与用户存在时一致（补充）。
- `check_password_strength(password, username, min_length, min_classes) -> list[str]`，返回不满足的原因代码（空列表表示通过）：
  - `TOO_SHORT`：长度小于 min_length
  - `TOO_FEW_CLASSES`：大写字母、小写字母、数字、符号四类中少于 min_classes 类
  - `SAME_AS_USERNAME`：去掉首尾空格后不区分大小写地等于用户名
  - `COMMON_PASSWORD`：不区分大小写地出现在弱密码表中
- 弱密码表：`app/core/data/common_passwords.txt`，用 SecLists 的 `Passwords/Common-Credentials/10k-most-common.txt`（MIT 许可，约 1 万条，技术方案 8.1 要求约 1 万条）。文件开头不能加注释行（会被当成密码），在同目录放 `common_passwords.LICENSE` 写明来源和许可证。启动时读一次，存成小写的 frozenset。

### 2. 令牌 `app/core/security.py`

- `create_access_token(user_id, session_id, token_version, must_change_password, ttl_minutes) -> str`：HS256，密钥取 `JWT_SECRET`；载荷只有 `sub`（字符串形式的用户 id）、`sid`、`tv`、`pwc`、`exp`、`jti`（技术方案 8.1，不放角色和权限）。
- `decode_access_token(token, verify_exp=True) -> AccessClaims`：签名错误、格式错误、过期（verify_exp 为 True 时）都抛 `TokenInvalid`。`verify_exp=False` 供登出使用。
- `new_refresh_token() -> tuple[str, str]`：返回（原文，SHA-256 十六进制）。原文用 `secrets.token_urlsafe(32)`。
- `hash_refresh_token(raw) -> str`。
- `JWT_SECRET` 为空或短于 32 字节时，应用启动失败并说明原因（补充）。

### 3. 系统设置服务 `app/settings/service.py`

- 用 Pydantic 定义 `PasswordSettings`、`LoginSettings`、`SessionSettings`、`ModelCallSettings` 和汇总的 `PlatformSettings`，字段、默认值、取值范围照 P1-03 的 `SettingsOut`。白名单的每一项校验为主机名、IP 或 CIDR（用 `ipaddress` 判断 IP 和网段，主机名按 RFC 1123）。
- 存储：settings 表每个分组一行（key 为 `password`、`login`、`session`、`model_call`），value 为该分组的 JSON。库里没有的分组或字段用默认值。
- `async get_settings(session) -> PlatformSettings`：进程内缓存 30 秒（补充：设置很少改，多副本时最多 30 秒不一致）。
- `async update_settings(session, patch: dict, actor_id) -> tuple[PlatformSettings, PlatformSettings]`：按分组合并、校验、写库、清本进程缓存，返回（修改前，修改后）。不在这里写审计（P1-09 在接口层写）。
- 以后新增分组（第三期“上传与解析”、第六期“解析引擎”）只需加一个 Pydantic 类，代码结构要支持这一点。

### 4. 初始化管理员命令 `app/cli.py`

- `python -m app.cli create-admin --username admin`：
  - 默认用 `getpass` 交互输入两次密码；`--password-stdin` 从标准输入读一行（给自动化部署和端到端测试用）。
  - 按当前系统设置的密码策略校验强度，不通过时打印原因并退出码 1。
  - 用户名转小写后已存在时报错退出。
  - 创建 `role=sys_admin`、`org_id=NULL`、`must_change_password=true` 的用户（技术方案 8.1：首次登录强制改密）。
  - 用应用账号的 `DATABASE_URL` 连接。
- 命令逻辑写成可以在测试里直接调用的异步函数，`cli.py` 只负责解析参数。
