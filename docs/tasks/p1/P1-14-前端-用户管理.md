# P1-14 前端：用户管理

状态：已验收
前置：P1-02、P1-03（联调需要 P1-10、P1-11）
被依赖：P1-15（复用编辑用户抽屉）、P1-19

## 目标

做出用户管理页：组织树筛选、用户列表、新建、编辑、重置密码、停用启用、解锁，以及系统管理员的任命和撤销。

## 依据

- 需求 10.1、10.2
- 技术方案 7.2
- 原型 `#v-users`、`#d-newuser`、`#d-edituser`、`#m-resetpw`
- 接口：`GET /orgs`、`GET/POST /users`、`PATCH /users/{id}`、`:disable`、`:enable`、`:reset-password`、`:unlock`、`:grant-sys-admin`、`:revoke-sys-admin`、`GET /auth/policy`、`GET /me`

## 要做

### 1. 页面布局（照原型 `#v-users`）

- 页头：标题“用户管理”、说明、右侧“新建用户”。
- 身份提示条（Alert）：组织管理员显示“当前身份：XX 的组织管理员。可管理 XX 及下级组织的用户；同级、上级组织管理员和系统管理员的账号不能操作，只能把下级组织的用户设为组织管理员。”；系统管理员显示“当前身份：系统管理员，可管理所有用户。”（补充）。
- 左侧组织树（`GET /orgs` 拼树），节点显示组织名和该组织含下级的用户数（前端把各级 `user_count` 累加）。点节点按该组织含下级筛选。
- **系统管理员**看到的树最上面多一个节点“系统管理员”，点它列出 `role=sys_admin` 的用户（需求 10.1：系统管理员单独成组显示；补充：原型没画）。
- 右侧工具条：关键字搜索、角色筛选（全部、组织管理员、搭建者、终端用户）、状态筛选（全部、启用、已停用），右侧显示“XX（含下级）共 N 人”。

### 2. 列表

- 列：用户名（本人加“我”标签）、姓名、所属组织、角色、邮箱、状态、最后登录、操作。
- 状态：启用（绿）、已停用（灰）；`locked` 为真时显示“已锁定”（橙），优先于启用。
- 最后登录用相对时间（今天 09:12、昨天 17:05、10-19 11:03）。
- 操作按 `manageable` 显示：编辑、重置密码、停用或启用；已锁定时最前面加“解锁”。本人那一行只显示“个人中心”链接。`manageable` 为假的其他行不显示操作。
- 系统管理员分组里，每行额外有“撤销系统管理员”（本人行也有，补充）。

### 3. 新建用户抽屉（`#d-newuser`）

- 字段：用户名、姓名、初始密码（提示策略，用 `GET /auth/policy`）、邮箱、手机、所属组织（TreeSelect，只列出 `GET /orgs` 返回的组织，即管理范围内的）、角色（搭建者、终端用户、组织管理员）、备注。
- 角色选“组织管理员”时：操作人是组织管理员的，所选组织必须是严格下级，否则该选项禁用并提示“只能把下级组织（…）的用户设为组织管理员”。
- 后端错误（`USERNAME_EXISTS`、`WEAK_PASSWORD`、`PERMISSION_DENIED`）显示在对应字段或表单顶部。

### 4. 编辑用户抽屉（`#d-edituser`），做成可复用组件 `UserEditDrawer`

- 用户名只读；姓名、邮箱、手机、所属组织、角色、备注可改；规则同新建。
- 改了所属组织时显示提示：“调整所属组织后，{用户名} 在 {原组织} 创建的 {owned_resource_count} 个资源留在 {原组织}，由 {原组织} 的组织管理员管理；{用户名} 不再拥有这些资源的创建人权限，需要时可把他加为协作者。”（数量为 0 时不显示这句）。
- **系统管理员**编辑非系统管理员用户时，角色选项多一个“系统管理员”；选中保存时弹确认框“任命后该用户不再属于任何组织，可管理整个平台”，确认后调用 `:grant-sys-admin`（补充）。
- 编辑系统管理员时不显示所属组织和角色字段。

### 5. 撤销系统管理员弹窗（补充）

选择所属组织（全部组织）和角色（组织管理员、搭建者、终端用户），确认后调用 `:revoke-sys-admin`。返回 `LAST_SYS_ADMIN` 时显示后端文案。

### 6. 重置密码弹窗（`#m-resetpw`）

新密码输入框和策略提示；两段说明文字照原型（“重置后，用户下次登录时必须修改密码。”“已登录的会话不会立即退出：刷新令牌随即作废，访问令牌最迟在到期时失效（默认 15 分钟）。”，分钟数取策略接口）。

### 7. 停用、启用、解锁

停用用 Popconfirm：“停用后账号、资源和审计记录保留；已登录的会话最迟在访问令牌到期时失效。”启用、解锁直接执行，成功后提示并刷新列表。

### 联调结果（2026-10-23，开发库 adp + headless Chromium）

用 API 造了组织「联调科技」(A)、其下级「联调研发部」(B)、无关组织「联调市场部」(C)，以及用户 oa1/oa2（A 的组织管理员）、ob1（B 的组织管理员）、buildera（A 的搭建者）、enda（A 的终端用户）。17 项断言全部通过：

- 组织管理员 oa1：身份提示条为组织管理员文案；组织树含 A、B 及各自含下级的用户数，不含 C；本人行只显示“个人中心”；同级组织管理员 oa2 行无任何操作按钮；下级组织管理员 ob1 行有编辑/重置密码/停用。
- 新建用户抽屉：选本组织 A 时“组织管理员”角色禁用，选下级组织 B 时可选，提示“只能把下级组织（联调研发部）的用户设为组织管理员”。
- 系统管理员 admin：组织树最上面有“系统管理员”分组，点开列出本人并显示“系统管理员共 1 人”；编辑 buildera 时角色多出“系统管理员”，选中保存弹出确认框“任命后该用户不再属于任何组织，可管理整个平台”，确认后 buildera 出现在“系统管理员”分组；随后撤销（指定组织 A、角色搭建者）成功。

联调中发现并修复的前端问题：`UsersPage.tsx` 的组织树用 `defaultExpandAll`，但 `orgs` 是异步到达的，首次渲染（空树）时该属性已失效，导致树默认全部折叠，与原型 `#v-users`（默认展开两级）不符。改为受控 `expandedKeys` + `useEffect` 按树数据展开有下级的节点。修复后重跑 `make frontend-check` 全绿（lint/typecheck/test/build）。
