## 要做

### 1. 端到端环境

- 用开发 Compose 中的 `adp_e2e` 库（P1-01 已建）。`make e2e-prepare`：重建 `adp_e2e`，执行迁移，用 `create-admin --password-stdin` 创建管理员 `admin`（初始密码写在 e2e 配置里，只用于测试）。
- Playwright 放在 `frontend/e2e/`，`playwright.config.ts` 的 `webServer` 同时启动后端（uvicorn，连 `adp_e2e`，`COOKIE_SECURE=false`，Redis 用单独的库号）和前端（`vite preview` 或 dev，带 `/api` 代理）。只跑 Chromium，宽度 1440。
- Makefile 增加 `e2e`（先 `e2e-prepare` 再 `pnpm exec playwright test`）。

### 2. 用例

1. 管理员首次登录 → 跳到改密页 → 改密 → 进入控制台，侧栏有“系统管理”五项。
2. 系统管理员新建顶级组织“集团”和下级“研发中心”“产品中心” → 在研发中心新建一个组织管理员、一个搭建者。
3. 用新建的组织管理员登录 → 首次改密 → 用户管理只看到研发中心及下级 → 看不到“系统设置”菜单 → 直接访问 `/system/settings` 显示 403 页。
4. 搭建者登录 → 首次改密 → 侧栏没有“系统管理”分组 → 个人中心改姓名成功 → 改密码后当前页面仍可操作。
5. 新建一个终端用户 → 登录改密后进入“我的应用”空页面 → 访问 `/system/users` 被带回“我的应用”。
6. 用错误密码连续登录 5 次 → 第 6 次提示“尝试次数过多” → 管理员在用户列表看到“已锁定”并解锁 → 该用户能登录。
7. 审计日志里能查到以上的登录、创建用户、解锁记录。

### 3. 部署文档 `deploy/README.md`

面向客户的实施人员，中文：

- 环境要求：Docker 和 Compose 版本、CPU 内存磁盘的最低配置（第一期按 2 核 4GB 写，标注“以后各期会提高”）。
- 安装步骤：生成密钥（`gen-secrets.sh`）、放置证书、`make prod-up`、创建初始系统管理员、首次登录改密。
- **必须备份的内容**：数据库；`deploy/.env` 中的 `JWT_SECRET`（以及第二期加入的 `MASTER_KEY`：丢失后所有模型密钥无法解密）。
- 备份与恢复：每日 `pg_dump` 的 cron 示例（用超级用户，输出 custom 格式，保留 N 份）；恢复步骤（停 api、`pg_restore`、启动）；恢复后做一次冒烟检查。
- 升级：备份 → 拉取新版本 → `make prod-up`（migrate 先迁移再启动 api）；只支持向前升级，升级说明会写明是否有不可逆的迁移。
- 日志：`docker compose logs`，日志是 JSON，带请求 ID；用户反馈问题时请他提供页面上的请求 ID。
- 健康检查：各服务的 healthcheck；api 的 `/readyz` 怎么在容器内调用。
- 网络：只开放 443（和跳转用的 80）；客户前面有负载均衡时 nginx real_ip 的改法；访问外网需要代理时设置 `HTTPS_PROXY`（第二期调用云模型时用）。
- 常见问题：忘记管理员密码（用 `create-admin` 再建一个系统管理员，或由另一个系统管理员重置）；账号被锁定（管理员解锁或等锁定时长到期）。

### 和卡片不一致 / 本机特殊情况

1. **端口与库**：按本机情况后端用 18000、前端用 14173、Redis 用 12 号库、数据库用 `adp_e2e`（避开别人占用的 8000/5173 和 `adp`、`adp_test`、`adp_test3`）。这些值写在 `frontend/e2e/config.ts` 和 `scripts/e2e-prepare.sh` 的默认值里，两处保持一致。
2. **e2e 用 `.e2e.ts` 后缀**：Vitest 默认会扫 `*.spec.ts`，会去执行 Playwright 用例并报错。把用例命名成 `phase1.e2e.ts`，并在 Playwright 配置里设 `testMatch: "**/*.e2e.ts"`，没有改 `vite.config.ts`。
3. **前端代理**：新增 `frontend/e2e/vite.config.ts` 而不是改开发用的 `vite.config.ts`。
4. **干净目录部署用独立项目名**：`deploy/docker-compose.yml` 里写死 `name: adp-prod`，验证时用 `COMPOSE_PROJECT_NAME=adp-doccheck` 覆盖，得到干净的容器/网络/卷，不动 `adp-prod` 和 `deploy` 两个现有项目。做完已 `down` 清理容器和网络，**留下的卷**：`adp-doccheck_adp_pgdata`（删除卷可能被本机安全检查拦截，故保留；确认无用后可 `docker volume rm adp-doccheck_adp_pgdata`）。
5. **创建管理员**：文档写的是交互式 `make prod-create-admin`；验证时为了自动化，直接在 api 容器里跑 `python -m app.cli create-admin --username admin --password-stdin`，等价。
6. **恢复命令**：文档里用 `pg_restore -U postgres`、不加 `--no-owner`，以保留表的所有者（迁移账号 `adp_migrator`），否则以后 `alembic upgrade` 会因所有权不对失败。
7. **AntD 按钮可访问名**：两个汉字的按钮会插空格（“登 录”“创 建”“保 存”），且按钮 loading 动画结束后 loading 图标的可访问名会残留一小会儿；e2e 用不带首尾锚点的正则匹配。这是测试选择器问题，不是产品缺陷。
