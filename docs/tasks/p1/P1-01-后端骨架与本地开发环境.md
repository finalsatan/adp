建好 `backend/` 项目骨架和本地开发用的 PostgreSQL、Redis。做完后：`make dev-up` 起数据库，`make backend-run` 起服务，`make backend-test` 能连真实数据库跑测试。后面所有后端卡片都在这个骨架上加东西。

## 要做

### 1. Python 项目

- `backend/pyproject.toml`，用 uv 管理，Python 3.12。本卡只加这些依赖：fastapi、uvicorn[standard]、pydantic（v2）、pydantic-settings、sqlalchemy[asyncio]（2.x）、asyncpg、alembic、redis（5.x 以上，用 `redis.asyncio`）。开发依赖：pytest、pytest-asyncio、httpx、ruff。版本由 `uv.lock` 锁定（锁文件带哈希），提交 `uv.lock`。
- ruff 配置：行宽 100，规则 `E,F,I,B,UP`，目标 py312。

### 2. 应用骨架

- `app/main.py`：`create_app(settings: Settings | None = None) -> FastAPI`，模块级 `app = create_app()`。OpenAPI 地址 `/api/v1/openapi.json`；`APP_ENV` 不是 `prod` 时开 `/api/v1/docs`（补充）。
- `app/core/config.py`：pydantic-settings 的 `Settings`，读环境变量和 `backend/.env`。字段：`APP_ENV`（dev / test / prod，默认 dev）、`DATABASE_URL`（应用账号）、`MIGRATION_DATABASE_URL`（迁移账号）、`REDIS_URL`、`JWT_SECRET`、`COOKIE_SECURE`（默认 true）、`LOG_LEVEL`（默认 INFO）。提供 `backend/.env.example`（指向第 4 步的开发数据库），`backend/.env` 不提交。
- `app/core/db.py`：异步引擎和 `async_sessionmaker`；FastAPI 依赖 `get_session()`，每个请求一个 `AsyncSession`；声明式基类 `Base`，带约束命名规则（`ix_%(column_0_label)s`、`uq_%(table_name)s_%(column_0_name)s` 等常见写法）。
- `app/core/tables_index.py`：集中 import 各模块的 `tables.py`，让 Alembic 能看到所有表。本卡里是空的，后续卡片新增模块时在这里加一行。
- `app/core/redis.py`：创建 `redis.asyncio.Redis` 客户端（`decode_responses=True`），FastAPI 依赖 `get_redis()`。
- `app/core/errors.py`：
  - `class AppError(Exception)`，属性 `status`、`code`、`message`、`detail`。具体错误码由 P1-03 补全，本卡先定义 `VALIDATION_ERROR`(422)、`NOT_FOUND`(404)、`NOT_IMPLEMENTED`(501)、`INTERNAL_ERROR`(500)。
  - 注册异常处理：`AppError` → 对应状态码；`RequestValidationError` → 422 `VALIDATION_ERROR`，`detail.errors` 放 Pydantic 的错误列表；Starlette 的 `HTTPException`（如路由不存在的 404）→ 转成统一格式；`NotImplementedError` → 501 `NOT_IMPLEMENTED`；其他异常 → 500 `INTERNAL_ERROR`，记 ERROR 日志并带堆栈，返回里不带堆栈。
  - 统一返回格式：`{"code": "...", "message": "中文说明", "detail": {...} 或 null, "request_id": "..."}`。
- `app/core/middleware.py`：请求 ID 中间件。沿用请求头 `X-Request-Id`（只接受 1–64 位的字母、数字、`-`），否则生成 uuid4 hex；放进 contextvar；写到响应头 `X-Request-Id`。**用纯 ASGI 中间件写，不要用 `BaseHTTPMiddleware`**：后者会影响流式响应和客户端断开时的取消（第二期的 SSE 要用）。
- `app/core/logging.py`：标准库 logging 输出单行 JSON 到标准输出，字段：`time`、`level`、`logger`、`message`、`request_id`、`user_id`（contextvar，本卡始终为空，P1-06 填）、以及调用方传入的额外字段。每个请求结束写一条访问日志：方法、路径、状态码、耗时毫秒。
- 健康检查（不在 `/api/v1` 下）：
  - `GET /healthz` → `{"status": "ok"}`，不连任何依赖。
  - `GET /readyz` → 执行 `SELECT 1` 和 Redis `PING`，都成功返回 200 `{"status": "ok", "checks": {"postgres": "ok", "redis": "ok"}}`；任一失败返回 503，失败项写错误类型（不写连接串）。每项检查超时 2 秒（补充）。
- `app/cli.py`：用标准库 argparse，`python -m app.cli <子命令>`。本卡实现 `export-openapi`：把 `create_app().openapi()` 以排序后的 JSON（`sort_keys=True, indent=2, ensure_ascii=False`）写到标准输出。后续卡片会加 `create-admin` 等子命令。

### 3. Alembic

- `backend/migrations/`，用 async 模板（`alembic init -t async`），`env.py` 读 `MIGRATION_DATABASE_URL`，`target_metadata = Base.metadata`，并 import `app.core.tables_index`。
- 本卡不建业务表（P1-04 建），但要能执行 `alembic upgrade head`（没有迁移时什么也不做）。

### 4. 本地开发用的数据库和 Redis

- `deploy/docker-compose.dev.yml`：
  - `postgres`：镜像 `paradedb/paradedb:0.26.x-pg16`。**到 Docker Hub 查 0.26 系列最新的补丁版本，写死完整 tag**；查不到 0.26 系列时停下来报告。宿主机端口 `55432`（补充：避开本机可能已有的 5432），数据放命名卷。超级用户 `postgres`，开发密码写在 compose 里即可（只用于本地）。
  - `redis`：`redis:7` 的具体补丁版本，宿主机端口 `56379`（补充）。
  - 都配 healthcheck。
- `deploy/postgres/init/10-adp.sh`（挂到 `/docker-entrypoint-initdb.d/`，容器首次初始化时执行）：
  - 创建两个角色（不存在时）：迁移账号 `adp_migrator`、应用账号 `adp_app`，密码取环境变量 `ADP_MIGRATOR_PASSWORD`、`ADP_APP_PASSWORD`。
  - 对环境变量 `ADP_DATABASES`（空格分隔，开发环境为 `adp adp_test adp_e2e`，生产只有 `adp`）中的每个库：
    - `CREATE DATABASE <db> OWNER adp_migrator`
    - 在该库中：`CREATE EXTENSION IF NOT EXISTS vector`、`CREATE EXTENSION IF NOT EXISTS pg_search`（ParadeDB 镜像可能已在默认库建过，所以都用 IF NOT EXISTS）
    - `CREATE SCHEMA IF NOT EXISTS kb_index AUTHORIZATION adp_migrator`，`GRANT USAGE, CREATE ON SCHEMA kb_index TO adp_app`（知识库上线后，应用账号在这里建每个知识库的索引表）
    - `GRANT CONNECT ON DATABASE <db> TO adp_app`；`GRANT USAGE ON SCHEMA public TO adp_app`
    - `ALTER DEFAULT PRIVILEGES FOR ROLE adp_migrator IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO adp_app`
    - `ALTER DEFAULT PRIVILEGES FOR ROLE adp_migrator IN SCHEMA public GRANT USAGE, SELECT ON SEQUENCES TO adp_app`
  - 支持手动调用 `10-adp.sh reset <db>`：删除并重建一个库，再执行上面的建库步骤。供 `make test-db-reset` 使用。
- 应用账号**不能**在 public 里建表（迁移账号是库的所有者，public 归它）。审计表收回 UPDATE、DELETE 的事在 P1-04 的迁移里做。

### 5. 测试夹具（`backend/tests/conftest.py`）

- 测试用的连接串取环境变量 `TEST_DATABASE_URL`（应用账号连 `adp_test`）、`TEST_MIGRATION_DATABASE_URL`（迁移账号连 `adp_test`）、`TEST_REDIS_URL`（Redis 的 15 号库），没设时默认指向第 4 步的开发容器。
- 会话开始时用迁移账号对 `adp_test` 执行 `alembic upgrade head`。
- 每个测试结束后：用迁移账号 `TRUNCATE` public 下除 `alembic_version` 外的全部表（`RESTART IDENTITY CASCADE`），并对测试 Redis 执行 `FLUSHDB`。
- 夹具：`settings`（测试配置）、`app`（用测试配置 `create_app`）、`client`（`httpx.AsyncClient` + `ASGITransport`，base_url `http://test`）、`session`（应用账号的 `AsyncSession`）、`redis`。
- pytest-asyncio 设为 auto 模式，并让 fixture 和测试共用 session 级事件循环（按所装版本的文档配置 loop scope）。否则异步引擎跨事件循环会报 “attached to a different loop”。

### 和卡片不一致 / 需要说明

1. 未捕获异常由最外层 `ServerErrorMiddleware` 处理，此时请求 ID 中间件的 contextvar 已经 reset，且这个响应不经过该中间件（所以中间件补不上 `X-Request-Id`）。因此 `error_response` 改为优先从 `request.state.request_id` 取值，并在错误响应上显式写 `X-Request-Id` 头，保证 body 里的 `request_id` 与响应头一致。
2. Makefile 里 `backend-run`、`migrate`、`backend-openapi` 依赖 `backend/.env`；`.env` 不存在时从 `.env.example` 复制一份。因为 `Settings` 要求 `DATABASE_URL`、`REDIS_URL`，而卡片要求 `.env` 不提交。
3. `.env.example` 里 `COOKIE_SECURE=false`（本地开发走 http）；`Settings` 的默认值仍是 `true`。
4. 初始化脚本里建/改角色的 SQL 用 psql 变量 + heredoc：`psql -c` 不做变量替换，`:'pw'` 会原样发给服务端报语法错。
5. 新增 `app/core/health.py`（健康检查路由）和 `app/core/context.py`（request_id / user_id 的 contextvar），都在卡片允许的 `app/core/*.py` 范围内。
6. 加了 `backend/migrations/versions/.gitkeep`：空目录 git 不跟踪，保留目录供 `alembic revision` 使用。
7. 初始化脚本只在数据卷为空时执行。本次调试中改过脚本，执行了 `docker compose -f deploy/docker-compose.dev.yml down -v` 删掉数据卷再 `make dev-up`；后续再改脚本也要这样做。
8. 本机当前 shell 不在 `docker` 组里，跑 docker 相关目标用了 `sg docker -c "make dev-up"` 这类方式；Makefile 本身仍直接调用 `docker`。
