# P1-06 请求上下文、权限码与“我的信息”

## 目标

实现每个接口都要用的请求上下文（当前用户是谁、什么角色、属于哪个组织）、权限码判断、管理范围判断，以及 `GET /api/v1/me`。同时提供测试用的造数据工具，后面各卡都用它。

## 要做

### 1. 请求上下文 `app/iam/context.py`

`Ctx`（不可变 dataclass）：`user_id`、`username`、`name`、`role`、`status`、`org_id`、`org_path`、`org_name`、`perms: frozenset[str]`、`session_id`、`pwc: bool`、`ip`、`request_id`。

加载步骤（实现 P1-03 的占位依赖 `current_ctx`）：

1. 读 Cookie `adp_at`，没有 → 401 `AUTH_REQUIRED`。
2. `decode_access_token`，失败或过期 → 401 `AUTH_REQUIRED`。
3. 从 Redis 读全局计数 `perm_version`（不存在按 0），读缓存 `user_ctx:{user_id}:{perm_version}`；没有缓存就查 users 联 orgs，写入缓存，有效期 600 秒（技术方案 7.2）。
4. 用户不存在或已停用 → 401 `AUTH_REQUIRED`（停用立即生效，技术方案 15）。
5. 权限码由角色查 `permissions.py` 得出，不入缓存也可以。
6. `pwc` 取自令牌：为 true 时，除“允许待改密”的接口外一律 403 `PASSWORD_CHANGE_REQUIRED`。做法：提供两个依赖 `current_ctx`（拒绝待改密）和 `current_ctx_allow_pwc`；P1-03 标了“允许待改密”的接口（`GET /me`、`/auth/change-password`、`/auth/policy`、`/auth/logout`）用后者。
7. 把 ctx 放到 `request.state.ctx`（审计要用），把 user_id 放进日志 contextvar。

- `ip`：取请求头 `X-Real-IP`（由 nginx 用 `$remote_addr` 覆盖），没有时用 `request.client.host`。**不读 `X-Forwarded-For`**（技术方案 8.1）。
- `bump_perm_version(redis)`：`INCR perm_version`。用户的角色、所属组织、状态变更，组织改名，都要调用它（由 P1-10、P1-11 调用），让所有人的缓存立即失效。

### 2. 权限依赖 `app/iam/deps.py`

- `require_perm(code)`：返回一个依赖，先取 `current_ctx`，没有该权限码 → 403 `PERMISSION_DENIED`；通过时返回 ctx，路由可以直接拿来用。
- 实现 P1-03 留下的占位，不改接口签名。

### 3. 管理范围 `app/iam/scope.py`

技术方案 7.2：

- `in_scope(ctx, org_path) -> bool`：系统管理员恒为真；组织管理员为 `org_path.startswith(ctx.org_path)`；其他角色为假。
- `strictly_below(ctx, org_path) -> bool`：组织管理员为 `org_path.startswith(ctx.org_path) and org_path != ctx.org_path`；系统管理员恒为真。
- `scope_org_ids_sql(ctx)`：返回“管理范围内的组织 id”的 SQLAlchemy 子查询（`orgs.path LIKE ctx.org_path || '%'`），给列表查询拼 WHERE 用；系统管理员返回 None 表示不加条件。**包含已软删除的组织**（审计和用量查询要用）。
- `can_manage_account(ctx, target_role, target_org_path, target_user_id) -> bool`（防止接管账号）：
  - 目标是自己 → 假（自己的资料走个人中心，补充）
  - 操作人是系统管理员 → 真
  - 操作人是组织管理员：目标是系统管理员 → 假；目标组织不在管理范围 → 假；目标是组织管理员且组织不严格在操作人组织之下 → 假；否则真
  - 其他角色 → 假

### 4. 接口

`GET /api/v1/me`（允许待改密）：返回 `MeOut`，`permissions` 为排好序的权限码列表，`must_change_password` 取令牌中的 pwc。`PATCH /api/v1/me` 不在本卡（P1-11 做，要写审计）。

### 5. 测试工具 `backend/tests/factories.py`

- `make_org(session, name, parent=None) -> Org`：按 P1-04 的方式生成 path。
- `make_user(session, role, org=None, username=None, password="Test@1234x", status="active", must_change_password=False) -> User`。
- `auth_cookies(user, pwc=False) -> dict`：直接用 `create_access_token` 签发访问令牌，返回可传给 httpx 的 cookies。
- 一个夹具 `org_tree`：建一棵常用的树，如“集团 → 研发中心 →（平台组、算法组）”和“集团 → 产品中心”，返回各节点。
