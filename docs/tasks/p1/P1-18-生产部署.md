# P1-18 生产部署：Compose、nginx、镜像

状态：待开始
前置：P1-02、P1-08
被依赖：P1-19

## 目标

一条命令在单机上用 Docker Compose 启动完整的第一期平台：nginx、api、一次性的 migrate、postgres（ParadeDB）、redis，通过 HTTPS 访问。

## 依据

- 技术方案 4、8.1（X-Real-IP、Cookie 同域）、9.6（SSE 关闭代理缓冲）、12（部署，**逐条照做**）
- 知识库技术方案 18 的 postgres 一行

## 要做

### 1. 镜像

- `backend/Dockerfile`：基于 `python:3.12-slim`（锁具体版本），用 uv 按 `uv.lock` 安装（`uv sync --frozen --no-dev`），非 root 用户运行；默认命令 `uvicorn app.main:app --host 0.0.0.0 --port 8000 --no-proxy-headers`（来源 IP 只由 nginx 写入的 X-Real-IP 决定，见 P1-06，不让 uvicorn 解析 X-Forwarded-For）。同一镜像也用于 migrate（命令为 `alembic upgrade head`）和运维命令。
- `deploy/nginx/Dockerfile`：多阶段构建，第一阶段用 Node（锁版本）+ pnpm 构建 `frontend/`，第二阶段 `nginx`（锁版本）拷入 `dist/` 和配置。

### 2. nginx 配置 `deploy/nginx/nginx.conf`

- 80 端口只做跳转到 443；443 用挂载进来的证书（`deploy/certs/server.crt`、`server.key`，客户提供，技术方案 12）。
- `/`：静态文件，前端路由用 `try_files $uri /index.html`；带哈希的静态资源长缓存，`index.html` 不缓存。
- `/api/`：转发到 `api:8000`；`proxy_set_header X-Real-IP $remote_addr`（**覆盖**客户端传来的值）；`proxy_set_header X-Request-Id $request_id`；清掉客户端传来的 `X-Forwarded-For`（不转发）；`proxy_read_timeout 60s`。
- SSE：后端的 SSE 响应会带 `X-Accel-Buffering: no` 头（第二期 P2-07 实现），nginx 据此对这类响应关闭缓冲，效果等同技术方案 9.6 的 `proxy_buffering off`，以后新增 SSE 接口不用改 nginx（补充）。本卡确认没有关闭 nginx 对该响应头的处理（`proxy_ignore_headers` 里不要含 `X-Accel-Buffering`）。
- 不对外暴露 `/healthz`、`/readyz`（只在容器网络内使用）。
- 加安全响应头：`X-Content-Type-Options: nosniff`、`Referrer-Policy: same-origin`、`X-Frame-Options: DENY`（补充）。
- 客户前面还有负载均衡时用 real_ip 模块只信任该负载均衡的地址：在配置里留注释说明怎么改，默认不开。

### 3. Compose `deploy/docker-compose.yml`

- 服务：`nginx`（发布 80、443）、`api`、`migrate`（执行完退出）、`postgres`、`redis`。只有 nginx 对外发布端口。
- postgres：与 P1-01 开发环境相同的 ParadeDB 镜像 tag；挂 `deploy/postgres/init/`；`ADP_DATABASES=adp`；数据目录用命名卷。
- 依赖：`migrate` 等 postgres healthy；`api` 等 `migrate` `service_completed_successfully` 和 redis healthy；`nginx` 等 api healthy（技术方案 12）。
- healthcheck：api 用 `/readyz`；postgres 用 `pg_isready`；redis 用 `redis-cli ping`。
- `restart: unless-stopped`（migrate 除外）。
- 日志走 Docker 默认驱动，服务只写标准输出。
- 环境变量从 `deploy/.env` 读。

### 4. `deploy/.env.example`

逐项注释：`POSTGRES_PASSWORD`（超级用户）、`ADP_MIGRATOR_PASSWORD`、`ADP_APP_PASSWORD`、`DATABASE_URL`（应用账号）、`MIGRATION_DATABASE_URL`（迁移账号，只给 migrate）、`REDIS_URL`、`JWT_SECRET`（必须随机生成并备份）、`COOKIE_SECURE=true`、`APP_ENV=prod`、`HTTPS_PROXY`（可选，第二期访问云模型用）。第二期会加 `MASTER_KEY`。

### 5. 脚本

- `deploy/gen-secrets.sh`：生成随机的数据库密码和 `JWT_SECRET`，写出一份 `.env`（已存在时拒绝覆盖）。
- `deploy/gen-dev-cert.sh`：生成本机测试用的自签名证书到 `deploy/certs/`。
- `deploy/smoke.sh`：部署后的冒烟检查（见验收）。
- Makefile 增加 `prod-up`（`docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build`）、`prod-down`、`prod-smoke`、`prod-create-admin`（在 api 容器里执行 `python -m app.cli create-admin`）。

## 验收标准

- [ ] 在干净环境：`deploy/gen-secrets.sh && deploy/gen-dev-cert.sh && make prod-up` 后所有服务 healthy，migrate 退出码 0。
- [ ] `make prod-create-admin` 能交互创建管理员。
- [ ] `deploy/smoke.sh` 通过，它检查：`https://localhost/` 返回 HTML；`/api/v1/openapi.json` 返回 200；用错误密码 `POST /api/v1/auth/login` 返回 401 JSON 且响应头有 `X-Request-Id`；带伪造 `X-Real-IP: 1.2.3.4` 连续失败 5 次后，换一个伪造值仍然是锁定状态（证明 nginx 覆盖了该头）；`http://localhost/` 跳转到 https。
- [ ] 应用账号连接数据库（进 postgres 容器用 `adp_app` 执行 `UPDATE audit_logs SET result='x'`）报权限错误。
- [ ] 镜像里没有 `.env`、`node_modules` 源目录、测试文件（检查 `.dockerignore`）。
- [ ] `make backend-lint backend-test frontend-check` 仍然通过。

## 注意

- 用户名锁定是按 IP 计的，所以 nginx 一定要用 `$remote_addr` 覆盖 `X-Real-IP`，这一条有冒烟检查。
