# P1-09 系统设置接口

状态：待开始
前置：P1-07
被依赖：P1-17

## 目标

实现 `GET/PATCH /api/v1/settings`，只有系统管理员能用，修改写审计。

## 依据

- 需求 10.8
- 技术方案 6.1（settings 表）
- 原型 `#v-settings`
- P1-03 的 `SettingsOut`、`SettingsPatch`；P1-05 的设置服务

## 要做

- 两个接口都要求 `settings.manage`。
- `GET`：返回 `get_settings()` 的结果。
- `PATCH`：
  - 路由依赖第一个放 `audited("settings.update")`。
  - 调用 `update_settings`，校验失败返回 422 `VALIDATION_ERROR`（`detail.errors` 指出哪一项）。
  - 成功后写审计 success：对象类型 `settings`，desc“系统设置”，org 为空；detail 为 `{"changes": {"login.lock_threshold": [5, 6], ...}}`，只列真正变化的字段（补充）。没有任何变化时也返回 200，但不写审计（补充）。
  - 返回修改后的完整设置。

## 文件

- 修改：`backend/app/settings/router.py`

## 不做

- 上传与解析、解析引擎两组设置（第三、六期）。

## 验收标准

- [ ] 测试：组织管理员、搭建者、终端用户调用 GET 和 PATCH 都返回 403，且 PATCH 被拒时有一条 failure 审计；系统管理员 GET 返回全部默认值；PATCH 只改一个字段时其他字段不变；超出范围返回 422；成功后审计 detail 中只含变化的字段；修改 `login.lock_threshold` 后登录锁定次数随之改变（与 P1-08 的接口联测一次）。
- [ ] `make backend-lint backend-test` 通过。
