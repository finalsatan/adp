# X12 解析实测在镜像内运行

状态：待开始
前置：X10、X11
被依赖：人工实测 H2

## 目标

`make parser-bench-docker` 在 parser 镜像里跑 X10 的实测脚本，宿主机不用装 LibreOffice 和 Docling 模型；doc、ppt、xls 的转换也能实测，耗时和内存是 Linux 容器里的数字。

## 依据

- X10 卡（脚本参数与输出）、X10 完成记录（本机缺 LibreOffice，旧格式转换报 `CONVERT_FAILED`）
- X02 卡（镜像内的 LibreOffice、unoserver）
- 决定（2026-10-27 用户确认）：实测改为在镜像内运行。

## 要做

1. 根目录 Makefile 加 `parser-bench-docker`：用 `adp-parser:test` 镜像（`--target test`，和 `parser-test-docker` 同一个镜像），把 `parser/bench` 和输入、输出目录挂进容器运行 `bench/run.py`。参数通过环境变量传：`PARSER_BENCH_INPUT`（宿主机输入目录，只读挂载）、`PARSER_BENCH_OUT`（宿主机输出目录）、`PARSER_BENCH_ENGINES`、`PARSER_BENCH_REPEAT`。输出文件属主是宿主机当前用户能读写的（必要时 `--user`）。
2. 只选本地引擎时用 `--network none`；选了 `mineru-*` 时允许容器访问宿主机上的 mineru 服务（Docker Desktop 用 `host.docker.internal`，Linux 用 `--add-host host.docker.internal:host-gateway`），`MINERU_URL`、`MINERU_API_KEY` 可通过环境变量覆盖，默认对应 `parser/compose.dev.yml` 的 mineru 服务。
3. 容器内的内存峰值仍按 X10 的方式（`RUSAGE_CHILDREN`）记录；在 `parser/bench/README.md` 写明镜像内运行的用法，以及“宿主机运行”和“镜像内运行”的区别。
4. 只在镜像内跑不通时才改 `run.py`（例如路径、转换器启动），改动最小。

## 文件

- 修改：根目录 `Makefile`、`parser/bench/README.md`；只在第 4 条需要时改 `parser/bench/run.py`
