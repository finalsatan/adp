# X14 远程引擎不占解析子进程

状态：待开始
前置：X01、X08
被依赖：—

## 目标

MinerU 这类远程引擎的作业在解析服务主进程里执行，等待 MinerU 结果期间不占用 Docling 等本地引擎的子进程；超时、取消、队列限制照常生效。

## 依据

- 知识库技术方案 6.3（“解析服务等待它时不占 Docling 进程”）
- X08 卡“要做”中的对应条目、“问题”5 及其决定
- X01 卡（进程池、runner、作业超时与取消）

## 要做

1. 引擎声明自己是远程引擎（如 `Engine` 协议加可选属性 `remote = True`，MinerU 引擎设为 True）。
2. runner 对远程引擎走单独路径：在主进程中执行（同步的 httpx 客户端放进线程，如 `asyncio.to_thread`，或改成异步客户端，选改动小的），不经过进程池；进度回调、结果的统一后处理、对象存储读写和本地引擎完全一样。
3. 并发上限：远程作业同时执行数用环境变量 `PARSER_REMOTE_CONCURRENCY` 限制（默认 4，补充），超出的排队；作业队列满时的 429 规则与本地作业一致。
4. 超时与取消：作业超时、取消时停止等待（轮询循环要能被打断），作业标为 `TIMEOUT` / `CANCELLED`；已提交给 MinerU 的任务不要求远端取消（MinerU V1 没有取消接口时在完成记录说明）。
5. 主进程里执行远程引擎前要先 `bootstrap()` 过注册表（确认主进程能拿到 MinerU 引擎实例）。

## 文件

- 修改：`parser/app/runner.py`、`parser/app/pool.py`（如需要）、`parser/app/engines/base.py`、`parser/app/engines/mineru/engine.py`、`parser/app/config.py`（新环境变量）、相关测试

## 不做

- 不改 MinerU 的 V1 客户端协议和 middle_json 转换（X08）。
- 不改本地引擎的执行方式。

## 验收标准

- [ ] 测试：`PARSER_WORKERS=1` 时，一个 MinerU 作业正在等待假 MinerU 服务（故意延迟）期间，提交的本地引擎作业（如 builtin 的 txt）能立即开始并完成。
- [ ] 测试：MinerU 作业超时、取消后状态正确，后续作业不受影响；假服务记录的轮询在超时/取消后停止。
- [ ] 测试：超过 `PARSER_REMOTE_CONCURRENCY` 的远程作业排队，不并发执行。
- [ ] X08 原有的测试（含 `test_mineru_api.py` 端到端）全部通过。
