# X15 单文件过大错误码

状态：待验收
前置：X08
被依赖：—

## 目标

文件超过 MinerU 单文件上限时返回专门的错误码 `FILE_TOO_LARGE`，不再借用压缩炸弹的 `ARCHIVE_TOO_LARGE`。

## 依据

- 知识库技术方案 6.2（MinerU 单文件上限 200 MiB）
- X08 卡“问题”6 及其决定

## 要做

1. `parser/app/errors.py` 新增 `FILE_TOO_LARGE`，说明“文件超过解析引擎的大小上限”（补充）。
2. MinerU 客户端的 200 MiB 检查改用 `FILE_TOO_LARGE`，具体说明保持“文件超过 MinerU 单文件上限 200 MiB”。
3. 后端把解析服务的错误码当作“非临时错误”处理（`backend/app/kb/pipeline.py` 的 `TEMPORARY_PARSE_CODES` 不含它），确认不需要改；后端的假解析服务（`backend/tests/fake_parser/`）如有错误码清单，同步加上。

## 文件

- 修改：`parser/app/errors.py`、`parser/app/engines/mineru/client.py`、相关测试；`backend/tests/fake_parser/server.py`（仅在有错误码清单时）

## 不做

- 不改平台上传接口的大小限制（P3-07）。

## 验收标准

- [ ] 测试：超过 200 MiB 的文件（用稀疏文件或打补丁的上限，不真的写 200MB）经 MinerU 引擎返回 `FILE_TOO_LARGE` 和对应说明。
- [ ] `make parser-lint parser-test` 通过；改了后端时 `make backend-lint backend-test` 通过。

## 问题

1. **本卡和代码无关的环境问题（记录备查，不是代码缺陷）**：第一次跑 `make backend-test` 时以退出码 4（pytest 收集错误）失败，
   原因是本工作区没有 `backend/.env`，`app/core/config.py` 在导入 `app.main` 时就校验 `DATABASE_URL`、`REDIS_URL`、
   `JWT_SECRET`、`MASTER_KEY`，四个字段全缺失，conftest 因此加载失败。证据：把 `.env` 移走后
   `cd backend && uv run pytest --collect-only -q; echo $?` 输出 `exit=4`，末行为 `MASTER_KEY ... 请在环境变量或 backend/.env 中设置`。
   按 Makefile 从示例生成 `backend/.env`（`cp backend/.env.example backend/.env`），并把 `deploy/docker-compose.dev.yml` 的
   postgres、redis 起到约定的 55432、56379（`make backend-test` 不会自动依赖 `backend/.env` 这个 target，容易踩到）。
   另：`tests/conftest.py` 的 `TEST_*` 默认值写死 55432 / 56379，测试库必须监听这两个端口，不能靠 `backend/.env` 改端口。
   与 X15 的代码改动无关，没有为此改任何测试。
