# X04 引擎：内置文本与表格解析

状态：待开始
前置：X03
被依赖：X10

## 目标

实现 `builtin` 引擎中 TXT、CSV、TSV、Excel 的部分（Markdown、HTML 的部分用 Docling 的解析器，在 X06 实现）。

## 依据

- 知识库技术方案 6.2 的“内置表格解析”“内置文本解析”两行、7（Excel、CSV 的表格元素保留工作表名和原始行号）、13（Excel、CSV 的定位：工作表和行范围）
- 需求 4.1.4 的“表格”一条、4.1.8 的 Excel、CSV 一行

## 要做

### 1. TXT

- 用 charset-normalizer 识别编码（覆盖 UTF-8、UTF-8 BOM、GBK、GB18030），按空行分段，每段一个段落元素。没有页码。

### 2. CSV、TSV

- 编码识别同上；csv 用逗号、tsv 用制表符（csv 文件实际是分号分隔时，用 `csv.Sniffer` 判断，补充）。
- 按表格设置的 `header_row`（默认 1）取表头，其上的行丢弃。整个文件一个表格元素。

### 3. Excel（xlsx；xls、ods 由 worker 先转成 xlsx，X02）

- pandas + openpyxl 读取；`sheets` 为 `all` 或工作表名列表（需求 4.1.4：默认全部）。
- 每个工作表一个表格元素；按 `header_row` 取表头。
- 合并单元格：值向下填充（知识库技术方案 6.2）。横向合并的单元格在表格结构里保留为跨列单元格（补充）。
- 隐藏的工作表默认也处理（补充：文档没提，按“全部”理解），在完成记录里提一句。
- 公式单元格取计算后的值（openpyxl `data_only=True`）；没有缓存值的公式取空（补充）。

### 4. 位置信息（关键）

知识库技术方案 7 要求表格元素保留工作表名和原始行号，13 节要求引用定位到“工作表 + 行范围”。约定（补充，先读 Docling 自带 Excel 解析器的源码确认它的做法，能沿用就沿用）：

- 每个工作表一页：`page_no` = 工作表序号（从 1 开始），页面上记录工作表名。
- 表格的每个数据行能还原出原始的 Excel 行号：**不删除表格中间的空行**；如果实现上必须删除，就另存一份“表格行 → 原始行号”的映射，放在 DoclingDocument 允许的扩展位置。
- 具体存放位置写进完成记录，第三期的分块代码要按它取行号。

### 5. 引擎注册

`builtin` 引擎在本卡支持 `txt`、`csv`、`excel`；`markdown`、`html` 在 X06 加上后才算完整。`availability()` 恒为可用。
