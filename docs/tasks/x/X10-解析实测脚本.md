# X10 解析实测脚本

状态：已验收
前置：X04–X08
被依赖：人工实测 H2

## 目标

写一个批量对比脚本：对一批样例文件分别用多个引擎解析，记录耗时、内存、结构统计，并生成一份便于人工逐份对比的报告。实测和评判由人来做（H2），本卡只提供工具。

## 依据

- 知识库技术方案 19.1（解析和检索实测的内容）
- `docs/research/WeKnora-docreader评估.html` 第 6 节（对比维度：标题层级、表格结构、阅读顺序、耗时）

## 要做

`parser/bench/run.py`：

- 参数：`--input <目录>`（递归找支持的文件）、`--engines`（如 `docling,docling-force,pypdfium,markitdown,mineru-flash,mineru-basic,builtin`，带档位或扫描页模式的写成变体名）、`--out <目录>`、`--repeat N`（测耗时取中位数，默认 1）。
- 本地引擎（docling、pypdfium、markitdown、builtin）：每个“文件 × 引擎”在一个新的子进程里调用与作业相同的执行代码（X01 的 runner，不经过 HTTP），记录墙钟耗时和子进程内存峰值（`resource.getrusage(RUSAGE_CHILDREN).ru_maxrss`）。首次加载模型的耗时单独记录，不算进每个文件的耗时（补充）。
- MinerU：通过 mineru 服务的接口调用（X08 的客户端），只记耗时，内存在报告里注明“见 mineru 容器”。
- 旧格式（doc、ppt、xls）对 Docling、MarkItDown、内置表格解析先走 X02 的转换，转换耗时单独一列。
- 每次结果记录：文件、类型、引擎、成功与否、错误码、页数、OCR 页数、耗时、内存峰值、各级标题数、表格数、图片数、文字字数。
- 输出：
  - `results.csv`：上面每条一行。
  - 每个“文件 × 引擎”的 `doc.md` 和 `doc.json`。
  - `report.html`：每个文件一节，几个引擎的 Markdown 渲染结果并排显示，表头列出结构统计和耗时；页面只用静态 HTML，不加载外部资源（补充：方便离线打开）。
- 汇总表：每个引擎按文件类型的成功率、平均每页耗时、内存峰值。

### Review 修正

- `parser/bench/run.py` 将旧格式转换移到外层：每个文件在 `--out` 下的临时目录转换一次，同文件需要转换的引擎及重复运行共用结果；转换时间传入工作进程，结束后清理临时目录。无需转换的组合仍使用原文件；转换失败的组合记录 `CONVERT_FAILED` 并继续处理其他组合。引擎的 `RUSAGE_CHILDREN` 不再包含外层转换器的子进程。
- 标题统计将文档标题记为 `title`，章节标题按数字层级记；`parser/bench/README.md` 说明统计与共享转换的含义。用文档标题 1 个、一级章节标题 2 个、二级章节标题 1 个的文档检查，得到 `{'title': 1, '1': 2, '2': 1}`。
- X06 的公开 `warmup()` 固定预热 `auto`，不接受扫描模式；为避免把 `force` 模型加载算进解析耗时，暂保留调用私有转换器缓存的补丁，并在代码中注明原因。
- 使用模拟转换器验证转换成功与失败、同文件只转换一次、重复运行共享、无需转换的引擎继续使用原文件和临时目录清理；另将模拟转换产物交给真实 Docling、MarkItDown 子进程，两个组合均成功且转换耗时相同。宿主机仍缺少 LibreOffice/unoserver，真实旧格式转换验收仍需在具备 X02 环境的机器完成。
- 使用原 `/tmp/adp-x10-validation` 样例目录、七种引擎变体分别输出 `/tmp/adp-x10-review-a` 和 `/tmp/adp-x10-review-b`；两轮各 `成功 30、不支持 26`，逐项比较状态、错误码、页数、OCR 页数、标题、表格、图片、文字字数，输出 `组合数: 56`、`结构差异: 0`。实际 Word 样例的 MarkItDown 标题统计为 `{"1": 1, "title": 1}`。
