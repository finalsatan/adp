## 要做

### 1. 项目

- `parser/pyproject.toml`，uv 管理，Python 3.12。本卡依赖：fastapi、uvicorn、pydantic、pydantic-settings、boto3、docling-core（只用它的 `DoclingDocument` 类型和导出功能）。开发依赖：pytest、pytest-asyncio、httpx、ruff、moto[s3]。`uv.lock` 提交。
- 目录：`parser/app/`（main、config、auth、jobs、pool、storage、runner、engines/、schemas）、`parser/tests/`。
- 配置（环境变量）：`PARSER_TOKEN`、`PARSER_WORKERS`（子进程数，默认 2）、`PARSER_QUEUE_MAX`（排队上限，默认 50，补充）、`PARSER_JOB_TIMEOUT_S`（默认 1800）、`PARSER_MAX_PAGES`（默认 2000）、`S3_ENDPOINT`、`S3_BUCKET`、`S3_ACCESS_KEY`、`S3_SECRET_KEY`、`PARSER_ENABLE_FAKE_ENGINE`（只在测试中开启）。

### 3. 引擎接口 `app/engines/base.py`

```python
class Engine(Protocol):
    name: str                                   # pypdfium / docling / markitdown / mineru / builtin / paddleocr
    def supports(self, file_type: str, ext: str) -> bool: ...
    def availability(self) -> tuple[bool, str | None]: ...   # (是否可用, 不可用原因：未部署 / 未配置 / 连接失败)
    def parse(self, ctx: ParseContext) -> ParseOutput: ...
```

- `ParseContext`：本地输入文件路径、`file_type`、`ext`、引擎参数（dict）、预处理开关、表格设置、临时工作目录、进度回调 `report(done_pages, total_pages)`、远端引擎配置（地址、密钥，可空）。
- `ParseOutput`：`DoclingDocument`、`pages`、`ocr_pages`、`engine_version`、`empty_pages`（没有文字层、未做 OCR 的页码，pypdfium 用）。
- 注册表 `app/engines/registry.py`：按名字取引擎；`list_engines()` 给 `/v1/engines` 用。
- 引擎在子进程中运行，**只处理本地文件，不访问对象存储**（补充：对象存储的下载上传在主进程做，便于测试和控制）。

### 4. 作业执行

- `runner.py`：主进程从对象存储下载源文件到临时目录 → 交给子进程执行引擎 → 拿回 `ParseOutput` → 执行统一后处理（X03 实现，本卡先留一个直接返回的占位函数）→ 把 `doc.json`、`doc.md` 写到 `output_prefix`，图片写到 `images_prefix` → 删除临时目录。
- `pool.py`：自己管理 `PARSER_WORKERS` 个常驻子进程（`multiprocessing`，spawn 方式），每个子进程启动时加载一次引擎所需的模型（知识库技术方案 6.3），通过队列收发任务和进度消息。**超时或取消时结束执行该作业的子进程，并补起一个新的**（补充：普通进程池无法中断正在执行的任务）。
- `jobs.py`：作业只存在内存里（知识库技术方案 6.1）。状态：`queued`、`running`、`succeeded`、`failed`、`cancelled`。排队数达到 `PARSER_QUEUE_MAX` 时提交返回 429。
- 页数超过 `PARSER_MAX_PAGES`、作业超过 `PARSER_JOB_TIMEOUT_S`：失败，错误码 `TOO_MANY_PAGES`、`TIMEOUT`（知识库技术方案 6.3）。

### 5. 接口（知识库技术方案 6.1）

| 接口 | 说明 |
| --- | --- |
| `POST /v1/jobs` | 请求：`source_key`、`file_type`、`ext`、`engine`、`engine_params`（dict）、`preprocess`（`merge_whitespace`、`remove_header_footer`、`remove_links_emails`）、`table`（`rows_per_chunk`、`header_row`、`sheets`，表格解析用）、`output_prefix`、`images_prefix`、`remote`（可空：`{base_url, api_key}`，MinerU 标准/高级档和 PaddleOCR 用）。校验引擎存在、支持该类型、当前可用。返回 202 `{id}` |
| `GET /v1/jobs/{id}` | `{id, status, progress: {done_pages, total_pages}, result: {doc_key, md_key, images_prefix, pages, ocr_pages, empty_pages, engine, engine_version, duration_ms} \| null, error: {code, message} \| null}`；不存在返回 404（worker 据此重新提交，知识库技术方案 6.1） |
| `DELETE /v1/jobs/{id}` | 取消；已结束的作业返回当前状态 |
| `GET /v1/engines` | `[{name, file_types: [...], available, reason}]`；本卡里 X02–X08 的引擎还没有，只返回已注册的 |
| `GET /healthz` | 不需认证 |

- 除 `/healthz` 外都要 `Authorization: Bearer {PARSER_TOKEN}`，用常量时间比较。
- 错误码（`error.code`）：`UNSUPPORTED_TYPE`、`ENGINE_UNAVAILABLE`、`FILE_CORRUPTED`、`FILE_ENCRYPTED`、`FILE_TYPE_MISMATCH`、`ARCHIVE_TOO_LARGE`、`TOO_MANY_PAGES`、`TIMEOUT`、`CANCELLED`、`REMOTE_ERROR`、`ENGINE_ERROR`。`message` 用中文，面向最终用户（知识库技术方案 8.3：失败原因面向用户书写）。
- 服务只在内网使用，不做跨域。

## 验收标准

- [ ] 测试（假引擎 + moto）：提交作业 → 轮询到 succeeded → 对象存储里有 `doc.json`、`doc.md`，`doc.json` 能被 `DoclingDocument` 加载；进度从 0 增长到总页数；引擎抛错时状态为 failed 且带错误码和中文说明；超时（把超时设为 1 秒、假引擎睡 5 秒）为 `TIMEOUT`，之后子进程数仍为 `PARSER_WORKERS`，新作业能正常执行；运行中取消为 `CANCELLED` 且子进程被补齐；排队数达到上限时返回 429；不带或带错 Token 返回 401；查询不存在的作业返回 404；不支持的类型、不可用的引擎在提交时就返回 4xx。
- [ ] `make parser-install parser-lint parser-test` 通过；`docker build parser/` 成功。

## 注意

- 子进程用 spawn 启动方式，避免 fork 后继承线程和连接的问题。
- 作业状态只在内存，服务重启全部丢失，这是设计（worker 会重新提交），不要加持久化。
