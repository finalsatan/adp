## 1. 背景与目标

企业内部有大量零散的 Word、Excel、PPT、PDF 文档，查找困难，而且各部门都有用大模型提升效率的需求。平台让企业内**经过授权和培训的搭建者**用模型、知识库、工具等资源，自己搭建面向具体场景的智能应用，发布给员工使用。

**首个场景是企业知识问答**：搭建者把文档整理成知识库，针对不同场景调好问答效果；员工在网页上直接提问，得到带原文出处的准确回答。智能体、工作流等其他应用类型按阶段补齐。

平台先在公司内部跑通，再以**私有化部署**的方式交付给外部客户。初期由我方实施人员在客户现场搭建和调优，之后培训客户的 IT 或业务骨干成为搭建者。

**与万悟的差异**：模块划分和万悟一致，但每个模块要做得更深。以知识库为例，要做到解析方案可灵活配置、结构和表格识别可检查、多版本管理、两层评测，还要能把问题一路追到具体环节。深度配置要通过"配置分层 + 模板"保持可用（见 4.3）。

**成功标准（内部试点）**

- **答得准**：评测集上的准确率达到约定目标；每条回答都带可点击的原文引用；查不到时明确说"未找到"，不编造
- **调得动**：搭建者遇到答错的问题，能在平台内定位原因（解析、切片、检索还是生成），改完配置后能立即验证效果
- **搭得出**：没有参与开发、只经过培训的搭建者，能独立从零搭好一个知识问答应用并发布
- **看得清**：管理员能看到谁在用、用了多少 Token、费用估算、哪些问题答不好

## 2. 产品定位与约束

| 项 | 结论 |
|---|---|
| 产品形态 | **智能体开发平台**：经授权的搭建者搭建应用，最终用户使用；模块划分参照万悟 |
| 首个场景 | 企业知识问答（知识库 + 知识问答应用优先做深） |
| 交付方式 | 私有化部署，每个客户一套实例 |
| 租户 | 租户 = 公司；单个实例通常只有一个租户，保留多租户能力用于集团 / 子公司场景 |
| 模型 | 云端模型 API 为主，由客户自己配置 Key 和地址，费用由客户承担 |
| 计费 | **不做**定价、账单、余额；只做用量统计和费用估算 |
| 文档权限 | 不按文档过滤；能用某个应用，就能问到该应用绑定的全部知识库 |
| 原文件访问 | 最终用户只能看到被引用的片段和文件元信息，不能下载原文件；原文件只有该知识库的所有者和协作者可以下载 |
| 最终用户入口 | 只有平台网页 |
| 监控 | 需要详细监控：用量、质量、调用链路、系统运行 |
| 品牌 | 需要支持客户替换 Logo、系统名称等 |
| 开发资源 | 1 人开发，必须严格按阶段推进（见第 8 节） |

## 3. 用户角色

| 角色 | 是谁 | 主要操作 |
|---|---|---|
| 系统管理员 | 实施人员 / 客户 IT | 安装初始化、品牌设置、租户管理、模型配置、用户与角色管理、授予搭建权限、系统监控、查看全部资源和应用 |
| 搭建者 | 初期是我方实施人员，后期是**经过授权和培训**的客户 IT 或业务骨干；不是普通员工 | 创建和维护资源（知识库、提示词、工具等）；搭建、调试、评测、发布应用；处理用户反馈；授权哪些人能用自己的应用 |
| 最终用户 | 客户的普通员工 | 在应用广场选择应用、对话、查看引用原文、点赞点踩 |

**对产品设计的影响**

- **搭建者是专业用户**：配置项可以完整暴露。但搭建者会不断换人、由客户人员接手，所以每个配置项都要有说明和合理默认值，并采用"基础 / 高级"分层（见 4.3）。
- **最终用户什么都不配置**：只能看到应用广场和对话界面，界面越简单越好。
- **实施人员会在多个客户之间复用经验**：资源和应用都要能导出、导入，并能沉淀为模板。

角色按万悟的方式实现：**角色可配置**，每个角色可以访问哪些菜单、能不能创建哪类资源和应用，都由系统管理员勾选。上面三个是预置角色。

## 4. 核心概念与通用机制

### 4.1 功能模块

| 模块 | 包含 | 说明 |
|---|---|---|
| 模型服务 | 模型管理 | 所有能力的来源 |
| 资源库 | **知识库**、提示词、插件工具、MCP 服务、Skills、安全护栏 | 可复用的"零件"，一个资源可被多个应用引用 |
| 应用开发 | **知识问答**、智能体、工作流 | 把模型和资源组装成面向场景的应用，调试后发布 |
| 探索广场 | 应用广场、模板广场 | 最终用户在这里找到并使用应用；搭建者在这里复用模板 |
| 应用观测 | 效果评测、统计看板、质量分析、调用记录 | 看应用效果、找问题，回到资源或应用里修改 |
| 管理中心 | 用户与角色、租户、系统监控、品牌、操作日志 | 管理底座 |

依赖方向：**模型 ← 资源 ← 应用 ← 观测**。加粗的是第一期做深的部分。

还没开发的模块在菜单中**灰色显示**，并标注计划阶段（如"智能体 · D"），点击后不能进入。这样客户能看到平台的完整路线。按角色没有权限的菜单则直接隐藏。

### 4.2 核心概念

| 概念 | 说明 |
|---|---|
| 知识库 | 一组文档和问答对的集合，连同它的解析方案、同义词表一起管理 |
| 解析方案 | 一套"文档 → 切片"的处理规则：怎么解析、怎么清洗、怎么切片、要不要补充摘要 / 关键词、用哪个向量模型。在知识库模块中管理，可命名、可被多个知识库引用、可导入导出 |
| 文档元数据 | 描述文档的属性。分两类：**系统自动记录**的（文件名、文件夹、文件类型、上传人、上传 / 更新时间）和**搭建者定义**的（如业务领域、版本号、生效日期）。用于筛选文档、限定检索范围、让新版本优先 |
| 文档版本 | 同一份文档（如《差旅管理办法》）的多个版本归为一组，组内只有一个现行版本 |
| 问答对（FAQ） | 知识库内的标准问题和标准答案，每条可带多个相似问法。用于高频问题的稳定回答，也是修正答错问题的主要手段 |
| 同义词表 | 业务术语、简称、别名的映射，例如"年假 = 带薪年休假"。每个知识库维护自己的同义词表 |
| 知识问答应用 | 面向一个具体场景的问答服务，例如"HR 制度问答"，由绑定的知识库、一套问答配置（检索、查询处理、生成）和展示信息组成 |
| 评测集 | 一批真实问题 + 标准答案 + 原文位置，用来衡量应用效果、对比不同配置 |
| 模板 | 一个资源或应用的配置快照，可发布到模板广场，供其他搭建者以它为起点创建 |

关系：**租户 → 资源 / 应用**；一个应用可以引用多个资源，一个资源可以被多个应用引用。问答应用绑定多个知识库时，查询处理合并使用这些知识库的同义词表。

### 4.3 通用机制（所有资源和应用都遵循）

| 机制 | 优先级 | 说明 |
|---|---|---|
| 所有者与协作者 | P0 | 创建者是所有者，可添加协作者（可编辑）；系统管理员可转移所有者 |
| 可见范围 | P0 | 仅自己 / 指定用户组 / 全租户。可见即可引用，但只有所有者和协作者能修改 |
| 配置分层 | P0 | 每个配置界面分"基础"和"高级"两层：基础只有几项必填，其余都有合理默认值，按默认就能用；高级配置默认折叠。每项都有说明文字 |
| 草稿与发布 | P0 | 应用的修改先存为草稿，不影响最终用户；发布后生成版本，可回滚 |
| 导入 / 导出 | P0（知识问答相关）| 连同引用的资源配置一起导出（不含文档内容），用于在客户之间复用 |
| 保存为模板 | P1 | 发布到模板广场（见 5.4） |
| 引用关系与影响提示 | P0 | 每个资源都能看到被哪些应用引用。修改被引用的资源（例如知识库的文档、切片、解析方案）会立即影响这些应用，包括已发布的版本，所以保存前要提示受影响的应用 |
| 删除保护 | P0 | 资源仍被应用引用时不能直接删除，先提示解除引用 |
| 操作日志 | P0 | 见 5.6 |

## 5. 功能需求

优先级：**P0** = 内部试点必须有；**P1** = 首个外部客户交付前要有；**P2** = 按需。属于后续阶段的模块在标题处注明阶段，模块内的优先级是指"进入该阶段后"的优先级。

### 5.1 模型服务

| 功能 | 优先级 | 说明 |
|---|---|---|
| 接入云端模型 | P0 | 兼容主流国内外模型服务；Key 加密保存 |
| 模型类型 | P0 | 对话、向量、重排；P1 增加看图（用于扫描件、图片） |
| 连通性测试 | P0 | 保存时自动测试一次 |
| 模型单价 | P0 | 只用于费用估算展示 |
| 模型可见范围 | P1 | 指定哪些角色 / 用户组的搭建者可以使用某个模型 |
| 模型体验 | P1 | 直接和某个对话模型对话，用于比较模型 |
| 失败重试、备用模型 | P1 | 主模型不可用时自动切换 |
| 调用频率限制 | P1 | 避免触发云厂商限流 |

### 5.2 资源库

#### 5.2.1 知识库：知识库与文档

| 功能 | 优先级 | 说明 |
|---|---|---|
| 创建知识库 | P0 | 名称、描述、默认解析方案、可见范围 |
| 上传 Word / PDF / PPT / Excel / Markdown / TXT | P0 | 后台处理，显示进度和失败原因 |
| 批量上传 | P0 | 多选、整个文件夹、压缩包 |
| 重复文件识别 | P0 | 内容相同的文件不重复入库 |
| 文档版本管理 | P0 | 见下方"制度类文档的多版本" |
| 文档列表 | P0 | 按状态、类型、所用解析方案、文件夹、元数据筛选；查看每个文档的切片数、处理耗时 |
| 保留文件夹结构 | P1 | 上传整个文件夹时保留目录结构，可按文件夹浏览、筛选 |
| 文档启用 / 停用 | P0 | 停用后不再参与检索，但保留文档和切片；用于临时下线过期或有问题的文档 |
| 处理失败重试、取消处理 | P0 | 单个或批量重试；正在排队或处理中的文档可以取消 |

| 文档内图片识别 | P1 | Word / PDF / PPT 中的流程图、截图等，用看图模型转成文字描述参与检索 |
| 扫描件 / 图片识别 | P1 | |
| 在平台内直接编写知识 | P2 | 不上传文件，直接录入一段文本作为文档 |
| 复制知识库、在知识库之间移动文档 | P2 | |
| 网页链接导入 | P2 | |
| 数据源定时同步 | P2 | 例如飞书文档、Confluence |

**制度类文档的多版本**

制度、办法、规范经常修订，新旧版本同时存在时，最容易出现"答出了旧标准"的错误。要求：

| 功能 | 优先级 | 说明 |
|---|---|---|
| 上传新版本 | P0 | 在已有文档上选择"上传新版本"；新版本成为现行版本，旧版本自动转为历史版本 |
| 疑似新版本提示 | P1 | 上传的文件与已有文档名称高度相似时（如《差旅管理办法（2025）》与《差旅管理办法（2023）》），提示搭建者是否作为新版本 |
| 手动归组 | P1 | 已经分别上传的多个文件，可以手动指定为同一文档的不同版本，并指定现行版本 |
| 历史版本不参与检索 | P0 | 默认只有现行版本参与问答；历史版本保留，搭建者可查看、可恢复为现行版本 |
| 版本信息 | P0 | 每个版本记录版本号、生效日期（可选填）、上传时间；引用中展示所引用文档的版本和生效日期，让用户知道依据的是哪一版 |
| 查询历史版本 | P2 | 用户明确问"2023 年的标准"时，允许检索历史版本，回答中注明版本 |

#### 5.2.2 知识库：解析方案

客户的文档千差万别（制度文件、产品手册、合同、表格、PPT 培训材料……），**解析方案必须能按客户的文档类型和内容灵活调整**，而不是一种格式只有一种固定处理方式。

**配置原则**：父子分块、补充摘要、查询扩写这类高级处理**不是越多越好**，不同场景效果不同。所以每项都做成独立开关，默认走最简单的处理，由搭建者用评测集验证有提升后再开启。

**方案内容**

| 环节 | 可配置项（示例） | 优先级 |
|---|---|---|
| 解析 | 解析精度档位（快速 / 高精度版面分析，后者更准但更慢、更耗资源）；是否识别扫描件 / 图片，是否自动判断文档是否为扫描件；表格的处理方式；是否去掉页眉页脚、目录页 | P0（扫描件 P1） |
| 清洗 | 自动去掉每页重复出现的文字（页眉、页脚、水印）；按规则删除或替换文本（例如固定免责声明、网址、多余空白）；丢弃过短、无意义的切片 | P1 |
| 切片 | 切片方式：按标题层级 / 按长度 / 按页 / 按表格行 / 按问答对；切片长度、重叠长度；自定义分隔符（如"。""\n\n""第X条"）；不在句子中间截断 | P0 |
| 结构识别 | 识别文档的标题层级（目录结构）；对没有样式信息的文档（如 PDF），可配置标题识别规则，例如"第X章""3.2""一、"等编号格式 | P0 |
| 切片上下文 | 见下方"切片上下文" | P0 |
| 补充 | 为切片自动生成可能被问到的问题，与切片一起参与检索 | P1 |
| 补充 | 为切片 / 文档自动生成摘要、关键词 | P2 |
| 向量化 | 选择向量模型 | P0 |

**切片上下文**

单个切片脱离原文后经常丢失关键信息。例如"标准为每天 300 元"这一段，如果不知道它属于"第三章 差旅 > 3.2 住宿标准 > 一线城市"，就既检索不到，也答不对。因此**每个切片都要带上它所在位置的上下文**：

| 上下文 | 适用文档 | 优先级 |
|---|---|---|
| 文档标题 / 文件名 | 全部 | P0 |
| 章节路径（如"第三章 差旅 > 3.2 住宿标准"） | Word、PDF、Markdown | P0 |
| 页标题 | PPT | P0 |
| 工作表名 + 表头 | Excel、文档中的表格 | P0 |
| 由模型生成的一句话背景说明（说明这段在全文中讲什么） | 全部 | P2 |

可配置项：

| 功能 | 优先级 | 说明 |
|---|---|---|
| 上下文用于哪些环节 | P0 | 分别开关：参与语义检索、参与关键词检索、提供给对话模型；默认全部开启 |

**父子分块**（P1，按场景开启，默认关闭）

用小切片检索、用大段落回答：小切片语义集中，检索更准；但小切片内容不完整，交给模型时换成它所属的大段落。适合答案跨越多段的场景（如操作步骤、条款说明）；FAQ、短条目类文档用不到。

| 功能 | 优先级 | 说明 |
|---|---|---|
| 父块划分方式 | P1 | 按章节（一个小节为一个父块）/ 按固定长度 |
| 子块划分方式 | P1 | 按长度 / 按句子 / 按段落 |
| 父块过长时的处理 | P1 | 超过上限时截断或退回只用子块 |
| 按命中比例决定是否换成父块 | P2 | 同一父块下命中的子块足够多时才换成父块，否则只用子块，避免把大量无关内容交给模型 |

对应地，知识问答应用中要配置**交给对话模型的内容**（见 5.3.1 检索配置）。

**结构识别必须可检查**：试运行和切片预览中要能看到识别出的目录树，以及每个切片挂在哪个标题下。标题识别错了，搭建者要能看出来，并通过调整识别规则修正。

**表格处理**

客户文档中最常见的是**夹在 Word / PDF 里的表格**（参数表、标准表、对照表），其次才是 Excel 数据表。当前只要求回答**查找类**问题（如"一线城市经理级住宿标准是多少"）；统计类问题（求和、计数、平均）目前不多，见 5.7。

| 功能 | 优先级 | 说明 |
|---|---|---|
| 表格识别 | P0 | 从 Word / PDF 中把表格与正文区分开，不能把表格内容打散成无结构的文字 |
| 表格切片方式可选 | P0 | 小表格整表作为一个切片；大表格按行切分，每个切片重复带上表头 |
| 表格上下文 | P0 | 切片带上表格标题（如"表 3-1 住宿标准"）、所在章节路径；Excel 带工作表名 |
| 合并单元格 | P0 | 合并单元格的值要正确对应到它覆盖的每一行 / 列，否则按行切分后会丢失信息 |
| 多级表头 | P1 | 如"住宿标准 > 一线城市 > 经理级" |
| 跨页表格 | P1 | PDF 中跨页的表格合并为一张表，续页表头不重复识别为数据 |
| 表格预览 | P0 | 试运行和切片预览中能看到表格被识别和切分的结果 |

验收：评测集中要包含一定比例的表格查找类问题，并单独统计这类问题的准确率。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 部署 | 一条命令启动；提供完整离线安装包 |
| 无外网 | 除调用客户配置的模型接口（以及搭建者自己配置的外部工具 / MCP 服务）外，运行时不依赖任何外网服务 |
| 升级 | 升级时自动迁移数据；提供备份 / 恢复方法；界面可查看版本号 |
| 性能 | 平台自身给每次问答增加的延迟 < 500ms；支持至少 100 个文档同时排队处理 |
| 安全 | 租户之间数据隔离；资源和应用按所有者 / 可见范围隔离；密钥加密保存；上传文件类型和大小校验；接口限流 |
| 可扩展 | 新增资源类型或应用类型时，只在对应模块下增加一项，不改动已有模块；预留安全护栏的接入位置 |

| 语言 | 先只做中文，界面文案可翻译 |
| 终端 | 只支持 PC 浏览器，暂不做手机适配 |
| 状态刷新 | 不做站内消息和主动通知。文档处理进度、批量评测进度等由前端定时查询刷新；搭建者在列表页看状态即可 |

## 7. 明确不做

- 未经授权的普通员工搭建应用（只有被授予搭建权限的角色才能创建资源和应用）
- 计费、定价、账单、余额
- License 授权控制
- 合规：内容审核、生成式 AI 备案、信创适配（安全护栏模块仅预留）
- 文档级权限过滤
- SaaS 能力：租户自助注册、套餐
- 万悟中与平台结构无关的业务模块：数字员工、本体建模、决策智能体等
- 当前版本：最终用户上传文件、网页以外的入口、对外 API

## 8. 阶段划分

排序原则：**答得准 → 调得动 → 交得出 → 搭得广**。前三个阶段都只做知识库 + 知识问答这一条线，把它做深；平台的其他模块从阶段 C 开始逐步补齐。具体周期见技术方案。

| 阶段 | 目标 | 主要内容 | 退出条件 |
|---|---|---|---|
| A 证明能答准 | 用一批真实文档证明效果 | 评测集；上传、解析、切片（先内置方案）；混合检索、重排、引用、拒答；检索测试；用量与处理过程开始记录。界面按 4.1 的模块结构搭好框架，未做的模块隐藏 | 评测集准确率达标，每条回答带引用 |
| B 搭建者能调优 | 搭建者能独立把一个场景调好 | 解析方案配置与试运行；知识问答完整配置；同义词表；调试对话；草稿与发布；批量评测；应用广场与对话；角色、所有者、可见范围、使用授权；操作日志 | 未参与开发的实施人员独立完成一个新场景的搭建和调优 |
| C 可交付 | 能交给第一个外部客户 | 问答对；导入导出；模板广场与内置模板；提示词库；未解决问题、版本对比；统计看板与质量指标；系统状态与告警；品牌定制；单点登录；离线安装包；操作手册 | 他人在干净环境中按文档完成安装，并独立搭好一个场景 |
| D 平台扩展 | 支持知识问答以外的应用 | 依次做：插件工具与 MCP → 智能体（以知识库作为检索工具）→ Skills → 工作流；API Key 与对外接口 | 按客户需求拉动，每项单独验收 |
| E 按需 | 由客户需求拉动 | 安全护栏；见 5.7 | |

**阶段 D 的顺序理由**：智能体依赖工具和 MCP，而且能直接复用已经做深的知识库，投入小、收益明显；工作流需要可视化画布，工作量最大，放在最后。
