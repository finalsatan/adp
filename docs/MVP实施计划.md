# ADP MVP 实施计划

日期：2026-10-20。需求基线：`docs/prd/智能体开发平台-需求文档-v0.2.html`。历史文档仅补充交互和工程细节；冲突以 v0.2 为准。

## 目标与技术决策

交付可运行、可持久化的前后端，完成“文档入库 → 带引用的多轮问答 → 反馈 → 评测”闭环，覆盖 P0 的组织权限、模型、知识库、发布、API Key、追踪、评测。P1/P2 不提前做。

- 前端：React + TypeScript + Vite，自带本地图标和 CSS，无运行时 CDN。
- API：Node.js 24 + TypeScript + Fastify；Zod 校验；Node 内置 SQLite，WAL、外键与事务；文件存本地数据卷。
- 解析：独立 Python HTTP 服务，PDF（pdfplumber/pypdf）、DOCX/PPTX/XLSX、HTML/Markdown/TXT/CSV，保留章节、页码/工作表行、表格。扫描件无法提取文字时明确失败；OCR/VLM 保留扩展协议，本轮尚未与已登记模型联通。
- 检索：中文字词/BM25 与真实 OpenAI 兼容 Embedding 余弦召回 + RRF；可选 rerank、查询改写；配置与阶段结果留 trace。
- 模型：真实 OpenAI 兼容 chat/embedding/vision；rerank 使用兼容 HTTP 协议；API Key AES-256-GCM 加密。离线演示模型明确标识为“本地演示（摘录回答）”，不能冒充大模型或语义质量证明。
- 异步：SQLite 持久任务队列，重启恢复、失败原因与重试、原子替换旧切片。单实例 MVP 保持组件少；服务/存储分层，规模扩大再迁移 PostgreSQL/pgvector，不宣称已有分布式能力。
- 交付：npm workspace，启动/构建/测试脚本、Docker Compose、单副本 Kubernetes 清单、环境配置与运维说明。

当前环境 Node 24 可用，原生开发已完成验证。Docker daemon 已启动且基础镜像已导入，实际容器构建受网络及自动审批超时影响，状态详见 [验收记录](MVP验收记录.md)。SQLite 使原生启动不依赖 Docker。

## 执行分工

Codex：范围与接口约定、根目录工具与部署、代码 review、系统测试、浏览器验收、修复跟进。

pi-api：仅负责 `apps/server/`（含 server package.json、tsconfig、后端测试）。实现 API、数据库、权限、模型与检索/问答/评测队列、样例种子。不要编辑根目录、前端、解析服务、现有资料；不提交 git。

pi-web：仅负责 `apps/web/`（含 web package.json、tsconfig、vite config）。实现完整中文管理后台与独立移动聊天页，按 `docs/MVP接口约定.md` 对接真实 API。不要编辑其他目录；不提交 git。

pi-parse：仅负责 `apps/parser/`（含 requirements/pyproject、Dockerfile、单元测试）。实现解析 HTTP 协议与格式定位。不要编辑其他目录；不提交 git。

所有工作直接在 `/Users/murphy/code/ai/adp`，以 Herdr agent 名称和返回的 pane ID 协调。保留用户原有 `.gitignore` 改动和下载数据。

## 完成门槛

1. 全新数据目录可初始化管理员并登录；组织树、多组织切换、成员/角色/菜单权限、知识库查看/编辑/授权、资源私有/组织/全平台可见性由服务端执行，子组织无隐式继承。关键操作审计。SSO 采用可选 OIDC 配置并有实际登录流程。
2. 模型可增改删、测试，支持全平台共享与本组织模型，密钥不在读取响应、日志或明文数据库出现。
3. 知识库文档可上传、替换、删除、重试；进度和失败原因可见；标题与表格、引用定位可检查；结构/语义/父子三种分块；编辑/合并/拆分/禁用可重新索引；检索测试展现阶段与得分。
4. 知识问答可配置和调试、保存草稿/发布不可变版本；独立 Web/iframe/API 入口；多轮会话历史、有效引用、无依据拒答；应用权限与引用知识库权限校验；API Key 只显示一次、绑定应用、可吊销。
5. 对话 trace 可回放改写、召回、融合、重排、上下文和模型；真实用量和耗时；点赞/点踩/纠错；反馈可加入评测集。
6. 评测集支持人工录入/JSON或CSV导入、按文档调用 LLM 生成；持久异步运行；召回、答案匹配、引用、拒答指标及两种检索配置对比；保留配置和用例快照。逐条人工评审分别记录 A/B 的答案与引用正确性，汇总已评审分母、准确率、评审人和时间；禁止将字符串指标包装成业务准确率。
7. 后端集成测试覆盖隔离/越权/密钥/API Key/入库/切片/问答/反馈/评测；构建与类型检查通过；浏览器运行核心流程和移动聊天布局。
8. README 写明一条启动路径、初始化方式、数据位置、测试、容器和恢复；所有未验证能力与限制据实列出。

业务侧验收与软件交付分开：PRD 中真实试点文档、200 条经业务确认的问题、X/Y/Z 指标均未提供；不得生成虚假业务签字或宣称达到待定指标。提供可导入的示例与运行工具，保留试点验收清单。

## Review 重点

认证与资源授权必须在服务端，不能只隐藏按钮；跨组织 ID、授权用户 ID、版本与 API Key 绑定均验证。外部调用带超时，上传有类型与大小校验，解压限制，避免路径穿越。用户内容作为不可信引用传模型。入库/编辑失败保留旧索引，禁用项不能被检索。发布版本与配置快照稳定。错误可读，前端具备加载、空、失败状态。
